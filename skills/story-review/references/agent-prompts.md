# story-review：full/lean 模式派子代理与综合

仅当实际模式仍是 full/lean 时读本文件。

用当前宿主 Agent 工具并行派发（Claude `subagent_type`、OpenCode `subagent` 的 `agent`、Codex `agent_type`、Antigravity `invoke_subagent` + `TypeName`、ZCode `Agent` 派注册角色）。子 Agent 不继承父上下文，prompt 须自包含路径、范围与 Schema，不写本 Skill 资料路径（各 reviewer 按自身模板读取表加载）。所有 reviewer 只读，不改任何文件。

**追踪修订号**：长篇工程（有 `追踪/_tracking-state.json`）派 consistency-checker 前，先跑 `scripts/tracking_commit.js check --project {项目根}`，将 `last_committed_chapter`、`state_revision` 填入其 prompt；返回 `drift_warnings` 注明以 `_tracking-state.json` 为准，check 报 exit 2 时写「check 失败，追踪文件不可信：{报错首行}」并在报告「没法判断的地方」白话说明。短篇两项均写「无追踪」。

**story-explorer 预查询（可选）**：仅 `Effective Mode` 为 `full`/`lean`、非子代理递归且当前宿主确认 `story-explorer` 可用时才可派发（传 `项目目录`、`查询类型: setting_appearances`、`查询参数`）；`solo` 或降级场景下直接检索。

## 公共输入与输出协议（Agent 1–3 共用）

派发 Agent 1–3 时在各自指令顶部填入以下公共字段，末尾附上统一输出要求：

```text
你的任务是【找问题】，不是验证正确性。以最严苛的标准审视。
只读审查：不改任何文件（含正文），只输出下方 VERDICT / FINDINGS / RECOMMENDATIONS。
项目路径：{项目根}
审查范围：{文件路径/章节/必要摘录}
文风路径：{本书文风全文路径，无则写无}
style_resolution：{生效要求及来源、覆盖的默认条款、事实边界}
审查基准包摘要：{Phase 1 形成的 rubric / fallback 摘要，必须内联}
Rubric Source: file | embedded fallback
```

统一输出格式：`VERDICT: APPROVE / CONCERNS / REJECT`；`FINDINGS:` 使用统一 Findings Schema（`severity` 为 S1/S2/S3/S4）；`RECOMMENDATIONS: [修改建议]`。（Agent 1 另附 `INHERITED_ITEMS`。）

**Agent 1: story-architect**（full/lean 均调用）
- 视角：核心卖点与期待推进、结构、钩子/反转、范围控制、平台期待。
- 附加字段与检查项：
  ```text
  你是 story-architect，从故事架构层面审查以下内容。
  {公共输入}
  相关文件路径：{设定/大纲/细纲文件路径}
  继承的开放项（分批审查必填，无则写「无」）：{追踪/伏笔.md 预计回收章 ≤ 本批末章的未回收钩子 + 上批未解决 findings}
  检查项：
  1. 是否紧扣核心卖点与读者期待推进（短篇按四轨验收：冷开场零秒续接、32%–44% 付费卡点、打脸/脑洞吐槽甜宠/死人追夫 50%–55% 蓄压/悬疑各按本轨推进与收尾）？
  2. 结构是否完整（按本章松紧核钩子/爽点/阶段兑现/悬念）？情绪节奏与反转质量如何？有无角色/设定膨胀？
  3. 剧情循环与高潮构建是否成立（紧章须有真实阻滞、对手私心反咬与意外变数；反派降智递话筒或零阻力套路打卡过场直判 S2，机械三检 0/0/0 亦不放行）？
  4. 伏笔密度与连载期待是否合理（密度仅作 S4 提示，除非造成理解混乱）？继承开放项里本批应兑现的是否落空？
  5. 对照通用 rubric 与平台表逐项判 PASS/FAIL。
  6. 开头抓力与切口（仅开篇/前 3 章）：是否用具体人物、处境与赌注抓人？商业爆款/品类经典开局范式（长短篇通用）有具体冲突与钩子即通过；空泛灌水或无赌注套壳判 S2/S3。
  7. 章尾总结/升华是否重复已有信息、削弱收束（先按本书叙述方式与功能复核）？
  另输出 INHERITED_ITEMS：逐条列继承开放项 + 已检查 / 未能检查；本批应兑现却落空的列为 finding。
  ```

**Agent 2: character-designer**（full 调用）
- 视角：角色声口一致性、对话质量、人物弧线、关系推进。
- 附加字段与检查项：
  ```text
  你是 character-designer，从角色和对话层面审查以下内容。
  {公共输入}
  相关角色文件：{角色设定文件路径}
  检查项：
  1. 角色声口是否与语言档案一致？人物弧线是否连贯？行为是否符合动机？
  2. 对话是否有信息控制与差异（长篇重潜台词；短篇强冲突场允许直球摊牌、狠话与围观烘托）？
  3. 感情线/核心搭档或对手关系的言行尺度是否匹配当前阶段，推进有无明确触发（短篇有明确触发即可快速心死/翻脸/结盟）？
  4. 排查四类对话硬伤：① 机械问答/无情绪承接；② 角色当「科普嘴」整段讲设定；③ 单轮 ≥60 字演讲式长台词未拆成来回交锋；④ 违背人设与场合的突兀插科打诨。命中按 S2/S3 给原文引用与改法。
  5. 女频作品同步排查：男主油腻爹味/物化称呼/强迫越界、女主恋爱脑向渣男/绝情亲人讨爱或低级扯头花雌竞，以及 CP 甜虐底线与排雷冲突。
  ```

**Agent 3: narrative-writer**（full 调用）
- 视角：三层去味诊断（表达、用笔、故事因果与变化）、情绪兑现、格式合规、节奏与文字自然度。
- 附加字段与检查项：
  ```text
  你是 narrative-writer，从文字质量层面审查以下内容。
  {公共输入}
  去味判据：按模板读取表完整读 deslop-guide 与 banned-words（短篇必叠读 short-deslop 并以其规则覆盖为准），三层都审；改写动作仅作建议，不落改。
  检查项：
  1. 词句与闲笔贴纸：查翻译腔、套词复读、变体油腻氛围词（空气发烫/声音又冷又哑）、代偿微动作及**无功能材质穿搭光影音效贴纸过载**（过载直判 S2，0/0/0 亦不放行）；刀子物件、直写情绪、算账与短篇反应词按规则留。
  2. 表达节奏：严查**抽干内心因果的剧本摄像头电报体**（连发短叙述碎行/强拆动作链直判 S2，0/0/0 亦不放行）、视角越界与空泛尾（对白短打独行，纯叙述留口语因果与盘算）。
  3. 格式与标点：手机竖屏适读（长篇禁 >100 字墙段）、无空行、对话独立；叙述默认 `。`，查旁白 `！` 过密（≥10/千字）、非热血全文咆哮（长 ≥22/短 ≥21/千字；克制流派按流派包）、旁白 `——`/`……` 刷屏与畸形破折号。
  4. 具体字数表达（「这五个字」类）是否准确必要？
  5. 用笔与故事：有无水戏或关键交锋被概述？行动依据、成立条件与场后变化是否立住？指明所属层与证据，category 用 prose。
  ```

**Agent 4: consistency-checker**（full/lean 均调用）
- 视角：grep-first + 推理型一致性检测，不做文学评价、不给创作建议。
- 提示指令：
  ```text
  你是 consistency-checker，使用 grep-first + 推理型一致性审查检测事实矛盾。
  你的任务是【找事实矛盾、状态断线和需要推理才能发现的设定逻辑冲突】，不做创作评判，不评价文学质量，不输出创作修改建议。
  项目路径：{项目根}
  审查范围：{文件路径/章节/必要摘录}
  已知角色：{从设定文件提取角色列表}
  last_committed_chapter：{check 输出；短篇写「无追踪」}
  state_revision：{check 输出；短篇写「无追踪」；check 失败写「check 失败，追踪文件不可信：{报错首行}」}
  继承的开放项（分批审查必填，无则写「无」）：{追踪/伏笔.md 预计回收章 ≤ 本批末章的未回收伏笔 + 上批未解决 findings}
  检查项：
  1. 角色属性、术语、身份、地点、能力边界是否前后一致？
  2. 世界规则与常识是否被违反？时间线是否自洽？（悬疑/推理核物理常识与关键线索前置时机；现代都市核协议离婚冷静期、担保责任等基础法律常识。）
  3. 伏笔状态（已埋/计划回收/已回收/断线）是否一致？继承开放项里本批应回收的是否悬空？

  输出格式：
  VERDICT: APPROVE / CONCERNS / REJECT
  FINDINGS: 使用统一 Findings Schema，severity 为 S1/S2/S3/S4；category 限 consistency / factual / format / causal / rule_boundary。
  INHERITED_ITEMS: 逐条列继承开放项 + 已检查 / 未能检查；新发现不在 伏笔.md 的开放钩子单列，供追踪修订。
  FACTUAL_RECONCILIATION: [仅列需统一的事实来源或需人工裁决项]
  REASONING_CHAINS: [仅列推理型 finding 的前提/规则 -> 触发事件 -> 矛盾点 -> 需裁决问题]
  ```

## 综合裁决

1. 收集实际执行的 reviewer 结果，合并去重，按 S1 > S2 > S3 > S4 及影响范围排序。
2. **可选事实核查**：涉及需验证的外部事实时，仅在 `Effective Mode` 为 `full`/`lean`、非子代理递归且当前宿主确认 `story-researcher` 可用时才可额外派发；否则标「需人工事实核查」。
3. reviewer 间有分歧时明确呈现让作者裁决，不自动妥协。按 SKILL.md「报告面向作者」用下方模板交付（降级 solo 改用 `solo.md` 模板）。
