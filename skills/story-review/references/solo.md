# story-review：solo 模式

当前会话直接审查，不 spawn Agent。按 Phase 1 加载通用 rubric 并叠加平台表（不可读用内置基准包）。

逐项完成基础检查：
1. **格式可读性**：对白净白短打、纯叙述保口语因果与盘算（长篇禁 >100 字墙段与抽干内心的摄像头电报体；短篇禁强拆连续动作）、无空行；核字数表达、叙述 `！`（≥10/千字）、全文咆哮（长 ≥22/短 ≥21/千字）与 ≥60 字演讲。
2. **设定一致性**：grep 角色名、属性、设定与伏笔词 + 核规则边界、跨章因果与常识（悬疑物理/线索前置；都市冷静期/担保；连载搬家物位、余额加减、相对日历）。
3. **三层 AI 味与硬红线**：读 `deslop-guide.md`、`banned-words.md`（短篇叠 `short-deslop.md`）；严查**反派递话筒/零阻力套路打卡**、**无功能材质穿搭光影音效贴纸**、**摄像头电报体**与**变体油腻氛围词**——命中直判 S2，机械三检 0/0/0 亦不放行。只报不改。
4. **内容评估**：按通用 rubric 与叠加的平台表逐维评估。
5. **追踪提醒**：长篇工程里若正文证据显示 `追踪/` 有错漏，不改 `追踪/`，把待修事实写进「需要你决定」，提示装好审稿助手后跑 `/story-review lean` 或在 `/story-long-write` 改该章时提交。
6. 按统一 Findings Schema 整理，转写为下方白话报告。

### solo 模式输出格式

```md

## 格式与设定

下一步：{一句话}
```
