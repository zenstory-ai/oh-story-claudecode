# story-review：多章分批审查

多章、整卷或整本审查需拆成两批及以上时读本文件，full、lean、solo 均适用；一次审完则不读。

## 跨批审查状态保存契约

分批时维护 **{项目根}/.story-review/state.md**：

1. 首批定完整范围和顺序；每批完后用同目录临时文件 + rename 原子重写 state.md，不只留在对话里。
2. 只记完整范围、已完成、下一批及「上一批未解决 findings 摘要」（含 location、issue、预计核查/兑现章范围）。
3. 下一批开审前读 state.md，将未解决摘要注入 reviewer prompt；已解决或用户忽略的项不再继承，须在本批说明。
4. 每项目仅一条跨批审查；新范围与未完成项不同时先告丢弃旧进度并确认，首批完时覆盖。续接遇 state.md 缺失/损坏或超范围须报错停止，不猜测；非分批不建此文件。

**.story-review/** 只存进度，不得借此修改正文、设定、大纲或 `追踪/`。

## 每批开审前

- **跨批连续性**：先读 `追踪/伏笔.md` 中 `已埋` 且计划回收章 ≤ 本批末章的行、相关 `追踪/逐章记录/` 与角色快照，将 state.md 未解决摘要作「继承开放项」注入 reviewer/consistency-checker（solo 自核）。未登记开放钩子列维护候选，有正文证据才进修订事务。
- **乱序/重叠提醒**：先审靠后（如 300–400）再审靠前（200–300）时，仅当本批新增/改动开放项且预计兑现章落入已审靠后范围才提醒并供选「复审受影响章/全量复审/仅记待办（默认）」。

## 中后期纵向漂移四查（≥第30章/多批必查）

1. **声线切频**：对照前 5 章，查是否漂成 `不是A。是B。` 碎句或科幻日志腔；
2. **通胀失感**：查境界/财富是否无阀门破顶、旧技弃用或脱离日常物价刻度；
3. **关系失血**：查换图是否清空老配角、核心配角是否超 40 章无交代失踪；
4. **复读与打架**：查同章机械复读同一轮台词、形近人名或年龄/职级穿帮。
