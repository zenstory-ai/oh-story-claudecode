# writing-workflow.md：短篇写作工作流详解

本文件包含 story-short-write 的详细工作流程指引。SKILL.md 中只保留摘要和触发条件。

## Phase 2 设计任务（框架确定后执行）

### 开始前先通过 Reference Gate（逐项检查，不能跳过）

- 工作流与投稿结构 → 加载 `writing-workflow.md`（本文件）+ `submission-craft.md` ✅/❌
- 定题材腔调/招式 → 加载一个精确的 `genre-styles/{题材}.md` + `short-craft.md`；冷门题材改用 `genre-writing-formulas.md` ✅/❌
- 写反派/揭露方式 → 加载 `villain-and-reveal.md`；不适用时写明原因 ✅/❌
- 反转信息差验证 → 加载 `short-reversal.md` ✅/❌
- 伏笔回查 → 见下方「伏笔回查清单」 ✅/❌
- 精确路径缺失或不可读时按 SKILL.md 首屏门禁停止，不创建/修改故事产物

### 设计步骤

1. **设计信物 / 贯穿物**（可选，1-2 个）：见题材包招式库「信物翻转」（如追妻火葬场的信物意义翻转）
   - 填写：`- 第1次出现（第X节）：{场景}（{含义}）` 重复三次，含节号定位
2. **设计反派**（如有）：用 villain-and-reveal.md 反派模板
   - 填写：`{身份} + {动机} + {作恶方式} + {致命弱点} + {报应}`
3. **确定揭露方式**：从 villain-and-reveal.md 4 种真相揭露机制中选一种
4. **编写 小节大纲.md**：使用固定 12 列 Markdown 表格，每节 1 行，表头如下（列名和顺序不可改）：

   `| 结构段/五段功能 | 主事件 | 情节推进 | 情绪 | 人物/关系变化 | 因果/逻辑链 | 读者新获知什么 | 结尾承接/钩子 | 伏笔/物件 | 场景形态 | 对白作用 | 目标字数 |`

   下一行写 Markdown 分隔行，再逐节填写数据行。
   - `结构段/五段功能` 使用开头/铺垫/升级/反转/结尾（或起因/发展/转折/高潮/结尾），用于轻量对应长篇的内容概括，但不要套长篇完整章节蓝图
   - `人物/关系变化` 写本节前后变化；没有人物或关系变化时，写 `无（本节改变：信息/风险/资源/决定/行动/读者理解中的具体一项）`，不为填表硬造关系波动
   - `因果/逻辑链` 写 `原因 → 行动 → 结果 → 后果/新问题`，避免小节只是情绪堆叠
   - `结尾承接/钩子` 写本节如何接下一节；最后一节写结尾落点
   - `情节推进` 写本节一个或多个真实改变；不设数量下限，相关情节点允许由同一动作链或对话同时兑现，禁止为凑数量加入阻碍、配角反应、短回忆或意外
   - 有先后关系的推进单元用 `->` 连接，每个单元包含具体情节点描述+功能标签：
     `具体发生了什么{功能标签}` 如 `发现账单上多了一笔4800{发现}` / `把戒指冲进马桶{冲突}` / `他笑了{递进}`
     功能标签：`对话` / `冲突` / `伏笔` / `回忆` / `发现` / `递进`
     情节点描述要具体到"谁做了什么"，不能只写标签如`对话`或`冲突`
   - `场景形态` 写主要推进引擎，如行动、对话权力、证据核验、手艺、等待、空间压力或关系回落；不要求动静交替
   - `对白作用` 写对白实际改变的信息、策略、权力、关系或下一步行动；无对白时写明由哪种动作、证据、物件或任务推进，不设占比或话轮数量
5. **反转信息差验证**（outline 写完后、写作前必须验证）：
   - `short-reversal.md` 判为无反转 → 写明理由，改查报应因果或甜度期待是否经过铺垫并得到兑现；跳过以下揭示检查
   - 记录：读者在第几节知道真相？用「揭穿节号 ÷ 全文总节数」计算位置百分比，供核对节次和篇幅分配；百分比本身不是通过阈值
   - 揭示前：错误解释是否已影响至少一次重要决定？还没有 → 误判尚未参与剧情，应补行动后果或调整揭示位置
   - 揭示后：是否留出新的行动、关系变化或代价结算？只剩口头解释 → 提前揭示或压缩说明
   - 双层反转：第一层阶段答案后是否发生基于该答案的新行动？没有 → 两层只是连续口供，应拉开功能距离
   - 检查：至少有 1 条读者被成功误导的假线索（不是读者猜到后等角色追上来）
   - 检查：反转前是否铺垫了 ≥3 条指向真相的线索（线索要隐蔽，不是明示）
   - 验证：找一个人（或自我模拟）只看 outline，能否在反转前猜到真相？猜到 = 失败
6. **伏笔回查清单**（outline 写完后、写作前检查）：
   - 列出结尾所有关键元素（物件/信息/角色/关系变化）
   - 每个结尾元素在前文有 ≥1 次铺垫？没有 = 天降，必须补铺垫
   - 贯穿道具三次出现完整？（第 1 次出现在铺垫段，第 2 次出现在反转段，第 3 次出现在结尾段）
   - 铺垫节号与揭穿节号的间距 ≥ 3 节（间距太短铺垫无效）

### Phase 2 设计校验与确定性验收

`设定.md` 写入 `## Phase 2 设计校验`，至少包含：一个真实的题材 reference 路径、2-3 个核心招式、反派五字段或带原因的不适用声明、反转类型、`反转位置：第 X 节 ÷ 共 Y 节 = Z%`、`付费点：第 N 节末`。`short-reversal.md` 判为无反转时，位置改写为带原因的“不适用”。付费点同时写入 `小节大纲.md` 对应节的“结尾承接/钩子”单元格。

生成两份文件后按 `workflow-design.md` 的 Phase 2 完成门禁运行 `node scripts/check-phase2-contract.js --json {短篇目录}`。失败时只按 JSON 的 `repair_scope` 做最小修改并复验，不做无目标整稿重写。

### 写作前加载

- 必读：`short-format.md`（正文格式）+ `short-craft.md`（通用底座）
- 必读：`short-deslop.md`（写作时自检 AI 腔）
- 按题材加载 1 个：`genre-styles/{题材}.md`（核心 10 题材）或 `genre-writing-formulas.md`（冷门题材速查表）
- 按需加载：`villain-and-reveal.md` / `emotional-methods.md`

### 工作目录结构

工作目录结构见 [Phase 2：构思核心框架](../SKILL.md#phase-2构思核心框架)。设定.md 内容构成：核心框架 + 人设 + 反转铺垫 + 贯穿道具（含三次出现追踪表）+ 反派设计 + 对标摘要。小节大纲.md 每节 1 行，格式以 [设计任务（框架确定后执行）](workflow-design.md#设计任务框架确定后执行) 第 4 步为准。

### 操作原则

- 正文直接写入文件，不要只输出在对话里
- 精修时读取文件再改写，修改记录直接体现在设定.md的贯穿道具追踪中
- 设定.md 维护贯穿道具追踪表：
  `| 物件 | 第1次出现(节号/含义) | 第2次出现(节号/含义) | 第3次出现(节号/含义) |`

## Phase 4 精修打磨

### 精修检查清单

```
## 精修清单

### 开头
- [ ] 前 3 句话能抓住人？
- [ ] 没有无意义的背景介绍？
- [ ] 包含一个开篇钩子？

### 情绪
- [ ] 情绪曲线是否有明确走向？
- [ ] 反转前的情绪铺垫够不够？
- [ ] 反转后的冲击够不够？

### 反转
- [ ] 反转是否出乎意料？
- [ ] 反转是否合情合理（回看有铺垫）？
- [ ] 反转时机是否合适？

### 节奏
- [ ] 有没有拖沓的部分？
- [ ] 每句话是否都有存在价值？
- [ ] 字数是否在目标范围内？

### 格式
- [ ] 段落以短为主、有长短交错与疏密变化（非通篇同长度）？无连续超长大段？
- [ ] 段间仅单换行？
- [ ] 对话独立成行、引号风格符合项目/平台约定？
- [ ] 标点节奏匹配语气/人物声线：没有通篇句号化，也没有随机堆砌问号/感叹号，或用 `……`/`——` 硬造停顿？
- [ ] 正文（含对话）里的 `……`、`——`、`—`、`--` 已改成动作、短句、逗号或句号？
- [ ] 对话标签是否避免高频、公式化重复；普通「说/道」低频使用可保留？

### 钩子
- [ ] 钩子是否出现在读者预期、行动方向或关系判断发生变化的位置；有没有连续提问却不局部兑现？
- [ ] 章末是否有未完成动作、新信息、局部兑现、关系变化、余韵或明确下一步之一？

### AI 腔
- [ ] 无禁止比喻：「命运的齿轮」「如潮水般」「仿佛春风」「心猛地一沉」「眼眶泛红」
- [ ] 同一身体部位/情绪描写不超 5 次（统计：手指/心/膝盖/眼睛，超限必须替换）
- [ ] 「像」使用频率：全文不超 10 处（含「像是」「不像」）
- [ ] 完整 AI 腔黑名单见 short-deslop.md

### 技法
- [ ] 情绪外化：直给的情绪词后面是否接了场景里的具体动作或物件？无空泛情绪总结句（一丝X涌上心头）？
- [ ] 信物（若用）：意义翻转是否完整？（查设定.md追踪表）
- [ ] 场景引擎：每节是否通过行动、证据、任务、对话、物件、等待或关系选择改变了至少一项状态？
- [ ] 开头密度：前 100 字事件 ≥ 3？

### 结尾
- [ ] 结尾是否有余韵？
- [ ] 读者会不会想转发？
```

### 标点确定性收尾

精修后对 `正文.md` 先运行 `node scripts/check-ai-patterns.js --check --fail-on=blocking 正文.md`。blocking 先改正文并复扫；advisory 只作读感提示，确属问题才改，功能性写法标 `[需复核]`。
再运行 `node scripts/normalize-punctuation.js 正文.md`（默认 `--quote-mode keep`）清理无功能省略号、破折号、双连字符和独立分隔线；盐言「」不受影响。

### 删减原则

1. 不推动剧情的对话 → 删
2. 不铺垫反转的描写 → 删
3. 不推高情绪的心理活动 → 删
4. 读者能猜到的内容 → 缩短
5. 重复表达的情绪 → 合并

## 常见问题与解决方案

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 开头不抓人 | 在做背景铺垫 | 直接从冲突开始 |
| 中间拖沓 | 信息密度太低 | 删减或合并场景 |
| 反转没力度 | 铺垫不够或太明显 | 增加误导线索 |
| 结尾无力 | 反转后拖太长 | 反转后 500 字内收尾 |
| 全篇平淡 | 情绪曲线太平 | 加大情绪落差 |
| 感觉像流水账 | 缺乏情绪描写 | 加入人物内心感受 |
