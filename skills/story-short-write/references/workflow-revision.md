# Phase 4：短篇精修打磨

> 谁读：精修或质量自检时主会话整份读；构思、写正文不读。

本文件中的 `scripts/` 与 `references/` 路径均相对本 skill 根目录。精修必读本文件与 `short-format.md`（格式快速检查、标点）；新对话里精修也先读它。

写正文时只查情节点写全和格式。**去味默认主会话自己做**：读 `references/short-deslop.md`（短篇卖点保护），先按检测结果和文末精修清单定点修复，再查前后一致；作者明确要交给写手时，才按 agent-calls.md「精修去味」派。作者要完整三层诊断或深查“为何过平”时，转 `/story-deslop`，不在本流程里做。主会话做最终扫描与交付验收，改后只复核改动处并重跑受影响的检查。

问题分两级：
- **blocking（必须修）**：检测脚本报 blocking 的命中，和清单里标「必须修」的项，修完才能交付。
- **advisory（建议看）**：检测脚本的 advisory 命中和清单其余项。回到上下文判断，有功能的写法保留，没功能的改；词句信号拿不准时查 `banned-words.md` 对应一节，不是出现就删。拿不准的列进交付说明请作者定；子代理标的 `[需复核]` 只写在交回说明里，`正文.md` 里不做标记。

文件模式依次运行 `node {skill 根}/scripts/check-ai-patterns.js --check --fail-on=blocking {短篇目录}/正文.md`、`node {skill 根}/scripts/check-outline-copy.js --outline {短篇目录}/小节大纲.md {短篇目录}/正文.md`、`node {skill 根}/scripts/normalize-punctuation.js {短篇目录}/正文.md`（默认 `--quote-mode keep`：引号里的省略号保留并统一成 `……`，引号外的省略号和破折号、双连字符、独立分隔线按 short-format「标点」整理，白名单里登记过的不动；保留盐言「」）、`node {skill 根}/scripts/check-degeneration.js --check {短篇目录}/正文.md`，blocking 先改正文再复扫。照搬检测报出的誓词、关键原话等功能性台词保留，登记进 `小节大纲.md` 表格下方「原样出现的原话：」（旧书叫「复沓锚句」）再复检，其余现场重写。

全部落盘后运行 `node scripts/check-delivery-contract.js --json --min-chars {MIN} --max-chars {MAX} --sections {N} {短篇目录}`。exit 0 才可交付；exit 1 只按 `repair_scope` 最小修复并重跑受影响的质量检查与本命令，最多 2 轮；仍失败则停止，按下方交付说明告诉作者哪项没达标、差多少。exit 2、脚本缺失或不可执行时不得声称交付契约通过。它只验字数、节数与排版。

#### Agent 调用：narrative-writer（作者要求时）+ consistency-checker

narrative-writer 只在作者明确要交给写手去味时派，prompt 见 [agent-calls.md](agent-calls.md)「精修去味」。按 SKILL 顶部的当前宿主角色来源确认可用时，一致性检查派 `consistency-checker`，Prompt：`项目目录：{dir}\n检查范围：{正文文件}\n检查类型：事实冲突+伏笔断线+角色属性不一致`。agent 不可用时主会话直接执行。

**正文洁净规则**：自检结果只在对话中说明，不另存或附正文；正文不得出现 `<!-- 自检 -->` 等检查标记。

**交付说明（给作者看）**：用白话说明：
1. 写了什么：标题、一句话核心钩子或反转、总字数、几节。
2. 要作者拍板的事：每件写成一句问题并附推荐默认（如「结尾要不要再留个小反转？默认不留」）；没有就省略。
3. 下一步可选：精修某段、去 AI 味、换平台改写等。

自查结果只写一句（如「自查过字数、分节和常见 AI 腔，都过了」；没过就说哪项差多少）。不写脚本名、检查 ID、字段名、参数或表格格式；写作助手用不了或是旧版时，按 SKILL.md 顶部各说一句白话，不另加技术备注。

## 精修清单

反转项只用于反转篇；无反转时核对「最后兑现什么」与关系递进。专项只在对应题材检查。删减按 SKILL.md 执行规则「每句话必须有用」。

```
### 前后一致（必须修）
- [ ] 人物动机转变有触发事件，关键行动符合人设
- [ ] 核心冲突、设定、时间线、人物信息前后一致，与设定.md 对得上；伏笔有回收
- [ ] 反复出现的物件（若用）意义翻转完整；改了出现位置，同步改 设定.md「反复出现的物件」表
- [ ] 字数、节数过 SKILL.md「Phase 3 完成门槛」：不足只补回原计划内容，超出删不推动剧情的内容

### 开头与成稿形态
- [ ] 首句从事件、对话、动作或信息开始，不从天气、风景、背景介绍开始
- [ ] 导语在正文最前（不写「导语」二字），交代核心冲突、留住底牌，和第 1 节衔接自然
- [ ] 付费点断在 设定.md 指定节末的未完成动作、证据/身份变化或两难选择上，核心大爽点没在付费点前放完

### 推进与钩子
- [ ] 每节按 SKILL.md「小节完整性流程」完成职责；节尾按小节大纲「节尾停在哪」落地，连续提问之间有局部兑现
- [ ] 同一情绪不连写三段以上；回忆短，且带出新视角
- [ ] 对白推动信息、策略、权力或关系变化，没有连串微型问答，也不换说法重复同一层意思

### 情绪与反转
- [ ] 情绪按 设定.md「情绪设计」的整体走向起落；虐爽题材一路只虐或只爽都要调
- [ ] 反转回看有铺垫，误导信息真实；最大兑现放在前因汇合、证据足以支撑的地方，反转后只写兑现与余韵

### 打脸、复仇专项
- [ ] 每个证据前文埋过线索，每次释放都改变行动或读者判断，最后一个改变全局认知；提前布好的证据符合主角能力、时间线和取证条件
- [ ] 主角的冷静靠取证、选择、延迟回应或调度资源体现，不配端水杯、整理西装、转笔这类标志动作；失控要改变行动、关系或代价
- [ ] 反派的反应由他的筹码、误判和损失决定，报应和他此前的行为有因果
- [ ] 台词长短、打断和沉默随双方筹码变化；审判式提问只在能逼对方选择或暴露矛盾时用

### 追妻、情绪流专项
- [ ] 女主心死后彻底抽离，不再照顾男主；最迟到付费点前已心死离开
- [ ] 男主有颜值、能力或地位的资本，读者才会期待他追回；他在女主抽离后才醒悟，伤得深就不轻易原谅
- [ ] 反派有真实动机，不靠降智

### AI 腔
- [ ] 比喻、情绪词与反应看上下文作用，不凭「如潮水般」「心猛地一沉」「眼眶泛红」这类孤立词句判错；空泛总结和套路修辞换成具体行动
- [ ] 重复的身体、情绪描写没有新信息就删，不换部位或同义动作凑数；内心独白只压空转部分
- [ ] 辞藻堆砌、书面腔改成口语或具体动作；相关动作连起来写，不拆成三五字的碎句
- [ ] 「像/好像/仿佛/如同」不成片堆叠；超过 10 处或检测器报比喻密度时逐处复核功能，有功能的留，不设硬上限、不机械全删
- [ ] 情绪落地按 short-craft「情绪落地」查上下文支撑；短篇卖点保护见 short-deslop.md

### 格式
- [ ] 按 short-format.md 文末「写完每段快速检查」逐项过，另查有无连续超长大段
```
