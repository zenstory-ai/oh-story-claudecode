# agent-calls.md：短篇派写手助手调用

> 谁读：仅当作者明确要求把写正文或精修去味交给 `narrative-writer` 时读取；直接写作与去味不读。

下文只列传给 `narrative-writer` 的内容边界；具体派发字段按 `SKILL.md` 顶部的当前宿主映射。

## 1. 派写正文

写手读不到本 skill 的 `references/`，调用前把下列信息摘进 prompt：

- **基础资料**：项目目录、输出文件 `正文.md`、本批要写的节号、目标情绪、`设定.md`（含导语草稿与平台基调）与 `小节大纲.md` 对应行。
- **流派与语感锚点**：命中的流派包要点（开篇公式、付费卡点、核心打脸招式、雷区）+ **2–3 段 150–250 字语感切片**（有同题材对标优先用 `设定.md` 里的原文切片，无对标直接贴流派包示范切片）。
- **硬格式与短篇笔法**：第一人称默认、手机竖屏单句成段（~20 字中位，单换行无空行）、按平台控口语对话占比（点众/黑岩 33%–48%，七猫/番茄 26%–35%，知乎吐槽/悬疑独白 15%–22%）独立成行、自然 `！`/`？` 与旁白 `——`、禁止元信息词。
- **偏好与分工**：作者这次说的要求、作者偏好 query 输出的 `lines`（在 prompt 填入一行 `\n作者偏好：{lines，无写无}`）；明确要求写手先保网感、情节与格式，完整检测扫描由调用方收尾。收到结果后按 `SKILL.md` 格式重排写入 `正文.md`。

## 2. 派精修去味

仅作者明确要求代修时派发 `narrative-writer`，在 prompt 中声明 `任务描述：审查+去AI味` 并带：

- **篇幅模式**：`短篇（--mode=short）`，强制读取写手资料里的短篇卖点保护（短篇去味覆盖规则）。
- **修什么**：只修检测命中的 `review_required` 与 5 类真 AI 味（论文公文腔、空洞哲理尾、纯景物铺垫、车轱辘复述、元信息词）。
- **保什么**：严禁把单句短段焊成长段、严禁删掉第一人称直给情绪/吐槽/剧透/围观震惊/反派嘴贱台词与自然标点；不得擅改主线事件与结局清算。
- **交回标准**：复读修改段及前后节衔接，写清改了什么、为什么保留，字数不达标如实交回。
