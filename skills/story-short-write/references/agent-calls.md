# agent-calls.md：短篇派写手的调用方式

> 谁读：写正文或精修去味要交给 narrative-writer 时主会话读。

下文只给目标角色与 prompt；调用参数按 SKILL 顶部的当前宿主映射。

## 写正文

派 `narrative-writer`，只传项目目录、输出文件、目标情绪、题材包要点、小节大纲、角色、「参考的书」里召回的写法、写法要求、作者偏好 query 输出的 lines、格式硬约束和写作硬约束，并传入检查分工：本批只做内容覆盖与格式自检，完整语义去味在精修时做，最终文件扫描由主会话负责。

写手读不到本 skill 的 references，主会话把要点摘进 prompt。题材包要点取 `设定.md`「这篇用的套路」及题材包的腔调、开篇收尾套路、情绪烈度；写法要求取作者这次说的与 `设定.md`「文风约定」「作者已定」，先后按 short-craft 开头那一句；写作硬约束取 short-craft「情绪落地」「句段节奏」与 scene-craft 要点，人称腔调与叙述姿态按题材包；格式硬约束取 `设定.md`「平台基调」（其余格式写手按自己的格式文件，标点与 short-format「标点」一致）。主会话收到结果后，按 workflow-draft.md 的格式规范重排，再写入 `正文.md`。

## 精修去味

作者明确要交给写手时才派。spawn `narrative-writer`，Prompt：`项目目录：{dir}\n任务描述：审查+去AI味\n检查分工：你负责本次精修清单与检测命中的定点语义修复及格式检查；最终文件扫描由主会话执行\n检查范围：{正文文件与待修位置、问题类别}\n检测类别：{照录命中类别，对应关系见写手资料 deslop-gates「按检测类别或问题限定范围」；类别不明写全部表达与用笔项，仍只处理本次精修问题}\n写法要求：{作者这次说的与 设定.md「文风约定」「作者已定」要点，没有写「无」}\n作者偏好：{query 输出的 lines}\n篇幅：短篇\n卖点保留：第一人称审判、火葬场预告、心死余韵按具体功能保留；压掉空泛与重复，不强制补反应\n执行边界：按写手资料 deslop-gates 的范围与权限修复；不扩大为完整故事重写；需新增动机、证据、事件或改变选择、结果、揭露时机的给出具体设计建议，已授权的执行\n验收：复读完整场景及小节承接，说明原文问题、修改动作与保留理由；不用固定删减率，字数不足如实交回`
