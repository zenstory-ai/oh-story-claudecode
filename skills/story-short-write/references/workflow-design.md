# 构思：写 设定.md 与 小节大纲.md

> 谁读：构思时主会话整份读；写正文、精修不读。

从目标情绪反推剧情：先和作者定核心框架，再执行「设计步骤」，最后把 `设定.md` 和 `小节大纲.md` 写入工作目录。正文只读这两份文件，构思内容必须落盘。

**导入的书**：`设定.md` 有「已写部分的写法」（旧书叫「本书续写基线」）时只补标 `[待补充]` 的项，不改已写章节的设定和大纲行，新节排在第 N 节之后。

#### Agent 调用：story-architect

按 SKILL 顶部的当前宿主角色来源确认 story-architect 可用时，可派它辅助框架设计，Prompt：`项目目录：{dir}\n任务类型：短篇构思\n查询参数：{目标情绪+题材方向}\n题材包要点：{所选题材包的节奏骨架、套路、开篇与收尾范式}\n平台要点：{本平台的基调、格式、导语写法与付费点位置}`。它读不到题材包和平台表，两项要点由主会话摘进 prompt；不可用时由主会话直接执行。

#### 设计步骤

**作者给的开头和设定照用。** 读者图的是情绪和痛快，不用按办案标准抠逻辑：不替作者补「为什么不早报警、早救人」这类漏洞，也不为了合理改掉作者写的设定；筹码按题材定实（虐爽押命、钱、孩子、名声；甜宠、沙雕、悬疑押关系、体面、秘密或性命），别缩成程序纠纷。

1. **定平台和题材**：读 `references/submission-craft.md` 定投稿平台，把该平台的基调、格式模板和导语写法记进「平台基调」；再读核心 10 题材对应的 `references/genre-styles/{题材}.md` 和 `references/short-craft.md`，从题材包「招式库」选 2-3 个套路写进「这篇用的套路」。冷门题材把参照的结构写进同一区，供写正文和精修使用。
2. **定情绪走向**：按 emotional-methods「整篇弧线与转折位置」选一种走向，写进「情绪设计」；写正文按它安排各节的情绪，不另设逐节递增。
3. **反复出现的物件**（可选，1-2 个）：一件物件出现三次，意义随剧情翻转，各记节号和当时的含义。
4. **反派与揭露**（有反派或真相揭露时）：读 `references/villain-and-reveal.md`，反派五字段写进「构思要点」，揭露方式写进「反转与揭露」；不需要时写明原因。
5. **小节大纲**：按下方模板写 `小节大纲.md`。先按 `submission-craft.md`「付费点」定付费点卡在哪一节末，用未完成动作、身份或证据变化、两难选择形成断点；把这一节想透，再倒排前后各节。任务卡点只在能推动情绪、证据、关系、反转或反击时使用。付费点写进该节的「节尾停在哪」；节尾怎么停只在 `references/hooks-chapter.md`「2. 节尾」定，拿不准时查它。
6. **反转与伏笔自查**（有反转时）：大纲写完后按下文「反转信息差验证」「伏笔回查」在心里过一遍，有漏洞就改大纲；不用把检查过程写进文件。

情绪设计里的「反转处」只用于有反转的篇目；无反转时写报应兑现或甜度变化的高潮处。

```markdown template=短篇设定
## 短篇核心框架

### 基本信息
- 标题（暂定）：{}
- 目标字数：{} 字（阿拉伯数字；作者没定时用该平台的投稿区间，未定平台用 8000-12000）
- 目标平台：{知乎盐言 / 番茄 / 七猫 / 黑岩 / 小程序 / 未定}（选一）
- 平台基调：{视角、矛盾烈度、节尾怎么停、结局质感；小节标记、引号和段落格式；导语字数和第 1 节怎么接}
- 目标情绪：{读者读完的感受}

### 一句话梗概
{主角 + 困境 + 反转 + 情绪落点}

### 这篇靠什么撑住
- 类型：{身份/视角/动机/时间线/信息/认知反转，或无反转}
- 最后兑现什么：{一句话写主揭示；无反转时写报应或关系兑现}
- 前面怎么埋：{关键铺垫点；无反转时写读者等着兑现的因果或关系变化}

### 情绪设计
- 整体走向：{先压后扬 / 先甜后崩 / 几起几落 / 一路上扬 / 憋到最后爆 / 最后急转，一句话说读者的感觉怎么走}
- 开头：{读者此时什么感觉}
- 中段：{读者此时什么感觉}
- 反转处：{读者此时什么感觉}
- 结尾：{读者读完什么感觉}

### 人设速写
- {角色}：{一句话人设}；说话方式：{}；口头禅：{有来由才写，可写无}（每人一行）
- 关系：{他们之间的关系}

### 这篇用的套路
- {套路名}：{本篇怎么用、落在哪几节}（2-3 条，一条一行）
参照的结构（冷门题材才写）：{分几段、每段读者什么感觉、必须有的场面和规矩}

### 文风约定
- {本篇对句子、标点、用词的明确要求；没有就写「无」}

### 作者已定
- {作者在对话里定下的人称、偏好、红线，一条一行；否掉的方案也记一行，写明为什么不要}

### 反转与揭露（有反转或揭露时）
- 揭露方式：{在第几节、当着谁的面揭开，靠什么揭开}

### 反复出现的物件（选用时）
| 物件 | 第一次（节号/含义） | 第二次（节号/含义） | 第三次（节号/含义） |

### 参考的书（有对标时）
| 书名 | 主要参考 / 顺带参考 | 同题材 / 不同题材 | 能学的写法 |

## 构思要点
- 题材：{题材包名，如 追妻火葬场；冷门题材写「冷门：所用公式名」}
- 反派：没有（{原因}）
- 反转类型：{身份/视角/动机/时间线/信息/认知/无反转}

- 付费点：第 {N} 节末
```

有反派时按 `villain-and-reveal.md` 人设模板，把「反派：没有」换成身份、动机、作恶方式、致命弱点、报应五行（一字段一行）。`short-reversal.md` 判断确属无反转题材时，写 `反转类型：无反转` 和 `反转在：不适用（{报应兑现/甜度递进等原因}）`，不硬编节号。

#### 小节大纲.md 模板

<!-- 按名读取：表头第一列「在全篇哪一段」、「节尾停在哪」（付费点）、「目标字数」（构思检查按列名找列，旧表头「结构段/五段功能」「结尾承接/钩子」等照认）；「原样出现的原话」（照搬检测）。 -->

每节一行，下接 Markdown 分隔行。只要五列；小节大纲是给自己看的路线，别当案卷把证据、线索、因果都塞进表里。

```markdown template=小节大纲
| 在全篇哪一段 | 这节发生的事 | 情绪 | 节尾停在哪 | 目标字数 |
|---|---|---|---|---|
```

- `在全篇哪一段`：开头/铺垫/升级/反转（无反转篇可写高潮）/结尾
- `这节发生的事`：一句话写本节真实发生的改变，谁做了什么；不设数量下限，相关情节点可以由同一动作链或对话同时兑现，不为凑数加阻碍、配角反应、短回忆或意外
- `节尾停在哪`：本节怎么接下一节；付费点那一节标「付费点」；最后一节写结尾落点
- 照搬检测报出要保留的原话时，登记在表格下方一行 `- 原样出现的原话：`，每行一条（精修时加）

#### 反转信息差验证

- 全篇同主线：开头困境、中段升级、反转与结尾须围绕同一矛盾，不半路换故事
- `short-reversal.md` 判无反转：写明理由，改查报应或甜度期待是否铺垫并兑现，跳过下方检查
- 记下读者在第几节知真相，只供核对篇幅，不是通过线
- 揭示前：错误解释是否已影响重要决定？没有就补后果或调位置
- 揭示后：是否留出新行动、关系变化或结算？只剩解释就提前揭示或压说明
- 双层反转：第一层揭开后要有基于它的新行动，拉开两层功能距离
- 反转前把真相线索藏进日常细节，正读忽略、回看能找到
- 遮住反转节及之后，只看前文「这节发生的事」：正读猜出算泄底，回看推出算公平

#### 伏笔回查

- 列出结尾关键元素（物件、信息、角色、关系变化），前文须有铺垫；没有就补
- 选了反复出现的物件时三次齐全：铺垫段、反转段、结尾段各一次
- 铺垫与揭穿之间隔开其他事件或误判，别刚埋就揭

#### Agent 调用：character-designer

只在作者要细化人设（声音、口头禅、人物小传）时，按 SKILL 顶部的当前宿主角色来源确认 character-designer 可用后派出，Prompt：`项目目录：{dir}\n任务类型：角色设定\n查询参数：{人设速写+关系}`；平常由主会话直接写。结果整理为每人一行（说话方式、口头禅、禁忌）写进 设定.md「人设速写」，写正文只读这里。

#### Phase 2 完成门禁

两份文件生成后、向用户声明构思完成或进入 Phase 3 前，运行 `node scripts/check-phase2-contract.js --json {短篇目录}`：

- exit 0：Phase 2 机械契约通过，可进入下一阶段；故事质量仍需判断
- exit 1：只把 `repair_scope` 中的检查 ID、证据、期望、reference 路径和修复范围交给本轮 writer；只改失败字段，再运行同一命令
- 最多做 2 轮定向 repair；仍失败则停止，用中文告诉作者设计还缺什么，不得声称 Phase 2 已完成
- exit 2、脚本缺失或不可执行：告诉作者自动检查没跑成，不得用泛化“自检”替代后继续
- 向作者汇报构思只讲故事（梗概、反转、付费点在第几节）和待拍板的问题（附推荐默认），不提脚本、检查 ID、字段或表格列数；作者拍板的改动先写回两份文件并重跑本门禁，汇报末尾按 SKILL.md「写前必读」建议新开对话写正文
