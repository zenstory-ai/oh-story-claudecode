## 2. 网文短篇笔法与平台表

**总铁律：商业短篇是强情绪爽感消费品：开篇百字抛炸弹，中后段连环打脸，结尾明账清算。** 公平推理、留白与慢热**仅限 `悬疑.md`**（或作者指定慢虐）；其余禁前 1/3 慢热、端余韵或洗白反派。

1. **人称声线**：默认第一人称「我」（含男频都市；作者或流派要第三人称才换）。叙述者在场：直给情绪、主观吐槽审判、提前剧透火葬场或底牌（「他们不知道……」）。
2. **竖屏排版与烟火物象**：默认单句成段，中位 **~20 字**，八成 ≤30 字，禁 >80 字砖块，单 `\n` 无空行无缩进禁 Markdown；对话独立成行，用日常物价/烟火物件锚定，少堆黑卡、香槟、百亿、大屏等悬浮套具。
3. **对话网感**：占比 **30%–40%**，首百字见冲突/对白；来回短打为主（**单句多 ≤15 字**，**≥45 字长演讲拆成问答/动作打断**）；口语算账禁公文腔，非悬疑允许直球摊牌、偷听、反派自白与围观震惊。
4. **克制标点**：**叙述默认 `。`**，`！` 留给峰拍震惊/揭底（`！+？` 控在 **8–14/千字**，禁旁白咆哮）；旁白 `——` 全篇 `≤5` 处（仅关键反转）；对话可用 `……`。
5. **冷开场导语（150–300 字）**：置首节前不写「导语」，前 3 句零景物/背景，直入背叛炸弹、重生反常选、强设定破局或底牌预告；停当下第 1 节顺接，写后果倒回补现场不抄导语。
6. **节奏卡点**：首节 1,300–1,600 字；3–4 节末（30%–40%）卡未落巴掌/刚掀底牌；**40% 起高频打脸**不拖尾；非末节 ≥70% 带硬钩子（狠话/来人/动作打断/证据露角）。
7. **明账清算**：除 `悬疑.md` 留白外，反派付实质代价（破产/入狱/社死/内讧/追悔被拒），主角高位收口；禁哲理空尾。

| 平台 | 调性 | 排版、标记与引号 | 字数 | 首章与付费点 |
|---|---|---|---|---|
| 知乎盐言 | 脑洞吐槽/大女主反杀/生活违和 | 极短段（~18字）；`1.`；`「」` | 10000–13000 | 30%–40% 折页强翻面 |
| 七猫 | 豪门/世情/男频反杀，清算痛快 | 短段（~21字）；`###第N章`（无小标题）/`###1.`；`“…”` | 9500–12000 | 首章 1300–2000字，3–4 节末 |
| 黑岩 | 强情绪虐爽/复仇/世情/民俗 | 一句一段（~20字）；`###1.`；`“…”` | 9500–12000 | 独立导语 + ~10 节，3–4 节末 |
| 点众·小程序 | 羞辱→亮牌→围观打脸快循环 | 极短段高对白（~19字）；`###1.`；`“…”` | 10000–13000 | 首章 ~1400字，卡脖子断点 |
| 番茄 | 顺滑无毒点，反派速成垫脚石 | 短段交织对话（~21字）；`###第N章`（无小标题）；`“…”` | 8000–12000 | 三成试读末节强翻盘钩 |

小节标记独占一行、后不接小标题；未定平台写 `未定`，默认 `###1.`、`“…”`、9500–12000 字。

## 4. Phase 3：锚定切片，连续落稿

**导入的书**：读「已写部分的写法」，正文从第 N+1 节接着写，不改已写节。

1. **锁参数**：作者字数范围优先（单数取 95%–105%，未给取 `设定.md` 与大纲节数）。写前跑 `node {skill 根}/scripts/check-delivery-contract.js --json --check-contract --min-chars {MIN} --max-chars {MAX} --sections {N} {短篇目录}`（exit 2 请作者调参数）。
2. **锚定切片**：每批前重读流派包（或对标）**2–3 段示范切片**，锁定「短段 + 高对白 + 口语吐槽」语感。
3. **2–3 节/批写 `正文.md`**（续写前重读导语与末尾 400 字；9–10k 目标按批控初稿在 **9,200–9,400 字**留修订余量）：导语（150–300 字）+ 第 1 节（1,300–1,600 字）打透赌注 → 第 2 节至付费点（30%–40%）阶梯加压卡死刀口 → 40%–85% 亮牌反打、写实围观 → 85%–100% 明账清算落地。
4. **红线**：叙述、对话与心理描写禁 `第X章`、`上一章`、`本章`、`前文`、`后文`、`伏笔`、`细纲`、`读者`（仅标题与小节标记允许）；欠字扩写现场对话反应，超字压重复解释。

## 字数统计

整篇字数以 `check-delivery-contract.js` 为准；查逐节与导语字数在书目录运行 Node.js 18+ 命令：

```bash
node -e '
const fs = require("fs");
const pat = /^(?:###\s*\d+\.|###\s*第[一二三四五六七八九十百千万两〇零0-9]+章|\d+\.)$/;
let cur = null, buf = [], out = [];
for (const line of fs.readFileSync("正文.md", "utf8").split(/\r?\n/)) {
  const s = line.trim();
  if (pat.test(s)) { out.push([cur, buf]); cur = s; buf = []; }
  else buf.push(line);
}
out.push([cur, buf]);
for (const [name, body] of out) {
  const n = [...body.join("").replace(/\s+/g, "")].length;
  if (name !== null || n) console.log(name || "导语", n);
}
'
```

## 5. Phase 4：快检、短篇去味与交付

1. **网感与一致快检**：自查首百字见冲突零纯景物、短段无 >80 字砖块、对白密、付费点后连环反击、清算落地（非悬疑禁样板尾句），并做**前后一致检查**（可用派 `consistency-checker`，否则自查动机、时间线与伏笔）。
2. **短篇去味**：只砍①论文公文腔②空洞哲理/样板尾句③无冲突纯景物④车轱辘复述⑤工程词。**放行**直写体感（`脸色一变/心口一沉`）、剧透审判、围观震惊、第一人称吐槽、单句成段与自然 `！`/`？`/`——`（旁白 `≤5` 处）。`.deslop-whitelist`（一行一句，上行 `# 来源：…`）**只记作者明确写法，禁自行放行或登泛词**。
3. **短篇模式验收**（脚本位于 `{skill 根}/scripts/`）：依次跑 `node …/normalize-punctuation.js --mode=short {短篇目录}/正文.md`、`node …/check-ai-patterns.js --mode=short --check --fail-on=review_required {短篇目录}/正文.md`、`node …/check-degeneration.js --check --fail-on=blocking {短篇目录}/正文.md`、`node …/check-outline-copy.js --outline {短篇目录}/小节大纲.md {短篇目录}/正文.md`（功能复沓记大纲末 `原样出现的原话：`，逐行缩进写）与 `node …/check-delivery-contract.js --json --min-chars {MIN} --max-chars {MAX} --sections {N} {短篇目录}`。硬错（exit 1）最多修 2 轮，仍不过停告作者；exit 2 或未跑成不得声称通过；正文禁留 `<!-- 自检 -->`。
4. **白话交付**：只报字数、节数、核心亮点（导语/卡点/清算）和下一步建议，不报脚本名与检查编号。
