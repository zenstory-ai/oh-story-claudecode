# 短篇源文钩子分析标尺

> 观察源文在段落、小节和付费断点处如何改变读者预期。只报告已出现的钩子、承诺与后续回应，不提供章首章尾模板，不套连载循环或固定字数。

## 钩子成立条件

判断段落或小节边界是否形成钩子，先看它改变了“读者接下来等待什么”。断句、情绪升高、角色震惊或预告须结合具体问题判断。

每个候选点记录：

```markdown
位置：{段落/小节/付费断点}
边界前已知：{事实与判断}
边界新增：{动作、证据、关系、风险或选择}
读者新问题：{具体问题}
后续回应：{位置与交付}
```

## 功能类型

| 类型 | 可观察变化 | 常见假阳性 |
|---|---|---|
| 未完成动作 | 角色开始一项有风险的行动，结果尚未出现 | 只说“他决定了”，下一节没有行动 |
| 证据归属 | 新证据出现，持有人、真伪或解释权改变 | 只增加一条背景资料 |
| 身份/动机裂缝 | 行为与表面身份或动机出现可回溯矛盾 | 结尾直接宣布“他有秘密” |
| 关系转向 | 信任、联盟、控制或责任发生变化 | 只有情绪争吵，关系位置未变 |
| 两难选择 | 两个真实代价同时成立，角色尚未选择 | 假选择，其中一项明显不可能 |
| 风险落地 | 抽象威胁变成具体期限、损失或追责 | 只扩大形容词，不改变行动条件 |
| 阶段答案 | 一个局部问题得到可信答案，同时暴露解释缺口 | 回答后立刻无因果地再翻一次 |
| 后果反打 | 刚完成的行动产生未预料但可追溯的后果 | 天降新危机，与前一行动无关 |
| 情绪欠账 | 一项关系或伦理选择尚未结算 | 用作者总结代替人物后果 |

## 强度判断

不用主观等级或“必须点击”的形容判断。比较三个可复核维度：

1. **预测变化**：边界是否让读者更新对嫌疑、关系、结果或代价的预测。
2. **行动牵引**：下一段/节是否必须回应这个变化，而不是另开话题。
3. **兑现质量**：回应是否交付证据、选择或后果，而非只重复问题。

结合三个维度说明牵引强弱及原因；部分成立时分别记录满足哪一项、缺少什么，不只贴强弱标签。

## 钩子链

钩子链通过因果衔接：前一问题的回应成为下一问题的原因。按下表追踪：

| 起点位置 | 问题 | 回应位置 | 回应交付 | 如何生成下一问题 |
|---|---|---|---|---|

若后一个问题与前一个答案没有因果关系，报告为“另起问题、链条断开”；若连续多个问题都没有局部回答，报告为“只提问不回答”。

## 付费断点

付费断点是商业位置，钩子是叙事功能，两者不能互相证明。分析时分别检查：

- 断点是否落在未完成动作、证据归属变化、关系转向或真实两难上。
- 付费后是否尽快回应断点承诺。
- 回应是否推进主问题，而非用旁支拖延。
- 核心大爽点是否在断点前就已放完。
- 如果没有平台信息，只报告“候选强断点”，不推测实际收费位置。

## 报告格式

```markdown
关键钩子：{位置、类型、边界前后变化}
读者新问题：{具体问题}
后续回应：{位置、交付}
钩子链：{因果接力或断裂}
付费断点：{已知/候选/证据不足}
弱边界或假钩子：{位置与原因}
```

## 边界

- `structure_counts.hooks` 数的是上表功能类型成立的钩子，按实际数填，可以为 0；不要求每节必须有强钩子，也不把固定数量作为质量门槛。
- 不把围观者震惊、系统奖励或新地图自动判作钩子，必须证明它改变了读者问题；围观反应只在带出新信息、改变公众评价或逼出行动时记一笔。
