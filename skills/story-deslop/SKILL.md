# story-deslop：网文去AI味

**文风裁决**：先读 [references/style-resolution.md](references/style-resolution.md)，加载本书文风，复用调用方的 `style_resolution` 与作者偏好；单独调用时按当前请求与本书文风裁决，并交给后续执行者。

**改写重点：表达自然、笔墨有重心、故事有依据；诊断与执行按作者范围，不把网文改成慢热严肃文学。**

## 执行边界

- 未限定范围时完整查表达、用笔、故事三层；用户指定词句、段落或某类问题时只查指定范围。
- 可直接修表达、恢复已有承接、删无功能冗余或调详略，但须保护伏笔、因果、人物选择、情绪体验与揭露顺序。改变事件、动机、结果或新增成立条件，须先出设计提案获授权；不靠加微动作、粗话或硬造冲突制造「真人感」。
- 文风裁决只管表达，不改事实与信息边界。准确直写情绪、角色算账判断、带立场叙述与功能性停顿均可保留，不机械套「只展示不说明」、固定句长或删减率。
- 只要求检测时只出诊断、不改正文；说「去AI味」「这篇太AI了」按改稿处理（表达与用笔直接改，故事层缺口给选项待授权）。作者报告用白话、原文位置与读感后果，不写检测类别名或脚本字段。
- 长篇项目（有 `正文/` 与 `追踪/`）涉及事件、关系、人物所知或结果修改时，即使已授权也带诊断转 `/story-long-write`「修改第X章」执行以同步追踪；本流程只改表达、用笔与已有依据的承接。
- 接收外部报告或 `/story-review` 结论时，只提取可定位到正文的问题。只复用调用方已有的作者偏好，独立调用不查不记作者记忆。

## 去味流程

### Phase 1：读原文与三层扫描

由正文路径定书目录与篇幅：单个 `正文.md` 为短篇，`正文/` 下逐章文件为长篇（优先作者/项目明确说明）。短篇必读 [references/short-deslop.md](references/short-deslop.md)，其规则覆盖表优先于通用默认值。

读取 [references/deslop-guide.md](references/deslop-guide.md)（含表达/用笔/故事三层方法、deslop-guide.md「按检测类别或问题限定范围」与 23 类脚本信号索引）；需核对具体词条时再查 [references/banned-words.md](references/banned-words.md)。通读本次正文并按需查相关前文/已定设计，不整读无关全书；资料缺失标明未知。多章时逐章跑完 Phase 1–4 再进下一章。

本地正文先跑确定性预检（从本 skill 根执行，正文用绝对路径；`--mode=auto` 对 `正文.md` 自动走 short 模式，非 `正文.md` 的短篇文件传 `--mode=short`）：

```bash
node scripts/check-ai-patterns.js --check --fail-on=review_required --mode=auto <正文文件...>
```

脚本命中只是线索，零命中不替三层扫描。`review_required` 重点复核（优先改写，确属剧情需要可说明理由保留或登记白名单），`advisory` 回语境判断。文件前 6 行内有 `<!-- 去味:跳过 -->` 时仍照常去味：`review_required` 清零后删该行，未清零则保留并告知作者。

### Phase 2：定位问题与确定改法

逐条记下原文位置、读感损失、所缺依据与最小改法，区分「直接修 / 需设计待授权 / 资料不足」。先定故事成立条件，再调场景用笔，最后修词句；剧情缺口未授权时先修独立可修项，不拿总结句或微动作遮盖因果缺口。仅检测时到此按下方模板交付，改稿时作为 Phase 3 依据。

<!-- author-report -->
```md
## 检查结果
- 表达：{实际问题 / 未发现明显问题 / 本次未检查}
- 用笔：{实际问题 / 未发现明显问题 / 本次未检查}
- 故事：{实际缺口 / 未发现明显问题 / 资料不足范围 / 本次未检查}

| 位置与原文 | 读起来有什么问题 | 建议怎样处理 |
|---|---|---|
| {可定位原文} | {具体损失或断点} | {直接改法，或需设计的最小选项与影响} |

{资料不足写清无法核实什么；无则省略。}
```

### Phase 3：按授权改稿

> 宿主与版本：只查当前宿主的 `narrative-writer`：Claude `.claude/agents/{agent}.md`（`subagent_type`）、OpenCode `.opencode/agents/{agent}.md`（`subagent` 的 `agent`）、Codex `.codex/agents/{agent}.toml`（`agent_type`）、Antigravity `.agents/agents/agent-name/agent.md`（`invoke_subagent` + `TypeName`）、ZCode 插件注册角色（`Agent` 按当前 schema）。先读项目根 `.story-deployed` 的 `agents_version`：与 `agents_version: 46` 不一致时照常检查并 spawn，用一句白话提示更新（小于 46 提示跑 `/story-setup` 后新开会话，大于 46 提示先更新插件/仓库、勿旧版降级覆盖）。仅当前宿主角色缺失或不可调用时降级直接改，白话告诉作者「这次由我直接改」，不加技术备注行。

改文件前先备份原文到书内 `.story/work/去味原稿/{YYYYMMDD}_{原文件名}`，供 Phase 4 对照与作者撤回。已在 `narrative-writer` 内或宿主无可用角色时直接改；否则派当前宿主 `narrative-writer` 执行（方法由写手按自身读取表加载，不抄规则正文）：

```text
项目目录：{绝对路径}
任务描述：审查+去AI味
正文文件：{本章/本篇绝对路径}
已读依据：{相关前文、设定与设计路径；缺失写明}
检查范围：{完整三层 / 指定段落、问题或类别}
本次诊断：{表达、用笔、故事实际问题与原文位置}
执行授权：{可直修范围；已授权重写及须保留的事实、结果、揭露时机}
文风路径：{本书文风全文路径；无则写无}
style_resolution：{生效要求及来源、覆盖的默认条款、事实与信息边界}
作者偏好：{调用方已有偏好；无则写无}
篇幅与格式：{长篇/短篇、字数与格式要求；短篇须读 short-deslop.md 按规则覆盖表执行}
检查分工：只做本次语义改稿，不按细纲补情节；父流程负责最终脚本复扫。
返回：按授权直接落改；只回路径、实际修改、未解决项与必要设计方案，不回全文。
```

### Phase 4：回读与文件收尾

对照原稿备份、已定设计与授权通读完整场景，复核事实、选择、因果、情绪承接与详略是否守住、有无引入新套式。落盘后跑复扫（非 `正文.md` 短篇传 `--mode=short`）：

```bash
node scripts/check-ai-patterns.js --check --fail-on=review_required --mode=auto <正文文件...>
node scripts/check-degeneration.js --check --fail-on=blocking <正文文件...>
```

- 退出 1 为有 `review_required`（句式）或 `blocking`（退化），退出 2 为命令/文件错。
- 句式 `review_required` 优先自然改写，确需保留可说明理由（长篇提交传 `--ack <rule-id>:<理由>`）或登记白名单；退化 `blocking`（复读/打转/截断/工程词）必须重写受损段再核对事实。
- 语义改完且无硬阻断后整理标点（完整去味跑脚本；局部修改只在范围内人工修）：

```bash
node scripts/normalize-punctuation.js --mode=auto <正文文件...>
```

标点脚本保留引号、系统面板 `【…】`、标准省略号 `……` 与标准破折号 `——`（长短篇均保留标准 `——`，只修畸形破折号/双连字符并删独立分隔线；旁白 `——` 过密交 `check-ai-patterns.js` 复核），默认不改引号（作者明确要求才加 `--quote-mode`）。仅针对新发现问题最多复扫三轮，无新问题即停；脚本不可用时如实说明，不宣称通过。

### Phase 5：交付实际结果

按三层说明实际处理（多章逐章列），有未授权设计缺口时不得称问题已清；只报实核字数与改动，用户要求才另存报告文件。

<!-- author-report -->
```md
## 改稿结果
- 表达：{改了什么；保留了哪些有效写法；未查则写本次未检查}
- 用笔：{压缩/展开处及原因；未查则写本次未检查}
- 故事：{已修承接/已授权改动；待设计或无法核实项；未查则写本次未检查}

### 代表性改动
{少量改前/改后对照与读感变化；无修改不列。}

### 尚需处理
{原文位置、缺口、最小选项及后文影响；无则省略。}

{文件模式：给修改路径与 ≤200 字片段，不回全文；零散贴入片段：给改后全文。}
{有备份时：改前原文留在 {备份路径}，想撤回告诉我。}
```

## 流程衔接

长篇剧情级改动转 `/story-long-write`；需继续设计剧情带缺口进 `/story-long-write` 或 `/story-short-write`；完整多视角审稿转 `/story-review`。
