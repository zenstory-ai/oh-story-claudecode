# 去味检查范围与执行接口

本文件承接调用方的范围和分工，不另存一套修法。表达按 [style-resolution.md](style-resolution.md) 裁决，详细判断只在下面三份方法中维护。

## 三层入口

| 层 | 读取 | 检查对象 |
|---|---|---|
| 表达 | [expression.md](expression.md) | 用词、句式、声口、句段组织与模板复现 |
| 用笔 | [narrative-focus.md](narrative-focus.md) | 详略、关键过程、细节功能、情绪承接和收尾 |
| 故事 | [story-logic.md](story-logic.md) | 行为依据、因果、人物立场、结果与知情顺序 |

独立去味或完整去味审查未限定范围时，三层都诊断；每层可以没有问题。调用方已指定问题、段落或检测类别时，只检查该范围所需方法，不借此另起一次全篇重写。章末脚本只负责提示可检测的表达问题，不能凭零命中推断后两层正常。

## 按检测类别或问题限定范围

调用方传来检测类别时，按 expression.md 末节「脚本提示怎样进入语义判断」的索引找判断对象和转交层；传来问题名时按下表检查（发现范围外的明显设计缺口可单列提示，不擅自扩大改稿）：

| 问题 | 对应方法 |
|---|---|
| 套词、句式 | 表达层的词句与模板判断 |
| 情绪 | 用笔层的心理过程与删除测试；表达层的直写与套式反应 |
| 节奏 | 用笔层的详略、重复与关键过程；表达层的句段组织 |
| 对话 | 用笔层的交锋与人物诉求；表达层的声口 |
| 收尾 | 用笔层的信息、兑现与余韵；表达层的空泛总结 |
| 解释与安排感 | 表达层的解释与叙述者；用笔层的信息交付；故事层的因果与知识边界 |

类别不明时检查上表全部表达与用笔项；调用方要求完整三层诊断时再按故事层完整检查。

## 执行与复核

写法抽查按用笔层的场景重心、删除/压缩/展开测试执行；普通去味与剧情重写的权限边界按故事层「诊断深度与执行权限分别确定」判断。审稿调用只报告不改文件；改稿调用把授权修改落盘，未获授权的设计方案写进报告。父流程负责最终脚本扫描时，执行者只做语义改稿并返回实际修改、保留与未解决项。
