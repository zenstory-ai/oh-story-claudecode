# story-long-scan：长篇网文扫榜

你负责从长篇榜单的重复样本中识别题材候选，结合作者条件给出可行性、失败风险与验证动作。单本排名只提供线索，近期多榜单、多作品的重复模式才支持趋势判断；各平台热度只按自身公开口径比（番茄看在读，起点看付费榜与总推荐，晋江看收藏、营养液与积分，七猫看热度），完读率、追读、订阅转化等作者后台数据未提供时不下结论。

---

## 扫榜流程

### Phase 1：确认平台和方向

沿用作者已给的条件；缺的一次问齐，给选项：

- 平台：起点 / 番茄 / 晋江 / 七猫 / 刺猬猫 / 多个平台对比
- 频道（番茄、七猫才分）：男频 / 女频 / 都看
- 看什么：新书里在冒头的（多采新书样本） / 成熟大盘（只采默认榜单）
- 有没有关注的题材方向（没有就做全榜概览）

---

### Phase 2：确定数据来源

| 优先级 | 模式 | 说明 | 何时用 |
|--------|------|------|--------|
| 1 | **脚本采集** | 直接抓取平台页面数据，产出结构化榜单文件 | 优先；起点排行榜不需要 Chrome |
| 2 | **作者提供** | 作者粘贴榜单文字、截图，或给已有的榜单文件 | 作者已有数据，或脚本采不到时 |
| 3 | **内置知识** | 只用历史题材候选做分析 | 无法联网、作者也没有数据时 |

#### 脚本采集模式

命令里的 `scripts/` 相对本 skill 根目录。

1. 每次扫榜在工作目录新建 `扫榜/{YYYYMMDD}/`（同日再扫加 `-2`），下文 `{outdir}` 指它。不往旧目录追加，聚合会混进旧榜。
2. 只读所选平台参考：[起点](references/platform-qidian.md) / [番茄](references/platform-fanqie.md) / [七猫](references/platform-qimao.md) / [晋江](references/platform-jjwxc.md) / [刺猬猫](references/platform-ciweimao.md)。按 Phase 1 的频道和「看什么」运行默认命令；需要 Chrome 的平台先 `/browser-cdp` 启动。
3. 聚合：`node scripts/aggregate-rank.js {outdir} --out {outdir}/扫榜聚合.md`。**主会话先只读聚合**：题材分布、去重本数、热度与字数中位、标签、书名词、多榜重合和代表作。
4. 看聚合的「采集情况」：标了问题（书名没解出来、没采到、只有书单、详情没取到）的榜单，按平台参考的「采不到时」排查后重采；重采不了，报告里说明结论不含它。只缺热度数字的榜不算采不到：题材、字数照用，只是不进热度结论。
5. 分析新人物设定、新切入设定和新桥段时按需抽样：`node scripts/aggregate-rank.js {outdir} --sample {题材/标签/书名词} --n 5`，一次一个方向。命中条数含多榜重复，样本本数按同平台书名+作者去重。

#### 作者提供

已有榜单文件就放进 `{outdir}` 聚合。作者给链接时，请他把页面内容复制过来或截图（番茄、起点有反爬，直接抓页面常拿不到）。把文字或截图整理成：首行 `# {平台} · {榜单名}`，平台名只用 起点 / 番茄 / 晋江 / 七猫 / 刺猬猫，才能和脚本数据合并；每本一段 `### #{排名} {书名}`，下一行 `*作者 · 题材 · 连载中 · 120万字 · 3.5万收藏*`（热度写「数字+口径」，有标签再加 `**标签：** a、b`）。存进 `{outdir}` 后同样聚合。

#### 内置知识

读 [references/genre-trends.md](references/genre-trends.md)，报告开头写明「以下分析基于历史题材候选，没有实时榜单校验，只能作为待验证的假设」，并列出需要复扫的榜单。

---

### Phase 3：数据分析

以聚合结果为主，先按所选平台参考的「分析维度」看，再看通用维度：

1. **题材分布**：本数、占比与热度中位。番茄按题材等额采样（聚合会注明），本数是采样上限，题材冷热看热度中位和平台 P75。
2. **新题材信号**：新书榜、书库新书样本与多榜重合；同时采到新书榜和其他榜时，聚合才显示「新书榜」列。上次日期目录有 `扫榜聚合.md` 时，按相同平台、榜单与筛选范围对比。
3. **头部老书**：月票、畅销、阅读榜上字数几百万、连载多年的书，代表这个题材的存量读者，不代表现在开新书能起来；判断新方向以新书榜、书库新书为主。
4. **经典题材变化**：老牌题材上升、稳定还是下降；没有上期数据就只写现状。
5. **字数**：字数分布与各题材字数中位。
6. **书名模式**：书名常见词 + 代表作书名。
7. **简介卖点**：标签热词 + 代表作简介。数据只有简介（聚合截到 30 字，采集截到 100 字），开篇怎么写留给拆文验证。
8. **新元素**：对候选方向抽样原始条目，标出新的人物设定、切入设定、桥段套路。

---

### Phase 4：输出扫榜报告

报告讲本次样本支持的结论和作者能写的方向；无可比上期时，趋势栏写「未比较」，不填涨跌。脚本名、命令和采集状态不进报告；缺榜时说「XX 榜这次没拿到（原因），结论不含它」。题材热度排行按热度中位从高到低排，没有热度数字的平台按本数排；与全平台比较用白话，如「比全平台四分之三的书都热」，不写 P75。

报告展示给作者，同时写进 `{outdir}/选题决策.md`：文件不存在就先按 [references/topic-decision.md](references/topic-decision.md) 的模板写文件头，再把报告作为「扫榜结论」一节写入（已有同名一节就整节替换）。作者只扫榜不选题，结论也已落盘。

### Phase 5：选题决策

按 [references/topic-decision.md](references/topic-decision.md) 的选题四步、可行性规则与模板，在 `{outdir}/选题决策.md` 写 2-3 个推荐选题。

**从文件接上：** 先读 `{outdir}/选题决策.md` 的「扫榜结论」和 `扫榜聚合.md`，不靠对话记忆；两者都没有就回 Phase 2。

**信息不足时，向作者补齐项目条件：**「目标平台、已有素材、擅长题材或写作限制、计划篇幅是什么？」
