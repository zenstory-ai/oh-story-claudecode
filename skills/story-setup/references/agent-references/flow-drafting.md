# 正文写作、日更调度与竖屏网感（flow-drafting）

> 谁读：主会话写一章、日更时整份读；`narrative-writer` 写正文时读「正文笔法与竖屏网感」一节；同时读本书 `genre-styles/{流派}.md`。

---

## 主会话调度与日更

### 缺文件先修（修好再写，本轮不硬写）

- `tracking_commit.js check` 报错（exit 2）：按提示修；仅返 `drift_warnings`（视图被手改）先问作者吸回改动还是按 JSON 重建。
- 已有正文却缺 `_tracking-state.json`：请作者走 `/story-import` 迁移；新书第 1 章前先读主会话追踪协议初始化第 0 章。
- 缺细纲：写指定章时按 `flow-outline.md` 补建点名章细纲并跑 `check-outline-contract.js`；日更批内停在该章前问作者。细纲缺「目标情绪」「主角目标/关键选择」两行时按卷纲补齐写回再写。
- 临时文件只放 `{书目录}/.story/work/第NNN章/`，不写 `/tmp` 或书根。

### 日更批次控制（串行逐章，单轮最多 3 章）

- 必须主会话内**串行逐章**完成（不并发派多章写手，防止追踪覆盖）。先跑 `tracking_commit.js check` 取 `last_committed_chapter + 1` 作首章；每批默认 2–3 章，写满即停并做跨章核对（标题去重、主角高光/期待兑现、增量伏笔盘点、批末一致性检查，收拢各章「本章没写成的」待补项与待拍板项），不因还有细纲继续跑下一批。
- 缺旧信息由近到远定点查：`grep` `追踪/伏笔.md` 或读 `追踪/角色状态/{名}.md` → 查 `追踪/逐章记录/` 近 5 条 → 最多回读 1 章原正文，不整读全库。

### 单章执行流程

1. **取纲与上下文**：读 `大纲/细纲_第{N}章.md` + 跑 `outline_view.js --chapter {N} {卷纲路径}`（同段复用，不整读卷纲）+ `tracking_commit.js check` + 读 `追踪/上下文.md` 全 7 栏与细纲点名设定。
2. **组装与切片锚定**：在 `{skill 根}` 的脚本目录跑 `build_writer_prompt.js --project {书目录} --chapter {N} --out`（`====` 上为 prompt、下为核对报告；exit 2 修完重跑）。核对报告报「召回降档不成立」时读 `benchmark-recall.md`；**无论是否降档，动笔前必须读入 1–2 段 150–250 字真网感原文切片**（有主对标优先取对标 `文风.md` 原文锚点，无对标取本书流派包内置切片）校准语感。
3. **写正文**：整章一次写完，批准内容写完即停。已部署 `narrative-writer` 时按子代理派发手册派发；主会话自写时同步列新增物申报表（无写 `0`）。
4. **检测收口**：跑 `storyctl.js chapter check --project {书目录} --chapter {N} --fix-punctuation --plain`（内置 `check-ai-patterns.js` 与 `check-degeneration.js`）。
   - 硬阻断项（退化/复读/截断/工程词）与 S1/S2 冲突必须清零；`review_required` 逐条看原文，真属 AI 腔则改，确属网文卖点/剧情需要保留则提交时附 `--ack <rule-id>:<理由>`。作者明确要求本章跳过检查时，可在标题行下加 `<!-- 去味:跳过 -->`。
   - **字数带外**：欠字不硬凑，按下方字数选项请作者定；超字净删一次（只删废话不加剧情），仍超请作者选（不到目标一半需作者坚持才加 `--force`）。
5. **一致性与提交**：申报表非 `0` 时按子代理派发手册调 `consistency-checker`（或主会话自核），按 SKILL.md「新增物三级」分流登记/修复/先问作者（「本章没写成的」中细纲没给的追加进 `.story/排纲笔记/`「写纲时补的」，先问作者的暂停提交问作者）。确认无阻塞后跑 `tracking_commit.js draft --project {书目录} --chapter {N}` 填 `delta` 与变化角色快照，再跑 `storyctl.js chapter commit --project {书目录} --chapter {N} --input {工作目录}/tracking.json`（报错读主会话追踪协议），返回 `tracking_committed: true` 即完成。

### 向作者汇报（白话，不带代码块围栏）

<!-- author-report -->
```md
第{N}章《{章名}》写好了，约 {字数} 字。
这章：{两三句讲清发生了什么、爽点在哪、停在什么钩子上}。
{有需留意的新人物/设定或作者习惯没带上时各一句原话说明；没有就删}
自查过设定和前文，{没发现冲突 / 已修正一处前后不一}。
下一章：第{N+1}章《{章名}》，要接着写吗？
```

- **日更批末**：合并汇报每章一句话 + 偏离/待拍板项 + 下一批进度。
- **字数带外**（一次净删后仍超或欠字）：报目标与实际字数差额和原因，给 3 选 `1. 按现在长度收下（推荐；不到目标一半不标推荐） / 2. 改细纲或目标再重写 / 3. 这章不要了`。
- **遇到「先问作者」项**：用故事话说清会牵动什么，给 `1. 留下/加上并同步改纲 / 2. 删掉/不加按原细纲写` + 推荐，本章暂停提交。

## 正文笔法与竖屏网感

写法冲突优先级：**作者本轮要求 ＞ 本书 `设定/文风.md` ＞ 主对标原文切片 ＞ 本书流派包 ＞ 本节默认**。文风不改细纲事实与字数范围。

### 1. 视角与开篇速度（对齐连载长篇节奏）

- **默认第三人称贴身限知**（仅当用户或流派明确指定才用第一人称）：镜头贴着主角走，心里盘算、吐槽、利害算账直接用角色口吻写出，不跳出来当说教旁白；同场可见反应（变脸、失态、私语）可拍，章尾允许切一短镜展示对手/幕后动向制造信息差（严苛悬疑与第一人称除外）。
- **黄金三章落笔铁律**（仅起点/晋江明确慢热向可放宽）：
  - 第 1 章**首段 ≤45 字**（常见 15–30 字）直抛困局、羞辱、反常或金手指异动；**前 100 字禁纯景物、天气、世界观说明书或身世简历**；
  - **≤300 字见首句对话，≤400 字进入核心冲突**；背景规则一次只放当前这场戏用得上的 1–2 条，随冲突带出；
  - 跑龙套路人不起全名（用职称/称呼指代），避免开篇人名扎堆；
  - 金手指/底牌首次生效必须立刻落到看得见的现实收益或他人态度变化上；
  - 第 1–3 章**章末 100% 留强卡点**（新危机/动作打断/奖励超预期/强敌逼近），第 1 章读完必须让读者知道主角眼下要干什么。

### 2. 手机竖屏排版与节奏（核心网感底座）

竖屏阅读基准（段长中位约 20–30 字、≤50 字短段与单句成段为主、>80 字长段尽量归零）：

- **短段为常态，一句一段为主**：一个动作拍、一个判断、一句对话或一拍反应自然独立成段；多数段落控制在 **15–40 字**，**超过 80 字的厚重叙述墙全章趋近于零**（仅复杂推理或关键环境压迫偶发允许）。
- **对话独立成行**：每句台词单独成段，不把多轮对话焊进大段叙述里；连续两人对顶省略「他说/她道」，靠语气词（吧/呢/啊/嘛/呵）和立场分清谁在说话。
- **把细纲演成戏，不抄提纲腔**：不把「起因/发展/转折/高潮/结尾」写成概括总结；重要转折写出中间台阶，过场赶路 1–2 句带过，爽点/打脸/对决放慢镜头逐拍写实（禁「斗了半晌」「众人纷纷点头」式量词折叠）。
- **具体数字折算切身利益**：用精确金额、年限、品级、倒计时替代「很久/很多」，顺手折算成主角急用的现实开销（如「一万二，够妹妹一学期学费」）。

### 3. 情绪直写与标点能量（解除过度文学束缚）

- **四条通道平级直写**：① 直接点明情绪（「他气笑了」「心里发沉」「彻底慌了」）；② 当下利害算账与内心吐槽；③ 台词反击与行动选择；④ 改变局面的真实动作/物件后果。
- **保留网文高频短效反应**：像「瞳孔一缩」「脸色一变」「呼吸一滞」「心头一震」这类读者秒懂的高速情绪缩写**允许自然使用**，不设禁令；只删**同一页里连续机械刷屏**或脱离上下文硬贴的空转小动作（如无意义的反复摸杯沿、理袖口）。
- **自然情绪标点**：冲突、震惊、打脸、反问和内心吐槽大胆用 `！` 与 `？`（常态约 **7–15 处/千字**，别通篇句号压死张力，也禁 `!!!` 刷屏）；叙述中**允许用标准破折号 `——` 做关键转折、身份反转或吐槽落拍**（避免刷屏）；`……` 用于对话吞吐、系统面板和适度停顿。

### 4. 对话驱动与爽点围观分层

- **对话占比参考 18%–38%**（冲突/打脸章可更高），靠直球交锋、筹码施压和话语权反转推进（前期对手长篇嚣张/轻视 → 主角用事实或底牌一句封死）；**不强求每句对话藏潜台词**，该翻脸就直给，该贴标签就让反派嚣张得让人想抽他。
- **装逼打脸四步**：① 读者先知底牌或筹码（防虐主）→ ② 旁人看低、对手把难度拔高 → ③ 主角干脆出手一击碾压（大高潮干净利落，不写险胜憋屈）→ ④ **围观反应分层写足**：普通人惊呼/倒吸凉气（可用，不单调堆砌）→ 懂行内行拆解分量（估价/打破常例）→ 有利害关系的大人物失态改口或重排算盘，最后落到主角实利到手（资产/地位/声望）。

### 5. 锚定切片与长篇真 AI 味自查

- **动笔前必看语感锚点**：开写前扫一眼对标 `文风.md` 或本书流派包的 150–250 字原文切片，对齐其断行密度、口语感、节奏快慢与标点力度（只学语感，严禁照抄人名、物件、台词或桥段）。
- **硬格式底线**：相邻段落单 `\n` 不空行、无段首缩进、正文无 Markdown 装饰符（合法章标题除外）、引号全书统一（默认 `“…”` 内嵌 `‘…’`）、标题行外零工程词（本章/上一章/前文/伏笔/细纲/读者）。
- **长篇真 AI 味六条黑名单（只砍这六类，不误伤网文套路）**：
  1. **论文/公文腔**：综上所述、不难看出、进一步落实、由此可见、请提供书面材料；
  2. **空洞哲理与翻页收尾**：他终于明白了生活的真谛、人生就是这样、属于他的传奇才刚刚开始；
  3. **无冲突纯景物注水**：开章或打脸前硬插无关的斑驳光影、微风拂面、天空阴沉；
  4. **机械微动作刷屏**：连续多段都靠垂眸、抿唇、指节泛白、端茶杯来翻译情绪；
  5. **细纲概括照搬**：把提纲里的「完成铺垫」「态度转变」原样抄成叙述总结；
  6. **工程元信息词**：正文混入第 X 章、上章、伏笔、细纲、读者。
- 需保留的特殊写法（如本书允许的特定复沓原句）登记到书目录 `.deslop-whitelist`（UTF-8 一行一条字面原句，上行 `# 来源：…`）。
