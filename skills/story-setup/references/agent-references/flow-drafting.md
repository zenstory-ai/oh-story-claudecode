# 正文写作、日更调度与竖屏网感（flow-drafting）

> 谁读：主会话写章/日更整份读；`narrative-writer` 读「正文笔法与竖屏网感」与题材包 **4–5 节（正文技巧/案例片段）**。

---

## 主会话调度与日更

### 缺文件先修（修好再写，本轮不硬写）

- `tracking_commit.js check` 报错（exit 2）先修；仅 `drift_warnings` 先问作者吸回手改还是按 JSON 重建。
- 已有正文缺 `_tracking-state.json`：先走 `/story-import`；新书第 1 章前读主会话追踪协议初始化第 0 章。
- 缺细纲：写指定章按 `flow-outline.md` 补建并跑 `check-outline-contract.js`；日更批内停在该章前问作者。缺「目标情绪」「主角目标/关键选择」按卷纲补齐再写；半成品导入后续写第 N+1 章前，先在卷纲卷尾补一段覆盖该章的剧情段。
- 临时文件只放 `{书目录}/.story/work/第NNN章/`，不写 `/tmp` 或书根。

### 日更批次控制（串行逐章，单轮最多 3 章）

- 主会话**串行逐章**写（禁并发多章）。先跑 `tracking_commit.js check` 取下章号；每批 2–3 章，写满即停并做跨章核对（去重、高光期待、伏笔一致与待定项），不自动续批。
- 缺旧信息由近到远定点查：`grep` `追踪/伏笔.md` 或 `追踪/角色状态/{名}.md` → 近 5 条 `追踪/逐章记录/` → 最多回读 1 章正文。

### 单章执行流程

1. **取纲与上下文**：读 `大纲/细纲_第{N}章.md` + 跑 `outline_view.js --chapter {N} {卷纲路径}`（同段复用，不整读卷纲）+ `tracking_commit.js check` + 读 `追踪/上下文.md` 全 7 栏与细纲点名设定。
2. **组装与切片锚定**：跑 `{skill 根}` 脚本 `build_writer_prompt.js --project {书目录} --chapter {N} --out`（`--out` 存纯 prompt，核对报告走 stdout；exit 2 修完重跑）。降档不成立读 `benchmark-recall.md`；**动笔前必读 1–2 段对标或流派包原文切片**校准语感。
3. **写正文**：整章一次写完，批准内容写完即停。已部署 `narrative-writer` 时按子代理派发手册派发；主会话自写时同步列新增物申报表（无写 `0`）。
4. **写后检测**：跑 `storyctl.js chapter check --project {书目录} --chapter {N} --fix-punctuation --plain`（内置 `check-ai-patterns.js` 与 `check-degeneration.js`）。
   - 硬阻断项（退化/复读/截断/工程词）与 S1/S2 冲突必须清零；`review_required` 逐条看原文，真属 AI 腔则改，确属网文卖点/剧情需要保留则提交时附 `--ack <rule-id>:<理由>`。作者明确要求本章跳过检查时，可在标题行下加 `<!-- 去味:跳过 -->`。
   - **字数带外**：欠字不硬凑，按下方字数选项请作者定；超字净删一次（只删废话不加剧情），仍超请作者选（不到目标一半需作者坚持才加 `--force`）。
5. **一致性与提交**：申报表非 `0` 时按子代理派发手册调 `consistency-checker`（或主会话自核），按 SKILL.md「新增物三级」分流登记/修复/先问作者（「本章没写成的」中细纲没给的追加进 `.story/排纲笔记/`「写纲时补的」，先问作者的暂停提交问作者）。确认无阻塞后跑 `tracking_commit.js draft --project {书目录} --chapter {N}` 填 `delta` 与变化角色快照，再跑 `storyctl.js chapter commit --project {书目录} --chapter {N} --input {工作目录}/tracking.json`（报错读主会话追踪协议），返回 `tracking_committed: true` 即完成。

### 向作者汇报（白话，不带代码块围栏）

<!-- author-report -->
```md
第{N}章《{章名}》写好了，约 {字数} 字。
这章：{两三句讲清发生了什么、爽点在哪、停在什么钩子上}。
{有需留意的新人物/设定或作者习惯没带上时各一句原话说明；没有就删}
自查过设定和前文，{没发现冲突 / 已修正一处前后不一}。
下一章：第{N+1}章《{章名}》，要接着写吗？
```

- **日更批末**：合并汇报每章一句话 + 偏离/待拍板项 + 下一批进度。
- **字数带外**（一次净删后仍超或欠字）：报目标与实际字数差额和原因，给 3 选 `1. 按现在长度收下（推荐；不到目标一半不标推荐） / 2. 改细纲或目标再重写 / 3. 这章不要了`。
- **遇到「先问作者」项**：用故事话说清会牵动什么，给 `1. 留下/加上并同步改纲 / 2. 删掉/不加按原细纲写` + 推荐，本章暂停提交。

## 正文笔法与竖屏网感

写法冲突优先级：**作者本轮要求 ＞ 本书 `设定/文风.md` ＞ 主对标原文切片 ＞ 本书流派包 ＞ 本节默认**。文风不改细纲事实与字数范围。

### 1. 视角与开篇速度（对齐连载长篇节奏）

- **第三人称主角视角**（指定或民俗灵异可用第一人称）：**同场内不乱跳多人内心**，盘算、吐槽、利害算账用角色口吻直出，不跳出来说教；同场可见反应可拍；**允许经独立场景切视角（独立行 `……` 或时空转场）切至对手/大人物/恋人视角**，展敌方设局（陷阱先知）或权威/恋人脑补震撼（严苛单视角与第一人称除外；女频/脑洞悬疑可切旁观）。
- **黄金三章铁律**（仅起点/晋江慢热向放宽）：
  - 首段一两句短脆直抛困局、羞辱、奇观/播报或金手指异动；**前 100 字禁纯景物、身世简历及「大脑寄存处/求好评/境界表」注水**；
  - 开头两三百字内见首句对话并落进简介核心场景（不照抄简介）、三四百字内入核心冲突（广播/奇观独白开场首对话可稍晚）；背景随冲突带 1–2 条；路人用职称指代不起全名；
  - 按 `flow-outline.md` 选一种开篇套路跑透（打脸翻盘 / 三章蓄力压抑+逐级垫脚石 / 真实痛点+小步数值养成+死党对照 / 强概念+双视角脑补或弹幕），卖点/底牌早亮牌并给可见反馈；
  - 前 3 章每章结尾都必须留强卡点，第 1 章读完须知主角眼下要干什么。

### 2. 手机竖屏排版与节奏

- **长篇自然呼吸＋活人讲述感**：**动作提示与台词分行、短对话干脆对顶；长篇叙述 1–3 句自然成段与极短孤句错落呼吸，严禁逐句一刀切敲成均匀短行节拍器，也不堆 >100 字文字墙**；盘算用角色心里活话（`谁不知道/可眼下/倒也没/哪想到`），**禁连刷「因为…/毕竟…/所以…」说明文解释句**，口语接词（`好家伙/瞬间/偏偏`）别连刷；净删压字留口语转折与「的」，**压完重跑 `check-ai-patterns` 并回核加减守恒、干湿/工时/伤势与金融司法常理**。
- **第 4 章起稳节奏**：换图或转权谋保住顺口大白话与人情算计，独立行 `……` 省过场，不膨胀成说明砖块。
- **短对话快推**：台词独立成行，连续对顶直接裸对白，**禁每句捆绑材质道具与微动作**；说话贴合时代（古风/正剧禁出戏热梗）。
- **砍空景摆设，保活人烟火与痛感钉子**：每章只细写 1–2 个改局物件与账目，**核心器物真名统一（同章角色口中自然简称代称，禁五字全称当 ID 连刷）、经手链与跨夜日期零穿帮，账目后台守恒禁章章播报「眼下实打实还剩…」盘点；标志物/口癖 3 章 ≤2 次，禁刷局部词（半寸/绷紧/立时/硬生生/恰在这时/分毫不差/不紧不慢/顿时一静）及同套「硬A不如B」句模**；禁材质空镜，留烟火细节。
- **演透主重戏，控住字数不爆**：2,200 字单章聚焦 **1 场主重戏（≤3 个推进步）+ 最多 1 场短过场/收尾钩子**（初稿自然落在 2,100–2,500 字），写透来回台阶、情绪钝痛与对话拉扯，禁折叠或硬塞双大场超字后压成碎句；换气章放开写松弛嘴贫。

### 3. 情绪直写、女频苏感与标点节奏

- **四条通道直写**：① 直接点情绪（「他气笑了」「心里发沉」）；② 当下利害算账与吐槽；③ 台词反击与行动选择；④ 改局动作/物件后果。
- **网文反应与女频去油**：**禁刷「背脊一凉/倒吸冷气/心里咯噔」与「胸口像被钝物撞/喉咙像被铁箍卡」躯体模板、把守则写进正文自夸（用条款动作演）及裁判/破折号解释补白句**（留白给停顿行动演），砍油腻词（`指节泛白/宠溺/喉结轻滚/声音低哑/耳尖泛红/骨节分明/小女人`，**`轻笑/低笑`不误杀**）。**女频去油≠阉割锋芒与失控心动**——守边界与托底，同时留危险压迫、棱角偏执与微吃醋失态（禁初识突兀报备或礼貌 HR）：
  - ❌（油腻 AI）：「祝衡眸色一暗、喉结轻滚，攥腕壁咚低哑道：『小女人，今晚哪儿也别想去。』舒禾耳尖发烫指节泛白。」
  - ✅（克制张力）：「大雨堵车，祝衡推开副驾门，下颌线绷得发紧：『上车。』被戳穿顺路撒谎，他移开视线哑声退半步：『上周那句不算——不愿坐我叫司机送。』」
- **按流派控标点**：**叙述默认 `。`**，`！` 只留给真正爆点（甜宠、双男主等克制流派更少用，高武、搞笑、老六文可略放开，禁旁白咆哮与 `!!!`）；旁白 `——` 尽量少用；`……` 用于吞吐、面板或独立行硬切。

### 4. 对话驱动与爽点反应层

- **对话交锋**：短对话快推为主，禁整段揭底宣讲式长台词；**推理拆账与审讯盘问每轮只抛一条硬细节一句点清，拆成「追问 → 抛硬细节 → 反驳/停顿 → 补第二条死证」短问答**；单人独角戏对话可偏少，辩经、群像与换气日常章可放开用对白推场。
- **博弈爽点与反应层**：靠**真实阻滞、对手按私心反咬、主角反预期实招破局**出爽，禁套「看低→碾压→三连呼」、**虚掩门缝偷听反派念全套大纲及主角心里对已知物装糊涂**；胜后用内行拆解、利害者改口或权威脑补显分量，实利落袋且留后手压力。

### 5. 锚定切片与长篇真 AI 味自查

- **写前看范文切片**：动笔前扫对标 `文风.md` 或流派包切片校准断行与口语（禁抄人名桥段）；**50/100+ 章回看前 5 章稳住前期语气**，守百章四件套（回扣旧敌、配角扛高光、松章末尾也留悬念钩子、大局加弹幕减压）；每 3–5 紧章配 1 松章。
  - ❌：「这不是恶战。是算力碾压。他瞳孔缩至临界点，系统日志刷屏。」→ ✅：「青砖渗黑血，老道把桃木剑往地上一插：『行，撞上硬茬了。』」
- **硬格式底线**：段间单 `\n` 不空行、无缩进、正文无 `**`、引号统一（默认 `“…”` 内 `‘…’`）、标题外零工程词（本章/上章/前文/伏笔/细纲/读者）。
- **真 AI 味六类黑名单（不误伤网文套路）**：① 公文腔（综上所述/进一步落实）；② 空洞哲理尾（传奇才刚开始）；③ 动作清单碎句（抽干内心的动作孤行/报时转场）；④ 没用的环境穿搭摆设与油腻标签（非功能材质穿搭/光影音效空镜、垂眸/指节泛白）；⑤ 细纲照搬或零阻力走过场；⑥ 工程元信息词。
- 书内需保留的特殊写法登记到 `.deslop-whitelist`（UTF-8 一行一句字面原句，上行 `# 来源：…`）。
