# 正文格式与小节结构

> 本文件规定默认正文交付格式；用户或目标平台的明确要求优先。
>
> **适用范围**：短篇默认竖屏一句一段（中位约 20 字）与单文件小节结构；长篇按戏剧单元/镜头断段，字数以细纲「字数目标」（或作者指定的「字数范围」）为准，按非空白可见字符数验收。

---

## 章节标记

按目标平台选择，未指定时用短篇默认格式：

| 格式 | 平台适用 | 示例 |
|------|----------|------|
| `###1.` | 短篇默认 | `###1.` `###2.` `###3.` |
| `###第一章` | 部分平台 | `###第一章` `###第二章` |
| `1.`（纯数字） | 知乎 | `1.` `2.` `3.`（无 ### 前缀） |

**规则**：全文统一一种格式，不要混用。短篇推荐 `###1.` 或纯数字，简洁高效。

---

## 段落格式

- **短篇竖屏短段（默认一句一段）**：短篇面向手机竖屏快读，默认一句一段或极短段（中位约 20 字、超七成 ≤30 字、极少超 80 字），对话独立成行，动作—对白—第一人称吐槽快切；**不把短篇单句段硬合并成长段**。相邻段落间**默认只用单个换行符 `\n`**（段间空行 `\n\n` 在交付检查中属软提醒 `advisory`），无缩进（禁 `　　` 或空格）。
- **长篇戏剧单元优先**：长篇按戏剧单元/镜头断段，高潮打脸可单句成段，完整推理、环境压迫、情绪链可保留稍长段，不按固定字数机械切段。
- **主语与角色名节奏**：段首、转场、多人同场或易混淆时点名建立视角；同一动作链内混用代词、动作承接和省略，关键转折或情绪爆点再点名（仅连续句/段无主语重置却反复点名才算主语过密）。

## 对话格式

| 优先级 | 格式 | 适用平台 |
|--------|------|----------|
| 首选 | `“说话内容”` | 短篇默认、番茄、七猫、黑岩 |
| 平台/项目指定 | `「说话内容」` | 知乎盐言短篇、部分古言、日式或用户指定 |

- 对话**独立成行**，不嵌在叙述段中；默认用中文弯引号 `“…”`（内嵌 `‘…’`），盐言风格或项目指定时用 `「」`（`quote-mode keep` 时不得改掉）。
- 高频公式化标签（「他说」「她道」「他笑了笑说」）用上下文或有后果动作替代，不为省标签硬配端茶杯、挑眉等微动作；普通「说」低频可留，两人连续对话且说话人清楚时可省标签。

```
✅ 正确（独立成行，普通「说」低频可留）：
她把杯子放下。
“你走吧。”她说。
他没有动。
“我说，你走吧。”

❌ 错误（对话嵌在叙述段中）：
她把杯子放下，说道：“你走吧。”他没有动，她又说：“我说，你走吧。”
```

## 语气标点谱系

标点服务语气、人物声线和情绪节奏：

| 语气 / 功能 | 标点策略 | 防线 |
|---|---|---|
| 压迫 / 冷静 / 克制 | 句号、逗号、冒号；动作和判断用逗号接成一句，冒号落判断 | 不人工加感叹号；克制不是每句都平铺句号 |
| 质问 / 试探 / 反问 | 问号 + 短促追问片段，配合动作停顿 | 避免每句话都以 `？` 结尾 |
| 惊讶 / 爆发 / 打脸 | 真正爆点可用 1 个感叹号，连续爆发最多 1-2 处 | 禁止 `!!!`、整段喊叫式感叹 |
| 犹豫 / 留白 / 面板 | 对话吞吐、面板提示及偶发留白用 `……`；普通停手改口用逗号 | 旁白禁连刷省略号 |
| 被打断 / 拖长音 / 转折拍 | 对话引号内收在 `——` 或 `……`；旁白仅在关键转折、揭底或系统提示处克制使用 `——` | 旁白 `——` 避免刷屏，畸形破折号须修正 |
| 信息揭示 / 判断落点 | 冒号、分号或单句成段制造落点 | 保持手机阅读友好，不写论文式分号串 |

- 强势角色常短句收束，试探角色多问号和半句，崩溃角色才用少量感叹/省略；长短篇均保留标准破折号 `——` 用于对话打断及旁白关键转折/系统提示（控制密度禁刷屏），短篇允许自然高频 `！`/`？` 情绪节拍；省略号（……）不在旁白连刷。精修重点排查**通篇句号化**与**随机标点堆砌**。

## 小节结构（短篇）

- 用统一小节标记（`###1.` / `1.` / `###第一章`）分割小节；150–300 字导语放首节前，不写「导语」二字，首百字入冲突或对话。
- **体量与卡点**：首节可略拉长（约 1300–1500 字）立住仇恨或核心钩子；全文约 30%–40% 节末落付费强卡点；约 40% 起持续推进连环反击/反转，终局明账清算。小节长度服从节拍，不设统一最低字数。
- **跨节衔接**：非末节节尾停在未完成动作、底牌将亮、狠话条件或突发异常上；下一节首句直接接住上一节结果，不写风景垫场。

### 小节内部结构

1. **2–3 个具体微节拍**：每节包含明确的冲突动作、对白刺点或局势翻转（改变风险、信息、关系或筹码），不把单一平淡事件注水成千字。
2. **对话驱动与情绪直给**：强冲突场对话占主要篇幅（参考 30%–40%），夹带第一人称口语吐槽或利害算账；过场一句带过。
3. **竖屏短段呈现**：一句一段为常态，叙述段尽量 ≤30 字、避免 >80 字大段。

## 8 条格式规则

以下规则按文件开头的优先级执行；其中标点默认可由本书明确的文风约定覆盖：

1. **分篇幅控段长**：短篇默认竖屏一句一段（中位约 20 字），不合并成大段；长篇按戏剧单元/镜头断段，不机械按字数强拆
2. **默认不留段间空行**：正文相邻段落之间默认只用一个换行符 `\n`，避免多余空行 `\n\n`（交付检查中属软提醒 `advisory`，仅平台规范或刻意转场留白时保留）
3. **避免对话标签机械化**：高频或公式化的「他说」「她道」「他笑了笑说」用上下文或有后果动作替代，不硬配端杯、挑眉等微动作；普通“说”可保留
4. **禁止缩进**：不使用 `　　`（全角空格）或半角空格缩进
5. **禁止正文段落 Markdown 渲染**：除统一的小节/章节标记（如 `###1.`）外，正文段落中不使用加粗 `**`、斜体 `*`、标题 `#`、分隔线 `---` 等 Markdown 语法
6. **默认停顿写法**：长短篇均保留标准 `——`（对话引号内打断/拖音，及旁白关键转折/揭底/系统提示处克制使用、避免刷屏）、系统面板及有节制留白 `……`；短篇允许自然高频 `！`/`？`。标点偏好不属于不可覆盖的文件结构协议。
7. **禁止通篇句号化或随机标点堆砌**：标点匹配语气、声线与情绪功能；不在旁白连刷 `……`，不得无功能乱撒 `？`/`！`
8. **禁止正文混入章节元信息**：章节号只允许出现在标题/小节标记/文件名/追踪记录中。正文叙述、对话、心理描写里不得出现 `第[一二三四五六七八九十百千万两0-9]+章|上一章|上章|前一章|本章|这一章|前文|后文|伏笔|细纲|读者` 这类写作工程词；要改成角色能感知的事件锚点或相对时间，例如把“比第一章那三秒开火更疼”改成“比那三秒开火更疼”。例外：角色在故事世界内真实阅读/讨论“第X章”文本，或真实身为作者/读者并谈论读者身份时，可保留相应词。
