# workflow-outline.md：出细纲（按剧情批出细纲、补纲）

> 谁读：主会话出细纲、补纲时整份读；「排纲方法」一节进 story-architect 细纲任务包。

## 主会话：出细纲的步骤与汇报

卷纲只用 `outline_view.py --unit {单元编号}` 取全卷段与本段剧情（老卷纲有「作用域：批次底稿」段时加 `--stage outline`），设定从 `设定/` 定点读，不回翻对话；参考文件按 SKILL.md「写前必读」总表「出细纲、补纲」一行读。

已部署 story-architect 时，每批细纲在它的新上下文里出，调用见 [agent-calls.md](agent-calls.md)。没有子代理时主会话按下方「排纲方法」自己出：先给本批走向提案，作者确认后落盘。

**收回与验收**：每章细纲落盘后跑 `node scripts/check-outline-contract.js --json --project {书目录} --chapter {N}`（查什么见 outline-template.md）。exit 1 只按 `repair_scope` 补报告点名的字段再复验，最多两轮；仍失败就报告检查 ID 停下，不改其他章。advisory 项逐条人工判断，不强制归零。exit 2、脚本缺失或 node 不可用时如实报告验收未完成，不得声称细纲已合规。出完一批另跑一次 `node scripts/check-outline-contract.js --json --supply {卷纲路径} {单元编号}`，验证排纲笔记里有「写纲前查缺」（含「无缺口」情形）；脚本只验小节存在，内容仍要人工判断。本检查只在新建、补建、回填时执行；既有项目的旧细纲不因此阻断写正文。

**中途补纲/扩纲小流程**（项目已有大纲；只改细纲不进入正文大修）：
1. 定位请求范围、已写进度和所属剧情段：读 `大纲/大纲.md`；卷纲先用 `outline_view.py --toc {卷纲路径}` 定位，再 `--unit {单元编号}` 取闭包，尚无剧情段用 `--contract` 取全卷段，不整读。另读 `设定/题材定位.md` 和已有 `追踪/上下文.md`；有正文却缺追踪时停止补纲，提示按 workflow-daily 修复/迁移，不猜进度；无正文也无追踪时以现有纲/设定规划，不为读取状态先初始化。
2. 请求章已属于既有剧情段时复用这张卡，只补/改点名细纲，不另建剧情段；沿用「细纲锁定」。确需新剧情段先按 workflow-volume.md 追加卡（含「对标节奏迁移」选同类剧情），向卷尾**追加**卡及情绪弧线、故事线、伏笔规划，已锁定内容不动。新故事线先加进卷纲故事线表并写清在哪并回主线，再供细纲引用；日更不自动扩纲。正文里新长出的伏笔怎么编号见 SKILL.md「新增物三级」。用户补纲不等于授权修改其他章；超出本卷体量时先确认扩卷或开新卷。
3. 追加剧情段时答 workflow-volume.md「排纲自查」四项（按段内 1/4·中点·3/4 口径）；进入细纲层时先做下方「写纲前查缺」。
4. 按本次交付层级停止：需要细纲时按批次边界只做请求范围，完成「细纲后设定补全」与批末复核。
5. 规划事件和未来揭示只落卷纲/细纲，不提前成为追踪事实。已有正文项目补纲不写 `追踪/`，不执行 init/commit；下一章必须履行的承诺在下一次正文事务里进入 `next_chapter_commitments`。

**向作者汇报**（开书、大纲、卷纲、细纲、补纲、改细纲都用这一份；按 SKILL.md「面向作者的汇报」）：写纲前查缺、批末复核是内部核对，只把结论翻成故事话；要问作者的缺口，以及设定互相冲突的情况，都作为「要你定的事」问。出细纲后最后一句建议新开对话说「写第N章」。

## 排纲方法：批次、设定补全与分批

所请求范围内每章必须有 `大纲/细纲_第XXX章.md`，不跳章。细纲按剧情批构建（见本节末「按剧情批出细纲」）；仅未限定范围的完整开书默认前 10 章，其他按 SKILL.md 的范围与停点交付：
1. **批次边界**：未指定章数时，一批 ≈ 一段剧情；>10 章拆两批。开书时前 10 章为一批、可跨段；每段建卡时召回一次，后续批共享结论。用户指定章数/范围时，只建范围内细纲，不因剧情段未完或剩余 ≤2 章而扩批；单批仍建议 ≤10 章。写正文缺纲按 workflow-chapter 开头处理。
2. **批次定位**（每一批补纲前先写进排纲笔记）：当前章节区间属于哪个阶段与哪段剧情、这一批推进什么、可以揭开什么、先压住什么、章尾钩子不能越过的边界。
3. **写纲前查缺**：每批出细纲前查六项：①对手戏由谁接？具名对手隔了 2 章以上没出现是复核提示；对手可为盟友或亲人，环境、关系章不为凑间隔新增反派。②未来 3 章出场角色的设定卡齐不齐？③能力的新增和已有的接不接得上？④本批要用的数字、制度、规矩、距离与脚程在设定里真有没有？引用前检索核对具体条目，不能只猜文件存在。⑤本批用到的地点先落档；只提名不强补场景布局。是否和上一段同场景、同对手、同胜负手连排，要不要调？⑥本批推进哪几条故事线，还有没有能调的存货？结果以「写纲前查缺」小节写进书目录下的 `.story/排纲笔记/{剧情段编号}.md`（模板见 outline-template.md「排纲笔记」，不进卷纲）：补上并记下的写清补了什么、落在哪个设定文件；要问作者的列候选及影响面；没缺写「无缺口」。并检查上一批「本章没写成的」与「写纲时补的」里还没解决的缺口。
4. **用卡排章**：建卡那批读这段剧情「参考对标书哪段剧情」指向的对标剧情（≤3 个文件，含结构分布/情节点索引），按「这段怎么排」铺章、情节点换素材；同一段的后续批共享卡里定下的结论，不重读对标剧情。当前卷纲缺少必需的剧情段字段时先补齐卷纲，不带缺失字段进入日更。
5. **写纲当场缺东西**：按下方「缺东西时三种处理」——能直接写的写进细纲，补上并记下的先落档再引用，要问作者的挂起受影响内容，其余部分继续。批末把后两种汇进同一份排纲笔记的「写纲时补的」：章号、缺什么、怎么处理、设定路径或提案；没有写「无」。直接写的现场材料不重复记录。
6. **批末复核**（每批建完必做）：七个必填字段和可执行情节点齐全；「这章不能说破」可不写。不得用“每个情节点固定等于多少字”预测容量或自动补事件。结构检查脚本由主会话跑，报告点名哪个字段就只补哪个。**旧章细纲缺字段是常态，不要照抄同目录既有文件的字段集**，以 outline-template.md 为准。内容好坏不设脚本检查。

不强行一次产出 30 章细纲；全书 ≤30 章且用户明确要全书细纲时，可分批连续交付。

### 细纲模板与验收

模板、字段说明（哪些字段被脚本按名读取）与验收口径见 [outline-template.md](outline-template.md)「细纲」；排纲笔记模板见同一文件「排纲笔记」。新建、补建、回填都照它补齐。

**细纲锁定**：已写正文的章细纲锁定，未经用户确认不得修改；未写的章细纲可随正文反馈微调，改了写进汇报。已进入正文的卷的卷纲锁定规则见 workflow-volume.md。

**细纲质量要求**：每章细纲都要能直接指导正文，七个必填字段齐备，但**强度按松紧分配、不是每章顶满**：爆发、推进章配齐钩子、爽点和悬念；松的章（感情或关系戏、修炼、日常、过渡）允许无显性爽点、弱钩子或只有情绪钩子，「这章怎么走」的高潮可写「本章无高潮：{功能}」，重点是把功能（喘息、关系、铺垫、转场）写到位。底线是每章都给读者一个往下看的理由、相邻章情绪不雷同（见 outline-methods「每章松还是紧」）。字段不完整时先补齐；无法从材料确定的关系或副线写 `[待补充]`，不得杜撰。单章默认字数见 outline-methods「排纲刻度」。

> **细纲钩子来源**：优先沿本批剧情段「参考对标书哪段剧情」的走法与兑现方式设计钩子链；对标登记 ≥2 本时读 `cross-book-recall.md`，副对标同基调 `章节/*_摘要.md` 仍可作单章钩子灵感（可选）

**章节标题规则**：章名取本章最有冲突或最有梗的那条信息，不用「开始」「觉醒」这类概括词，也不把本章的兑现剧透出来。只做轻量去重；发现同名或明显重复标题时，按本章核心事件改名，并保持细纲标题与正文文件名一致。

**细纲后设定补全（每批细纲建完后执行）**：扫描本批细纲新出现的具名角色/势力/关键设定，对**会复用**的（按卷纲/细纲判断：后续多次出场或承担剧情功能）自动建档，不等用户确认：
- 角色 → 建 `设定/角色/{名}.md`（填空模板见 character-basics.md 主角卡/配角卡）；核心复用角色真正进入正文后，由追踪事务建立 `追踪/角色状态/{名}.md` 动态快照；
- 势力/组织 → 建 `设定/势力/{名}.md`（名称、定位、核心目标、关键人物、与主角关系）；
- 影响多章的世界观规则 → 建/补 `设定/世界观/{主题}.md`（规则、适用范围）。
- **刻度与名目** → 建/补 `设定/世界观/{主题}.md` 里的对照表。凡是正文要拿来**比大小、算价钱、报名次、定档位**的东西都算：资质/评级档位、职级与待遇、货币与物价、等级与进度格、名次与席位、赏罚名目、时限与期限。写成**可数的序列**（几档、哪一档在哪、相邻两档差多少），不要只写一个孤立的值。

**缺东西时三种处理——不许硬写，也不许一律停摆。** 判据见 SKILL.md「新增物三级」（交给 story-architect 时任务包末尾已附原文）。排纲时需要一样东西（角色、能力、物价、规矩、刻度、场景）而设定里查不到时，先查再分：

0. **先查**：`设定/世界观/`、`设定/势力/`、`设定/题材定位.md`（实力怎么一级一级往上走）里是不是已经有（同一件事在不同文件里可能叫不同名字，换个说法登记的也算）。
1. **直接写**：写进细纲，不落档、不上报。
2. **补上并记下**：不与既有设定冲突时直接补。先补进设定文件，再供细纲引用，并在排纲笔记的「写纲前查缺」里登记。项目引用用书目录相对路径（如 `设定/角色/张三.md`）；`./`、`../` 相对细纲目录，裸文件名不校验。地点只补本批用到的分区、进出口、相对位置或脚程。
3. **问作者**：不自行决定。在排纲笔记的「写纲前查缺」里列具体缺口、1-2 个候选及关联设定影响，批末按汇报模板用故事话问作者；作者定了先落设定再引用，不以占位或临时编数代替。设定互相冲突时列出出处供作者判断。

已存在的设定文件按细纲新信息**增量补充、不覆盖**。一次性路人、后文无戏份的配角不建静态档案或动态快照。建档只填细纲已确定的信息，未定字段留占位符，不提前杜撰。

### 按剧情批出细纲（细纲分批边界）

一批细纲 = 卷纲里的一段剧情。体量换算：这段字数 ÷ 单章目标字数 → 章数，单章目标字数取本书既有细纲惯例，没有惯例按 outline-methods「排纲刻度」。一段 >10 章拆两批，两批共享同一次召回；开书时前 10 章为一批、可跨段（跨入的那段建卡时召回一次，余章由后续批共享卡里的结论），停靠规则见上文批次步骤 1。

建卡时做一次**剧情批召回**：读这段「参考对标书哪段剧情」指向的对标剧情（≤3 个文件）的「结构分布」「情节点索引」，回查该书 `剧情/节奏.md` 同章节区间的爽点循环 / 触动点与被引情绪模块卡，提炼 5-8 拍共性节拍写入卡的「这段怎么排」，「这段让读者图什么」对照主对标 `剧情/情绪模块.md` 的可复现模块校准。主产物在但被引的单个情绪模块卡没命中，只跳过该卡；主产物缺了怎么办按 benchmark-recall.md。换素材与修硬伤同 workflow-volume.md「对标节奏迁移」步骤 3、4——保留情绪链和功能位，对象、场景、事件全换，对标弱处理就地修正。结论写进卡里后，逐章细纲只用卡，不重读对标剧情。

**「只用卡」管的是不重读对标，不冻结逐章出纲。** 排纲当场发现的缺口（某拍无对手、数值没验过、地点没有场景布局、角色既定规矩挡场之类）按上文「缺东西时三种处理」，处理完记一行，批末汇进排纲笔记的「**写纲时补的**」（见上文批次步骤 5）；下一批写纲前查缺固定读它，并按缺口类别加批前盘点项。

日更中途发现卷纲缺少「参考对标书哪段剧情」等必需字段时，先补齐卷纲再建细纲；锁定卷纲不得自动回写，必须停在补纲边界。节拍分析过程不写进追踪文件，只有最终影响未来连续性的约束或下一章承诺才进入本章追踪事务。
