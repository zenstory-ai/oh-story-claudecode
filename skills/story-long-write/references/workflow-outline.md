# workflow-outline.md：出细纲（按剧情批出细纲、补纲）

作者要看一批章节怎么走、或要补/改细纲时读本文件。卷纲只用 `outline_view.py --unit {单元ID}` 取本单元闭包，设定从 `设定/` 定点读，不回翻对话；前 3 章细纲另读 [opening-design.md](opening-design.md)，建角色档案时读 character-basics.md。没有子代理时先给本批走向提案、作者确认后落盘；交付汇报最后一句建议新开对话说「写第N章」，技术备注在它后面。

所请求范围内每章必须有 `大纲/细纲_第XXX章.md`，不跳章。

细纲按剧情批构建（见文末「按剧情批出细纲」）；仅未限定范围的完整开书默认前 10 章，其他按 SKILL.md 的范围与停点交付：
1. **批次边界**：未指定章数时，一批 ≈ 一个剧情单元（5-15 章）；>10 章拆两批。开书首批前 10 章封顶、可跨单元；每单元建卡时召回一次，后续批共享结论。用户指定章数/范围时，只建范围内细纲，不因单元未完或剩余 ≤2 章而扩批；单批仍建议 ≤10 章。日更缺纲按 workflow-daily 的补建流程处理。
2. **批次定位与阶段约束**（每批补纲前先写）：当前章节区间属于哪个阶段与哪个剧情单元（单元ID）、本批推进目标、本批可释放信息、本批严禁提前释放信息、章尾钩子不能越过的边界。
3. **供给自查**（排纲自查第 5 项）：每批出细纲前检查六项：①对手戏由谁承接？具名对手间隔超过 2 章是复核提示；对手可为盟友或亲人，环境、关系章不为凑间隔新增反派。②未来 3 章出场角色的设定卡是否齐全？③能力增量与既有库存是否接得上？④本批引用的数字、制度、规矩、距离与脚程是否确实存在？引用前 grep 核对文件里的具体条目，不能只猜文件存在。⑤本批使用的地点空间属性先落档；仅提名不强补底图。是否与上一单元同场景、同对手、同胜负手连排，需要调整？⑥本批有哪些故事线推进，是否有可调存量？结果以「供给自查」小节写进 `大纲/排纲底稿_{单元ID}.md`（模板见文末，不写进卷纲）：「写了要报」登记新增内容与设定路径，「先问作者」列候选及影响面交作者裁定；无缺口写「无缺口」。并检查上一批「本章没写成的」与「建纲追加」里的未解决缺口。
4. **剧情单元消费**：建卡批读本批剧情单元卡「对标剧情参照」指向的剧情单元（≤3 个文件，含结构分布/情节点索引），按单元节拍→章映射铺章、情节点换素材；同一剧情单元的后续批共享剧情单元卡固化结论，不重读剧情单元。当前卷纲缺少必需剧情单元字段时先补齐卷纲，不带缺失字段进入日更。
5. **建纲当场缺口**：按下方三级处置——直接写的写进细纲，写了要报的先落档再引用，先问作者的挂起受影响内容，其余部分继续。建纲批末把后两级汇入同一份排纲底稿的「建纲追加」小节：章号、缺口、级别、设定路径或提案；无追加写「无」。不重复记录直接写的现场材料。
6. **建纲批末复核**（每批建完必做）：确认 `visible_chars_v1` 口径、九个必填字段、禁止提前释放和可执行情节点齐全。不得用“每个情节点固定等于多少字”预测容量或自动补事件；每章细纲落盘后必须跑 `node scripts/check-outline-contract.js --json --project {书目录} --chapter {N}`：exit 1 只按 `repair_scope` 补点名字段再复验，最多两轮；advisory 项逐条人工判断，不强制归零。建纲批末另跑一次 `node scripts/check-outline-contract.js --json --supply {卷纲路径} {单元ID}` 验证本批供给自查已写进排纲底稿（含「无缺口」情形）；脚本仅验供给小节存在，内容仍需人工判断。**旧章细纲缺字段是常态，不要照抄同目录既有文件的字段集**，以本节模板为准。语义仍不设 checker。场面块见 scene-grammar.md，不填或全是待补充则通过。

不强行一次产出 30 章细纲；全书 ≤30 章且用户明确要全书细纲时，可分批连续交付。

#### 细纲模板与验收

细纲是正文写作的章节蓝图，而不是只列事件和钩子的清单。模板见下（唯一权威副本：九个必填字段、四个小节、不含逐点字数的四列情节点表，阶段位置、结构公式等在末尾「可选」块）。新建、补建、回填都按权威模板补齐，未知字段写 `[待补充]`，不为补齐字段杜撰副线或人物关系。

`目标情绪` 与 `主角目标/关键选择` 要写实际内容，不能留 `[待补充]`：隔离实验里只补这两个字段就能复现补齐全部字段的正文收益，补满其余字段与只补这两个不可区分。其余字段未知时仍按上文写 `[待补充]`。

落盘后运行 `node scripts/check-outline-contract.js --json --project {书目录} --chapter {N}` 做结构检查：它只判字段、四个小节、五段式、情节点表结构（默认四列 `# / 情节点 / 功能标签 / 执行边界（禁＋放）`；需要时可在功能标签后加「分辨率」列）和字数目标口径是否在场，不判内容好坏。exit 1 时只按 `repair_scope` 补报告点名的字段并复验，最多两轮；仍失败就报告检查 ID 停下，不改其他章。exit 2、脚本缺失或 node 不可用时如实报告验收未完成，不得声称细纲已合规。本检查只在新建/补建/回填时执行；既有项目的旧细纲不因此阻断写正文。

**大纲锁定**：已进入正文写作的前 10 章细纲锁定，未经用户确认不得修改；后续滚动细纲可随正文反馈微调。已进入正文的卷的卷纲锁定规则见 workflow-volume.md。

**中途补纲/扩纲小流程**（项目已有大纲；只改细纲不进入正文大修）：
1. 定位请求范围、已写进度和所属单元：读 `大纲/大纲.md`；卷纲先用 `outline_view.py --toc {卷纲路径}` 定位，再 `--unit {单元ID}` 取闭包，尚无单元用 `--contract` 取契约，不整读。另读 `设定/题材定位.md` 和已有 `追踪/上下文.md`；有正文却缺追踪时停止补纲，提示按 workflow-daily 修复/迁移，不猜进度；无正文也无追踪时以现有纲/设定规划，不为读取状态先初始化。
2. 请求章已属于既有单元时复用单元卡，只补/改点名细纲，不另建单元；沿用上方锁定规则。确需新单元先按 workflow-volume.md 追加单元卡（含「对标节奏迁移」选同类单元），向卷尾**追加**卡及情绪弧线、故事线、伏笔规划，已锁定内容不动。用户补纲不等于授权修改其他章；超出本卷体量时先确认扩卷或开新卷。
3. 追加单元时答 workflow-volume.md「排纲自查」1–4（按单元内 1/4·中点·3/4 口径）；进入细纲层时做本文件步骤 3 供给自查。
4. 按本次交付层级停止：需要细纲时按上述批次边界只做请求范围，完成「细纲后设定补全」与建纲批末复核。
5. 规划事件和未来揭示只落卷纲/细纲，不提前成为追踪事实。已有正文项目补纲不写 `追踪/`，不执行 init/commit；下一章必须履行的承诺在下一次正文事务里进入 `next_chapter_commitments`。

**细纲质量要求**：每章细纲都要按当前章节蓝图直接指导正文（核心事件、字数目标、字数口径、单元ID/位置、目标情绪、主角目标/关键选择、章首钩子、爽点、本章禁止提前释放九个必填字段齐备），但**强度按章节定位分配、不是每章顶满**：高压/推进章配齐钩子+爽点+悬念；低压/关系/修炼/信息整理章允许无显性爽点、弱钩子或仅情绪钩子，重点是把功能（喘息、关系、铺垫、转场）写到位。底线是每章都给读者一个往下看的理由、相邻章不情绪趋同（见 workflow-volume.md「章节定位与张弛」）。字段不完整时先补齐；无法从材料确定的关系或副线写 `[待补充]`，不得杜撰。

> **细纲钩子来源**：优先沿本批剧情单元卡「对标剧情参照」的单元节拍与兑现方式设计钩子链；对标登记 ≥2 本时读 `references/cross-book-recall.md`，副对标同基调 `章节/*_摘要.md` 仍可作单章钩子灵感（可选）；有 `灵感库/` 时可按「适用阶段=细纲」召回 active CBA 辅助钩子设计，零命中不阻塞

**章节标题规则**：只做轻量去重；发现同名或明显重复标题时，按本章核心事件改名，并保持细纲标题与正文文件名一致。

**细纲后设定补全（每批细纲建完后执行）**：扫描本批细纲新出现的具名角色/势力/关键设定，对**会复用**的（按卷纲/细纲判断：后续多次出场或承担剧情功能）自动建档，不等用户确认：
- 角色 → 建 `设定/角色/{名}.md`（填空模板见 character-basics.md 主角卡/配角卡）；核心复用角色真正进入正文后，由追踪事务建立 `追踪/角色状态/{名}.md` 动态快照；
- 势力/组织 → 建 `设定/势力/{名}.md`（名称、定位、核心目标、关键人物、与主角关系）；
- 影响多章的世界观规则 → 建/补 `设定/世界观/{主题}.md`（规则、适用范围）。
- **刻度与名目** → 建/补 `设定/世界观/{主题}.md` 里的对照表。凡是正文要拿来**比大小、算价钱、报名次、定档位**的东西都算：资质/评级档位、职级与待遇、货币与物价、等级与进度格、名次与席位、赏罚名目、时限与期限。写成**可数的序列**（几档、哪一档在哪、相邻两档差多少），不要只写一个孤立的值。

**缺什么按新增物三级处置——不许硬写，也不许一律停摆。** 判据见 SKILL.md「新增物三级」（交给 story-architect 时任务包末尾已附原文）。排纲时需要一样东西（角色、能力、物价、规矩、刻度、场景）而设定里查不到时，先查再分级：

0. **先查**：`设定/世界观/`、`设定/势力/`、`设定/题材定位.md`（升级台阶）里是不是已经有（同一件事在不同文件里可能叫不同名字，换个说法登记的也算）。查不到的按下面三级处置。
1. **直接写**：写进细纲，不落档、不上报。
2. **写了要报**（发明＋落档）：不与既有裁定冲突时直接补充。先增量落设定，再供细纲引用，并在排纲底稿的供给自查里登记。项目引用用书目录相对路径（如 `设定/角色/张三.md`）；`./`、`../` 相对细纲目录，裸文件名不校验。地点只补本批用到的分区、进出口、相对位置或脚程。补纲授权下的新故事线先在卷纲故事线表分配 L 编号并写清主线对接口，再供细纲引用；日更不自动扩纲。
3. **先问作者**（提案裁定）：不自行决定。在排纲底稿的供给自查里列具体缺口、1-2 个候选及关联设定影响，建纲批末按下方汇报模板用故事话问作者；裁定先落设定再引用，不以占位或临时编数代替。设定互相冲突时列出出处供作者判断。

已存在的设定文件按细纲新信息**增量补充、不覆盖**。一次性路人、后文无戏份的配角不建静态档案或动态快照。建档只填细纲已确定的信息，未定字段留占位符，不提前杜撰。

**规划交付后向作者汇报**（细纲、补纲、改细纲用；按 SKILL.md「面向作者的汇报」）：供给自查、建纲批末复核是内部核对，只把结论翻成故事话；「先问作者」的缺口和两个设定互相冲突都作为「要你定的事」问。

## 附：按剧情批出细纲与排纲底稿模板

### 按剧情批出细纲（细纲分批边界）

一批细纲 = 卷纲里的一个剧情单元（约 5-15 章）。体量换算：剧情单元字数 ÷ 单章目标字数 → 章数，单章目标字数取本书既有细纲惯例，无惯例按题材节奏档取默认（快节奏/短平快约 2000，均衡约 3000）；剧情单元超过 1.5 万字且单元节拍含两个以上独立高潮时拆成多个剧情单元，否则单个剧情单元。剧情单元 >10 章拆两批建纲，两批共享同一次召回；首批 = 前 10 章封顶、可跨单元（跨入的剧情单元建卡时召回一次，余章由后续滚动批共享剧情单元卡结论），停靠规则见上文批次步骤 1。

建卡时做一次**剧情批召回**：读剧情单元卡「对标剧情参照」指向的剧情单元（≤3 个文件）的「结构分布」「情节点索引」，回查该书 `剧情/节奏.md` 同章节区间的爽点循环 / 触动点与被引情绪模块卡，提炼 5-8 拍共性节拍写入剧情单元卡「单元节拍/章功能分配」，单元情绪引擎字段对照主对标 `剧情/情绪模块.md` 的可复现模块校准。若主产物存在但被引的单个情绪模块卡未命中，只跳过该卡；`剧情/情绪模块.md` 或 `剧情/节奏.md` 文件缺失按 workflow-volume.md「对标节奏迁移」的 fail-fast 先修复。换素材与修硬伤纪律同该节步骤 3/4——保留情绪链和功能位，对象、场景、事件全换，对标弱处理就地修正。结论固化进剧情单元卡后，逐章细纲只消费剧情单元卡，不重读剧情单元。

**「只消费剧情单元卡」管的是不重读对标，不冻结逐章建纲。** 排纲当场发现的缺口（某拍无对手、数值没验过、地点无底图、角色既定规矩挡场之类）按新增物三级处置（直接写／写了要报：先落档再引用／先问作者：挂起提案，见上文「缺什么按新增物三级处置」），处置完记一行，批末汇进排纲底稿的「**建纲追加**」小节（见上文批次步骤 5）；下一批供给自查以该小节为固定输入（按当场缺口类别加问批前盘点项）。

日更中途发现卷纲缺少「对标剧情参照」等当前协议必需字段时，先补齐卷纲再建细纲；锁定卷纲不得自动回写，必须停在补纲边界。单元节拍分析过程不写进追踪文件，只有最终影响未来连续性的约束或下一章承诺才进入本章追踪事务。
