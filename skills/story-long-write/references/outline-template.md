# 细纲与排纲笔记模板

> 谁读：主会话出细纲、补纲、写正文前补建点名章细纲时读；story-architect 出细纲的任务包整份带入。

## 细纲（`大纲/细纲_第XXX章.md`）

细纲是正文写作的章节蓝图，事件和钩子之外还要写清情绪、选择和情节点。模板见下（唯一一份：八个必填字段、四个小节、不含逐点字数的四列情节点表，阶段位置、结构公式等在末尾「可选」块）。新建、补建、回填都按模板补齐，未知字段写 `[待补充]`，不为补齐字段杜撰副线或人物关系。

`目标情绪` 与 `主角目标/关键选择` 要写实际内容，不能留 `[待补充]`。章首、章尾钩子的类型见 long-chapter-hooks.md「章首钩子 7 式」「章尾钩子 13 式」，只选类型，不照抄示例句。前 3 章里要安排一次主角和对手的正面冲突（当面交锋，不是只听说或远远看见），排进其中一章的情节点表（见 opening-design「开篇规划」）。

`check-outline-contract.js` 只判字段、四个小节、五段式、情节点表结构（四列 `# / 情节点 / 作用 / 分寸`；需要时可在「作用」后加「分辨率」列）和字数目标是否在场，不判内容好坏。老细纲的旧字段名照样过检查；作者想统一成新写法可跑 `scripts/convert_outline_format.py {书目录}`（只换格式不改内容）。

<!-- 脚本按名读取、改名会让它们读不到的字段：「字数目标」「字数范围」（章节检查与字数验收）、「属于哪段剧情」末尾注释里的单元编号、「目标情绪」（写正文的组装脚本）、
「原样出现的原话」（细纲照搬检测）、「## 第 N 章：章名」这一行（正文文件名）；必填字段与四个小节名由细纲检查脚本核对。 -->

```markdown template=细纲
## 细纲（第 N 章）

### 第 N 章：{章名}
- 核心事件：{一句话}
- 字数目标：{X} 字
- 属于哪段剧情：{卷纲里那段剧情的名字}，{这章在那段里做什么，如「第二步：加压」} <!-- {单元编号，如 L1-01} -->
- 目标情绪：{读者从什么情绪走到什么情绪；这章把这段剧情让读者图的那口气推进到哪；不要只写「热血」「悲伤」这类词}
- 主角目标/关键选择：{主角这章要什么；必须做出的判断或取舍}
- 章首钩子：{从章首7式中选择} — {具体内容；松的章、过场章可写「弱钩子/只有情绪钩子，功能是…」}
- 爽点：{这章的爽点；松的章、修炼章、过场章可写「无显性爽点，功能是…」，但仍要给读者一个往下看的理由}
- 这章不能说破：{只写这章特有的三五条；全卷都不能碰的已在卷纲「本卷不能碰的大牌」，不逐章复读；没有写「无」}

#### 内容概括（五段式）
- 起因：{这章的事为什么发生}
- 发展：{冲突怎么推进}
- 转折：{信息、关系或局势哪里变了}
- 高潮：{情绪或动作最高的地方；松的章、过场章写「本章无高潮：{功能}」}
- 结尾：{最后落在谁的什么动作、画面或台词上——写具体落点，不写「尘埃落定」「一切结束」这类判词}

#### 情节安排（多线）
- 主线推进：{这章对主目标的推进}
- 辅线推进：{按卷纲故事线表的线名写「老兵线从哪一步推到哪一步」；这章确实没有别的线在动写「无」，不凭空制造。一批细纲不许每章都是「无」}
- 事件线 / 任务线：{外部事件链；有「办事被卡住」时写清卡出什么变化，删掉也不损失的卡点不进细纲}
- 感情线 / 关系线：{有感情线时写所处阶段和这章推进，CP 的言行不越过当前阶段；没有显性感情线写「无显性，但关系变化为…」}
- 逻辑线：原因 → 行动 → 结果 → 后果/新问题

#### 人物关系和出场顺序
- 出场顺序：{角色、势力、关键物件按实际出现顺序}
- 人物关系变化：{这章前 → 这章后}
- 视角/信息差：{谁知道什么；读者知道什么；主角误判什么。取自 `追踪/时间线/读者已知.md`，不另起一套；还没有追踪的新书按设定与卷纲写}

#### 情节细化
| # | 情节点（谁做了什么） | 作用 | 分寸 |
|---|---|---|---|
| 1 | {主角在账单上发现4800元转出} | {信息揭示} | {他当场算出这笔钱等于几个月房租；幕后是谁先不露} |

- 作用＝这一点干什么：铺垫/高潮/爽点/打脸/人物塑造/设定。点数按需要定，不填逐点字数，不用 `目标字数 / beat 数` 反推。
- 分寸＝这一点放到什么程度：可以写到多满（谁能出声、谁能失态、能不能当场算价钱），哪些先不露；每章至少一个点写明可以放开写的地方。
- 原样出现的原话：{必须一字不差进正文的原话（誓言、面板、旧案原话），一行一条并注明在第几点，如「点3：立此为凭…」；没有写「无」}
- 行动成本（可无）/收益归属：{可无行动成本；收益归谁、怎么让人看见、有没有留下后续账}

#### 结尾设定和钩子
- 结尾设定：{落到什么具体动作或画面（不写「就这样……」「他终于明白……」这类判词）；没解决的问题；下一章往前推的力}
- 章尾钩子：{从章尾13式中选择} — {具体内容，强/中/弱；松的章、过场章可以弱钩子或留阶段目标；下一章怎么接}

#### 可选：需要时再写（写了写手照样用，不写不拦）
- 字数范围：{作者给了上下限才写，如 2000-2600}
- 阶段位置、松紧（高压/推进/修炼试错/关系回收/低压生活/信息整理）、本章结构公式
- 本章标价（得失折算成读者已知的什么）、闭环状态（获得/使用/见效/估值走到哪一拍）
- 写手自由区（本章最值得放开、由写手发明的几处）、镜头准入（一场给谁台词位）、信息差触发点（在第几点提醒读者手里的牌）
- 情节点表加「分辨率」列（密/中/疏，同类并列递减）
- 有没有硬伤：只在这章让剧情段的「有没有硬伤」变了时写（没问题/要补/有硬伤）
```

## 排纲笔记（`大纲/排纲笔记_{单元编号}.md`）

排纲时的工作笔记，每段剧情一份，只在排纲/补纲时读，写正文不读。老书里叫 `排纲底稿_{单元编号}.md`、小节叫「供给自查」「建纲追加」的照样认，不必改名。

```markdown template=排纲笔记
# {这段剧情的名字} 排纲笔记

## 批次定位
{每批补纲前先写，见 workflow-outline「排纲方法」的批次定位：阶段与哪段剧情、本批推进目标、可以亮什么与不能说破什么、章尾钩子的边界；多批时一批一段}

## 写纲前查缺
{本段出细纲前写，见「排纲方法」的写纲前查缺。六行：对手 / 角色 / 能力与金手指 / 数字与刻度 / 场景与底图 / 故事线。补上并记下的各列一行「补了什么＋落在哪个设定文件」；要问作者的列候选＋影响面；没缺写「无缺口」}

## 写纲时补的
{本批建完后回填，见「排纲方法」的写纲当场缺东西；写正文时申报表「本章没写成的」里「细纲没给」的也追加在这里。逐章落笔时才发现的缺口，一条一行，不和上面六行混写。格式：`第 N 章排到哪一步发现缺什么 ／ 怎么处理的 ／ 落在哪个设定文件或提案`。一条也没有写「无」。下一批写纲前查缺固定读这里}
```
