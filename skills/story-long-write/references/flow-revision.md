# 回炉大修与症状诊断（flow-revision）

> 谁读：主会话修改、回炉、重写已写章节时整份读；同时按需读 `flow-drafting.md`「正文笔法与竖屏网感」与本书 `references/genre-styles/{流派}.md`。

只改细纲走 `flow-outline.md`。作者只给模糊感受、没点名章号时，先按下方诊断定位请作者确认再进 Step 1。

---

## 症状诊断（作者只说感受时先用）

| 作者或读者反馈 | 优先排查 | 常见病因 | 改法与对应手册 |
|---|---|---|---|
| **开头留不住人 / 闷** | 第 1–3 章 | 纯景物开篇、首章迟迟无冲突、金手指滞后、章末无钩 | 按 `flow-drafting.md` 黄金三章 + 流派包重写；结构错先改纲 |
| **文学腔重 / 看着累** | 段落与标点 | 整块文字墙、书面抒情、缺交锋（先核是否独角戏） | 删书面虚饰拆开大段文字墙，保留口语因果过渡与短对话快推（禁硬剁成无内心碎句） |
| **拖、水、不知在干嘛** | 期待链与松紧 | 旧爽点兑现后无新期待、过场长、兑现慢 | 兑现前移、并章过场；兑现前埋下条钩（`flow-outline.md`） |
| **剧情空洞 / 假、太顺** | 博弈与阻力 | 反派送脸自爆、双重巧合喂饭、主角全知零阻力走过场 | 回 `flow-outline.md` 补对手真实私心反咬、意外阻滞与实感代价，删水过场 |
| **「又是这一套」/ 腻了** | 相邻剧情段 | 连续两段同场景、同对手或同破局手段 | 回 `flow-opening-plan.md` 换场景、换层级或开金手指新用法 |
| **主角憋屈 / 毒 / 圣母** | 四个排纲问题 | 功劳被外援抢、低级降智、核心资产白交 | 回 `flow-opening-plan.md` 四问修纲，把抉择实利拿回主角 |
| **换地图后崩了** | 换图前 3 章 | 旧关系旧期待清空，像从零开新书 | 回 `flow-opening-plan.md` 换图带入旧仇、熟人或上级线 |
| **战力/财富越写越飘** | 升级与物价 | 境界/资产破顶、旧技弃用、失生活刻度 | 回 `flow-outline.md` 四阀：定硬顶、旧技二创、补支出与物价 |
| **中后期失焦/串腔/复读** | ≥50 章近批 | 配角失踪、漂成 `不是A。是B。`、复读或年龄打架 | 回 `flow-drafting.md` 复读前 5 章找回前期语气、删复读并锁年龄 |
| **变味 / 串台** | 流派边界 | 写了邻近题材节奏或雷区 | 回本书 `genre-styles/{流派}.md` 核对定位、说话语气与雷区 |
| **男主油腻 / 爹味下头** | 感情互动戏 | 喊「小女人/小白兔」、壁咚强迫、暴力霸道当痞帅、用钱敷衍 | 回 `flow-drafting.md`「女频去油」与人设去油红线：删强压标签，写尊重边界与关键托底 |
| **女主恋爱脑 / 低级雌竞** | 冲突与情感戏 | 向绝情亲人/渣男讨爱、扯头花、连章受气不反制 | 回 `flow-opening-plan.md` 主体性红线：改干脆止损、账本反击或女性互助 |
| **甜虐失衡 / 工业糖精** | 情感弧线 | 靠 `宠溺/喉结/耳尖红` 喂糖、虐超 3 章无反手或真出轨洗白 | 回 `flow-outline.md` CP 四拍与排雷底线：糖落具体小事，真出轨改男二上位 |
| **动作碎句 / 环境摆设 / AI 味** | 叙述与细节 | 抽干内心的动作碎句、没用的材质穿搭和空镜摆设、对白绑道具、公文腔 | 补主角盘算与口语因果、改短对话快推、只留关键改局道具；整章走 `/story-deslop` |

白话报 1–2 个主因、先改哪章与一句改法，确认再动手。

## 大修流程

### Step 1：定章与范围

1. 定位 `正文/第{X}章_*.md`（按章号或章名查，找不到就问）。
2. 点到具体场面 → **局部修改**；说「重写/回炉」→ **整章重写**；拿不准用白话选项问：`1. 只改点到的地方（推荐） / 2. 按原细纲整章重写 / 3. 先改细纲再重写（先走 flow-outline.md）`。

### Step 2：按范围加载上下文

- **必读**：待改章全文、`大纲/细纲_第{X}章.md`、`tracking_commit.js check`（取 `state_revision`）与 `追踪/上下文.md`（缺 state 停下先走 `/story-import`）。
- **局部修改**：前章看末尾几段（第 1 章无）、后章看开头几段；只读涉及角色卡与 `追踪/角色状态/`。
- **整章重写**：前后两章全文 + 细纲点名设定；第 1 章看 `设定/题材定位.md` 与流派包切片。

### Step 3：备份、改写与检测

1. **备份与计字**：复制原稿到 `.story/work/修订原稿/{YYYYMMDD}_{原文件名}`（不放 `正文/`）；改章名须先移走旧正文文件防双文件撞车；跑 `node {skill 根}/scripts/storyctl.js wordcount measure --file {正文文件}` 记原字数。
2. **改写**：有 `narrative-writer` 按 `agent-calls.md`「大修改写」派发；否则按 `flow-drafting.md` 与流派包自改。局部改不动范围外，不擅加细纲外剧情。
3. **改后检测**：跑 `node {skill 根}/scripts/storyctl.js chapter check --project {书目录} --chapter {X} --fix-punctuation --plain`，复核动作碎句、空景摆设与零阻力过场；删旁白点评句须留口语转折免缩成碎句。硬伤清零，`review_required` 改净或附 `--ack <rule-id>:<理由>`；欠字不补、超字净删一次，仍超请作者选；篇幅变化明显时明说。
4. 核对人物、伏笔、物件流转、数值账目与时间线无冲突；外部事实不明先查证。

### Step 4：追踪级联更新与提交

用一次 `mode=revision` 事务（报错才读 `tracking-protocol.md`）：

1. 跑 `node {skill 根}/scripts/tracking_commit.js draft --project {书目录} --chapter {X}`，对照新正文保留有效项、修正推翻项。
2. 逐项重算受影响伏笔（到最新章 M）、时间线（删标 `action=delete`）与核心角色截至 M 章快照；X ≤ `imported_through_chapter` 自动生覆盖记录；连改多章时全局约束改写与退役集中放最后改完的章 M，免反复退役撑大体积。
3. 跑 `node {skill 根}/scripts/storyctl.js chapter commit --project {书目录} --chapter {X} --input {书目录}/.story/work/第{XXX}章/tracking.json`（字数带外给 `1. 按现长度收下 / 2. 再调整 / 3. 退回原稿`，选 1 用 `accept-current-length` 或 `--ack length:<理由>`，不到目标一半坚持才加 `--force`）。
4. 跑 `tracking_commit.js check --project {书目录}` 确认干净，并扫后续章看是否受影响。

### Step 5：向作者汇报（白话，不带代码块围栏）

<!-- author-report -->
```md
第{X}章《{章名}》改好了，原稿留着，想退回随时说：
- {改了什么：原来怎样 → 现在怎样}
{篇幅变化明显时补一句字数变化；无明显变化就删}
{后面章受影响时：「第{X+1}章《{章名}》里{某设定/情节}还按旧说法，要一起改吗？1. 一起改（推荐）2. 先不动」；不受影响写「后面的章不受影响」}
```

连续改多章时逐章走 Step 1–5。
