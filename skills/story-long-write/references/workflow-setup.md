# workflow-setup.md：开书与规划的时刻表，以及「定方向」「定设定」

> 谁读：主会话定方向、定设定时整份读；「Phase 2」与题材定位、全书梗概、关系三份模板进 story-architect 定设定任务包。

开书是一串作者要确认的时刻，每个时刻只读自己的文件；后一时刻只靠落盘文件接上前一时刻，不靠对话记忆。先按 SKILL.md「写作流程」确定交付范围；只讨论时取所需技法，不执行建档；其余按范围补必要前置，不重做已有设定。

| 时刻 | 作者确认什么 | 落盘 |
|---|---|---|
| 定方向 | 题材、卖点、对标书 | 书目录与 `.active-book`；`设定/题材定位.md` 的基本信息、对标登记、作者已定 |
| 定设定 | 主角、世界、核心冲突、全书大概怎么走 | 题材定位补全；全书梗概；关系；主角与关键角色卡；影响全书的世界观（见 Phase 2） |
| 出卷纲 | 全书分段与第一卷 | `大纲/大纲.md`、`大纲/卷纲_第X卷.md` |
| 出细纲 | 前 10 章怎么走 | `大纲/细纲_第XXX章.md`、排纲笔记 |
| 看第 1 章 | 正文 | `正文/` |

**交接只靠落盘**：每个时刻交付前，把作者在对话里定下的事（方向、偏好、红线、否掉的方案）写进 `设定/题材定位.md` 的对应小节，再往下走；下一时刻不回翻对话。本书的事只落设定，作者跨书通用的写作习惯才走作者记忆。
**换上下文**：定方向由主会话和作者商量；定设定、卷纲与每批细纲要读的方法最多，已部署 story-architect 时交给它按任务包在新上下文里出（调用见 [agent-calls.md](agent-calls.md)），主会话把提案拿给作者确认、按作者意见改文件、汇报。无子代理时由主会话按同一确认顺序完成。没有子代理时每个时刻交付后、有子代理时细纲交付后，汇报最后一句建议「新开一个对话，说『定设定』/『出卷纲』/『出第1-10章细纲』/『写第1章』，会更专注」；作者要在本对话继续也照做。

## Phase 1：确认选题方向

**作者已给方向时**：以作者的方向为准，跳过选题决策查找与下面的方向提问，只按题材读下方匹配文件，再做「对标上下文加载」。

**先查选题决策**（作者没给方向时）：项目根有 `选题决策.md`（story-long-scan Phase 5 产出）就读，取排在最前的推荐选题问用户：「扫榜建议写 X（能爆的原因 Y，差异化 Z），按这个开书？」`扫榜日期` 距今较久时提示可能过期、建议复扫。认可 → 带其题材/卖点/差异化进入 Phase 2；文件里没有「推荐选题」→ 走下面的常规提问。
缺失时先找：从项目根及其上一级起向下最多 3 层搜 `选题决策.md`（跳过隐藏目录），取最新 2 份。搜到 → AskUserQuestion 列候选（路径＋`扫榜日期`，另加「我自己给路径」「都不用」），选中或用户给的路径复制到项目根再读；「都不用」走常规提问。搜不到 → 问一句：「之前扫过榜、有现成的选题建议吗？有的话告诉我放在哪；没有就直接答下面的问题。」仍无 → 常规提问。

如果用户没有方向：

问用户：**「你想让读者什么感觉？有没有喜欢的书想对标？」**

### 对标上下文加载

> **对标书路径查找** 见 SKILL.md「路径与术语约定」。对标资料齐不齐、缺了怎么办，只在 [benchmark-recall.md](benchmark-recall.md) 定义，这里只管发现、选择、登记和复制。

**对标发现（先于下方反应式加载）**：无论用户是否点名对标书，先扫 `拆文库/` 按题材主动推荐，不要被动等用户开口。

1. `ls 拆文库/`（数据源）与项目 `对标/`（引用视图）列已有书目；先按当前项目目录名、`.active-book` 和 `设定/题材定位.md` 中的本书信息识别当前作品，排除同名或来源指向当前正文的 `拆文库/{当前书}/`。story-import 为重建工程生成的本书拆文分析不是对标候选，也不得复制回 `对标/`。排除后都为空 → 跳到第 4 条。
2. 逐本读题材（短篇读 `拆文库/{书}/_meta.json` 的 `genre_detected`；长篇读 `概要.md` 头部或 `拆文报告.md`「基本信息」的「题材」），与本书题材/方向比对，标 同题材 / 弱相关 / 不相关。挑选标准：同平台、同题材、同类型，选精品到万订之间、套路框架易懂、题材经过市场验证的中层样本；三不选——强品牌强粉丝的头部作品（品牌和笔力遮住结构，功能位没法直接复用）、刚火题材的跟风书、个人风格极强的书。融合多本时只复用功能位，不复用具体桥段。
3. 有同题材或弱相关候选 → 用 AskUserQuestion 推荐（列候选书 +「都不用」+「另拆一本」），主对标 1 本走文风/正文、其余作副对标。选定后写入 `设定/题材定位.md`「对标登记」的 `主对标书` / `对标书列表`（定方向交付时落盘），并在首次引用时从 `拆文库/{书}/` 复制相关子目录（章节/角色/剧情/设定）、`剧情/节奏.md`、`剧情/情绪模块.md`、`文风.md` 和 `拆文报告.md` 到 `对标/{书}/`，已有不重复复制。作者选「都不用」→ 在「对标登记」写「主对标书：无」（照这几个字写，写正文的脚本按它认），之后写作不再从 `拆文库/` 里别的书取对标。
4. 无候选 → 无对标继续（卷纲按常见的八步结构自排，见 workflow-volume.md），「对标登记」同样写「主对标书：无」；用户想对标可先 `/story-long-analyze` 拆一本。

已有 `对标/` 目录时，按第 1 条同一口径排除本书（老导入项目可能留着误建的自对标目录），没有外部对标书就按无对标继续，有就照 benchmark-recall.md 读。

根据回答按 SKILL.md「写前必读」总表「定方向」一行各读一次（脑洞、同人、模拟算特殊题材）。

### 定方向交付前

还没有书目录时，用作者给的书名（没有就起暂定名，定设定时可改）建 `{书名}/`，作者指定了位置就放那里，并在工作区根写 `.active-book` 指向它；书名改了，目录与 `.active-book` 一起改。然后建 `设定/题材定位.md`，把选定的题材、卖点、对标，以及作者在对话里说过的偏好、红线和否掉的方案，写进「基本信息」「对标登记」「作者已定」（模板见文末），其余小节留到定设定补。

### Agent 调用：story-architect

轻量题材定位优先由主会话完成；复杂世界观、多线结构、强反转工程或用户明确要求时才调用，调用方式见 [agent-calls.md](agent-calls.md)；agent 不可用则主会话直接执行。

## Phase 2：核心设定

开头先看 `.active-book`：上一时刻漏建就按「定方向交付前」补建。从 Phase 1 确定的目标情绪出发，在题材框架中找到对应的剧情模式，从对标书提取可复用模块（把具体角色看成功能位），用用户自己的角色和设定填充。已部署 story-architect 时只走 `--task world` 任务包（调用见 agent-calls.md）；作者明确要细化某个角色时才另派 character-designer。

完整开书时定设定交付这几样（仅规划时只落与所请求结构有关的已定设定），模板见文末：
- `设定/题材定位.md`：在定方向已写的基础上补「核心设定」（主角、世界观骨架、核心冲突与最大阻碍）、读者期待、后面才揭开或用上的东西（开书填一次，之后排卷纲只对照）、核心梗三分法与对标分析（表保留 2-3 行摘要，详见 `对标/`），不删作者已定；
- `设定/全书梗概.md`：用讲故事的话写主角最终要什么、最大的阻碍是什么、前几次大转折；结局没想好可以空着，长篇写到中途再定也行；
- `设定/关系.md`；
- 主角与关键角色的 `设定/角色/{名}.md`（character-basics.md 主角卡/配角卡）；其余角色出细纲时增量补；
- 影响全书的 `设定/世界观/{主题}.md`（力量体系、社会结构等一题一文件，题材定位只留骨架一句）。
- `设定/题材正文提示卡.md` 开书时不建，写第 1 章前由写前召回生成。
- 对标登记 ≥2 本时，副对标的锚点写进「对标分析」表附录。

**数值先问作者**：物价与收入量级、境界/力量档位、金手指上限这类影响全书的刻度，按 SKILL.md「新增物三级」属问作者——在提案里给 1-2 个候选请作者定，确认后才写进设定，不直接写死、只在汇报里概括。

## 定设定时建的文件模板

作者会打开的设定、大纲、细纲和开书总览只写故事和设定本身，不写检查结果、流程说明、本轮停点或「不写正文」这类工作记录，也不用排纲时的行话（锚点、卷尺度、量级、里程碑、接口、增量、定案、单元因果之类），用故事里的话说；这些放在汇报里说。
