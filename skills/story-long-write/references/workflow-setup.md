# workflow-setup.md：开书与规划的时刻表，以及「定方向」「定设定」

> 谁读：主会话定方向、定设定时整份读；「Phase 2」与题材定位、全书梗概、关系三份模板进 story-architect 定设定任务包。

开书是一串作者要确认的时刻，每个时刻只读自己的文件；后一时刻只靠落盘文件接上前一时刻，不靠对话记忆。先按 SKILL.md「写作流程」确定交付范围；只讨论时取所需技法，不执行建档；其余按范围补必要前置，不重做已有设定。

| 时刻 | 作者确认什么 | 落盘 |
|---|---|---|
| 定方向 | 题材、卖点、对标书 | 书目录与 `.active-book`；`设定/题材定位.md` 的基本信息、对标登记、作者已定 |
| 定设定 | 主角、世界、核心冲突、全书大概怎么走 | 题材定位补全；全书梗概；关系；主角与关键角色卡；影响全书的世界观（见 Phase 2） |
| 出卷纲 | 全书分段与第一卷 | `大纲/大纲.md`、`大纲/卷纲_第X卷.md` |
| 出细纲 | 前 10 章怎么走 | `大纲/细纲_第XXX章.md`、排纲笔记 |
| 看第 1 章 | 正文 | `正文/` |

**交接只靠落盘**：每个时刻交付前，把作者在对话里定下的事（方向、偏好、红线、否掉的方案）写进 `设定/题材定位.md` 的对应小节，再往下走；下一时刻不回翻对话。本书的事只落设定，作者跨书通用的写作习惯才走作者记忆。
**换上下文**：定方向由主会话和作者商量；定设定、卷纲与每批细纲要读的方法最多，已部署 story-architect 时交给它按任务包在新上下文里出（调用见 [agent-calls.md](agent-calls.md)），主会话把提案拿给作者确认、按作者意见改文件、汇报。无子代理时由主会话按同一确认顺序完成。没有子代理时每个时刻交付后、有子代理时细纲交付后，汇报最后一句建议「新开一个对话，说『定设定』/『出卷纲』/『出第1-10章细纲』/『写第1章』，会更专注」；作者要在本对话继续也照做。

## Phase 1：确认选题方向

**作者已给方向时**：以作者方向为准，跳过选题决策查找与方向提问，按题材读匹配文件后做「对标上下文加载」。

**先查选题决策**（作者没给方向时）：项目根有 `选题决策.md`（`story-long-scan` Phase 5 产出）就读「推荐选题」，取排首位的选题问用户：「扫榜建议写 X（能爆的原因 Y，差异化 Z），按这个开书？」（`扫榜日期` 较久时提示可复扫）。认可 → 进入 Phase 2；没有「推荐选题」或文件缺失时，从项目根及上一级向下最多 3 层搜 `选题决策.md`（跳过隐藏目录，取最新 2 份），搜到用 AskUserQuestion 列候选，搜不到问一句是否有现成选题建议，仍无则直接问：**「你想让读者什么感觉？有没有喜欢的书想对标？」**

### 对标上下文加载

> 对标书路径查找见 SKILL.md「路径与术语约定」；对标资料齐不齐与缺口处理见 [benchmark-recall.md](benchmark-recall.md)。

**对标发现**：无论用户是否点名对标书，先扫 `拆文库/` 按题材主动推荐：

1. 列 `ls 拆文库/` 与项目 `对标/`，排除同名或来源指向当前正文的 `拆文库/{当前书}/`（story-import 生成的本书拆文不是对标候选，不得复制回 `对标/`）。排除后为空 → 跳到第 4 条。
2. 逐本读题材（短篇读 `_meta.json` 的 `genre_detected`；长篇读 `概要.md` 或 `拆文报告.md`「基本信息」的「题材」），标 同题材 / 弱相关 / 不相关。选同平台同题材、框架易懂的中层样本；不选强品牌头部书、刚火跟风书、个人风格极强的书。多本融合只复用功能位。
3. 有候选 → AskUserQuestion 推荐（列候选 +「都不用」+「另拆一本」），主对标 1 本走文风/正文、其余作副对标。选定后写入 `设定/题材定位.md`「对标登记」，首次引用时从 `拆文库/{书}/` 复制章节/角色/剧情/设定、`剧情/节奏.md`、`剧情/情绪模块.md`、`文风.md` 和 `拆文报告.md` 到 `对标/{书}/`。选「都不用」→ 在「对标登记」写「主对标书：无」。
4. 无候选 → 无对标继续，「对标登记」写「主对标书：无」；想对标可先 `/story-long-analyze` 拆一本。

根据回答按 SKILL.md「写前必读」总表「定方向」一行各读一次（脑洞、同人、模拟算特殊题材）。

### 定方向交付前

还没有书目录时建 `{书名}/` 并在工作区根写 `.active-book` 指向它；建 `设定/题材定位.md`，把题材、卖点、对标及作者说过的偏好、红线、否掉的方案写进「基本信息」「对标登记」「作者已定」，其余留到定设定补。

### Agent 调用：story-architect

轻量题材定位主会话完成；复杂世界观、多线结构、强反转或用户明确要求时按 [agent-calls.md](agent-calls.md) 调用。

## Phase 2：核心设定

先核对 `.active-book`（漏建按「定方向交付前」补建）。已部署 story-architect 时走 `--task world` 任务包（见 agent-calls.md）；作者明确要细化某角色时另派 character-designer。

定设定交付（仅规划时只落与所请求结构有关的设定，模板见文末）：
- `设定/题材定位.md`：补「核心设定」「读者期待」「后面才揭开或用上的东西」「这本书靠什么吸引人」「对标分析」（对标 ≥2 本时副对标锚点写进表附录），不删「作者已定」；
- `设定/全书梗概.md`、`设定/关系.md`；
- 主角与关键角色的 `设定/角色/{名}.md`（其余角色出细纲时增量补）；
- 影响全书的 `设定/世界观/{主题}.md`（一题一文件；`设定/题材正文提示卡.md` 写第 1 章前才生成）。

**数值先问作者**：物价、收入、力量档位、金手指上限这类全书刻度，按 SKILL.md「新增物三级」属问作者，只给 1-2 个候选请作者定。

## 定设定时建的文件模板

作者会打开的设定、大纲、细纲和开书总览只写故事和设定本身，不写检查结果、流程说明、本轮停点或「不写正文」这类工作记录，也不用排纲时的行话（锚点、卷尺度、量级、里程碑、接口、增量、定案、单元因果之类），用故事里的话说；这些放在汇报里说。
