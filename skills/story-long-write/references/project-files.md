# 项目文件与产物协议

> 谁读：主会话缺文件要修、或要找某类产物放哪时读。

#### 项目文件结构

需落盘时在用户指定目录按下表组织；只讨论不建工程，仅规划只创建本次产物所需目录，不为凑齐目录树生成正文或追踪：

```
{书名}/
├── 设定/
│   ├── 世界观/
│   │   ├── 背景设定.md        # 时代背景、地理、历史
│   │   ├── 力量体系.md        # 修炼/能力/等级体系
│   │   └── ...
│   ├── 角色/
│   │   ├── 沈栀.md            # 每个人物一个文件，文件名用角色名
│   │   └── ...
│   ├── 势力/
│   │   ├── 天机阁.md          # 每个势力/组织一个文件
│   │   └── ...
│   ├── 关系.md                # 角色关系映射
│   ├── 题材定位.md            # 题材核心梗+读者期待+对标+后面才揭开或用上的东西
│   ├── 全书梗概.md            # 主角最终要什么、最大阻碍、前几次大转折、结局设想（可空）
│   ├── 文风.md                # 本书自定义文风（可选，导入时作者同意才建）
│   └── 题材正文提示卡.md       # 题材正文核心：边界/期待/爽点/节奏/禁漂移
├── 大纲/
│   ├── 大纲.md                # 全书卷级结构
│   ├── 卷纲_第一卷.md         # 每卷一个：读者期待+故事线+各段剧情+情绪弧线+人物弧线+伏笔+反转
│   └── 细纲_第001章.md        # 每章一个：七个必填字段+四个小节+结尾设定和钩子
├── 正文/
│   ├── 第001章_章名.md
│   └── ...
├── 对标/                          ← 拆文产出的结构化资产
│   └── {对标书名}/
│       ├── 原文/第001章_章名.md
│       ├── 章节/第K章_摘要.md
│       ├── 角色/                  ← 从拆文库/结构化输出同步
│       │   └── {角色名}.md
│       ├── 剧情/                  ← 从拆文库/结构化输出同步
│       │   ├── {剧情单元名}.md
│       │   ├── 故事线.md
│       │   ├── 节奏.md             # 关键信息推进 + 情绪触动点 + 爆发节奏（权威节奏索引）
│       │   └── 情绪模块.md         # 读者需求/情绪引擎 + 可复现模块（权威模块索引）
│       ├── 设定/                  ← 从拆文库/结构化输出同步
│       │   ├── 世界观/{主题}.md
│       │   └── 势力/{势力名}.md
│       ├── 文风.md
│       └── 拆文报告.md
├── 追踪/
│   ├── _tracking-state.json        ← 唯一结构化权威状态
│   ├── 上下文.md                  ← 派生续写状态卡（固定 7 栏）
│   ├── 逐章记录/第NNN章.md          ← 未来相关紧凑记录
│   ├── 角色状态/{角色名}.md         ← 派生核心角色当前快照
│   ├── 伏笔.md                    ← 派生伏笔当前视图
│   └── 时间线/{作者真相.md,读者已知.md}
├── 参考资料/
│   └── {topic}.md             # story-researcher 输出的研究资料
├── .story/排纲笔记/L1-01.md    ← 每段剧情一份排纲自用底稿：写纲前查缺+写纲时补的（作者不用读；老书在 大纲/排纲笔记_ 或 排纲底稿_）
├── .story/work/第NNN章/        ← 本章临时文件（分组 segment、prompt 留档、事务 JSON），提交后自动删除
```

**产物映射表**（创建模板详见 [references/artifact-protocols.md](artifact-protocols.md)；`追踪/` 下各文件的体积上限见 tracking-transaction.md）：

| 文件 | 粒度 | 创建阶段 | 读取时机 |
|------|------|---------|---------|
| 设定/关系.md | 全书 | Phase 2 | 按需：story-explorer relationship 查询、story-review 查设定（不在每章写作回路里逐章读） |
| 设定/题材定位.md（含 `主对标书` 字段，多对标时必填） | 全书 | Phase 1 建，Phase 2 补全 | Phase 3 大纲、每卷开始前、Phase 4 写前召回 |
| 设定/全书梗概.md | 全书 | Phase 2 | Phase 3 分卷、每卷开始前；写到中途方向变了就改它 |
| 设定/题材正文提示卡.md | 全书/题材 | 见 `genre-prose-cards.md`「全书题材正文提示卡」 | Phase 4 每章写作前 |
| 设定/角色/{角色名}.md、设定/势力/{名}.md | 角色/势力 | Phase 2 建主角与关键角色；Phase 3 细纲后增量补全 | Phase 4 状态筛选/写作 |
| 设定/文风.md（自定义文风，可选） | 本书 | 导入时作者同意才建，或作者自写；导入/拆解不覆盖 | Phase 4 每章写作前；没有就按当前请求与对标文风 |
| 对标/{书名}/文风.md | 对标书 | analyze Stage 6 输出 → story-import 显式绑定或本 skill 首次引用时同步 | Phase 4 每章写作前（文风召回；有自定义文风时降为参考/句长兜底） |
| 大纲/卷纲_第X卷.md | 卷 | Phase 3 | **一律走取段器 `outline_view.py --chapter/--unit/--contract/--toc`，不整读**（见「路径与术语约定」）；标题末尾注释与 `--check` 见 artifact-protocols.md |
| .story/排纲笔记/{剧情段编号}.md（老书在 大纲/排纲笔记_ 或 排纲底稿_） | 一段剧情 | Phase 3；正文「细纲没给」追加进「写纲时补的」 | 只在排纲/补纲时读 |
| 追踪/_tracking-state.json | 全书 | 首次写正文前初始化（规划阶段不建） | 唯一结构化权威，不进正文 prompt；每章运行 `tracking_commit.py check` 读取章号和修订号 |
| 追踪/伏笔.md | 全书当前视图 | 与 state 同时初始化 | 续写状态卡缺项时按 ID 定点查询；每 ID 只一行 |
| 追踪/时间线/{作者真相.md,读者已知.md} | 全书当前事实/认知派生视图 | 与 state 同时初始化 | 按作者真相或读者认知的实际问题选择视图 |
| 对标/{书名}/拆文报告.md | 对标书 | 用户手动+analyze | Phase 2 核心设定、Phase 3 大纲、Phase 4 写作 |
| 追踪/逐章记录/第NNN章.md | 章 | Phase 4 每章事务 | 日更默认不整读，查历史原因时定点读取 |
| 追踪/上下文.md（续写状态卡） | 全书当前状态 | 与 state 同时初始化 | 日更每章整份读；由事务工具整份重建，固定 7 栏 |
| 参考资料/{topic}.md | 按需 | Phase 4（story-researcher 输出） | Phase 4 后续章节写作时复用 |
| 追踪/角色状态/{角色名}.md | 核心角色 | 首次进入正文或导入初始化 | 久别角色按名读取一个小快照；静态人设仍读 `设定/角色/` |
| 对标/{书名}/角色/{角色名}.md | 对标书 | analyze 输出 | Phase 4 模块召回（角色参考） |
| 对标/{书名}/剧情/{剧情单元名}.md | 对标书 | analyze 输出 | Phase 3 卷纲选段与细纲成批（剧情段的「参考对标书哪段剧情」）、Phase 4 模块召回（剧情模块参考） |
| 对标/{书名}/剧情/情绪模块.md | 对标书 | analyze Stage 3 输出 → story-import 显式绑定或本 skill 首次引用时同步 | Phase 2 核心设定、Phase 3 大纲、Phase 4 每章写作前（读者需求 / 情绪引擎、可复现模块选择） |
| 对标/{书名}/剧情/节奏.md | 对标书 | analyze Stage 3 输出 → story-import 显式绑定或本 skill 首次引用时同步 | Phase 3 大纲、Phase 4 每章写作前（关键信息推进、情绪触动点、爆发节奏参考） |
| 对标/{书名}/设定/*.md | 对标书 | analyze 输出 | Phase 2 设定参考、Phase 4 世界观约束 |

对标资料缺了怎么办、各份对标资料谁说了算，只在 benchmark-recall.md 定义；追踪文件缺失或损坏按 tracking-transaction.md 先跑 `tracking_commit.py check` 再用事务修复，卷纲里的计划不能代替已发生的事实。

**文件组织原则：**
- **人物一个一个文件**：`角色/角色名.md`，方便按需读取
- **势力一个一个文件**：`势力/势力名.md`，组织/门派/家族/国家等
- **世界观按主题拆分**：背景、力量体系、社会结构等各自独立
- **细纲一章一个文件**：`细纲_第XXX章.md`，含钩子设计，与正文一一对应
- **正文按章拆分**：每章一个文件，`第XXX章_章名.md`
- 每章写完直接写入 `正文/` 目录，不要先输出到对话

`/story-long-analyze` 产出在 `拆文库/`，首次引用时同步到项目 `对标/`。
