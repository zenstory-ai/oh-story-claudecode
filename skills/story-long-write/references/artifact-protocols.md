# 产物创建模板

各产物的标准模板与创建指引。agent 在 Phase 2-3 过渡时按需加载此文件。

**模板列表：**
- 设定/关系.md
- 设定/题材定位.md（含读者契约 + 终局底牌/升级台阶 + 对标登记字段）
- 大纲/大纲.md（全书鸟瞰 + 全书体量与阶段总览）
- 大纲/卷纲_第X卷.md（含卷契约+终局储备+剧情单元+情绪弧线+反转规划）
- 追踪/_tracking-state.json（唯一结构化权威状态）
- 追踪/逐章记录/第NNN章.md（未来相关紧凑增量）
- 追踪/伏笔.md
- 追踪/时间线/作者真相.md + 读者已知.md（派生视图）
- 追踪/角色状态/{角色名}.md
- 追踪/上下文.md（续写状态卡，固定 7 栏）
- 对标/{对标书名}/全局分析/*.md + structure_blocks.csv + chapter_index.csv
- 对标/{对标书名}/原文/第XXX章_{章名}.md

**层级关系（全书 › 卷 › 剧情单元 › 章 › 情节点；故事线横向贯穿多个剧情单元）：**
- 大纲.md = 全书鸟瞰（每卷一两句话定位）
- 卷纲_第X卷.md = 单卷规划（剧情单元+情绪+人物+伏笔+反转）
- 细纲_第XXX章.md = 单章蓝图（单元ID/位置 + 主角目标/关键选择 + 内容概括 + 多线情节安排 + 人物关系/出场顺序 + 情节细化 + 结尾设定/钩子）

**概念对照（统一叫法，减少混淆）：**
- **剧情单元** = 一段完整剧情（1.5-3 万字/数章，一个机制从触发到兑现）。拆书侧先由 `爆款机制.md` + `六维拆书.md` 的“三维节奏”章节 + `structure_blocks.csv` 选语义范围，再由五列 `chapter_index.csv` 定位原文；本书侧落成卷纲里的**剧情单元卡**。
- **故事线** = 贯穿多个剧情单元的线；对标拆书侧从 `六维拆书.md` 的“双时间线与信息差”章节读取，不再依赖单独的逐章剧情文件。
- 「循环」一词只在**节奏义**保留（爽点循环、升级循环、小/中/大循环等），不再指代规划单元。

## 对标/{对标书名}/全局分析/*.md + structure_blocks.csv + chapter_index.csv

> **拆文库/对标关系**：`拆文库/` = analyze skill 的原始产出（数据源）。`对标/` = 写作项目的引用视图。首次引用时从 `拆文库/` 复制到 `对标/`。

这些文件由 `story-long-analyze` 的 JSON checkpoint schema v4、分析契约 v5.0 输出。write skill 的职责是读取三个全局文件和结构块，再用五列 `chapter_index.csv` 把候选章号映射为 `source_locator` 并回读原文；索引本身不参与语义选择，也不创建兼容版逐章摘要。

完整契约：`六维拆书.md`（含人物关系图谱、双时间线与信息差、三维节奏）、`爆款机制.md`、`证据与边界.md`、`structure_blocks.csv`、五列 `chapter_index.csv` 与可回读的 `原文/`。缺机制、六维中的必要章节、结构块、索引或原文时 fail-fast，不能用手写简版摘要顶替。

如需给人看的派生概览，可写在项目笔记中，但不得作为召回权威：

```markdown

- 作者：{}
- 题材/类型：{}
- 目标平台：{}
- 成绩：{均订/在读/热度}

## 核心发现（附权威来源 ID）
```

## 大纲/细纲_第XXX章.md

细纲是正文写作的章节蓝图，而不是只列事件和钩子的清单。**模板唯一权威副本**见 [Phase 3：大纲搭建](workflow-setup.md#phase-3大纲搭建) 的「细纲（全书每章）」模板（含单元ID/位置、主角目标/关键选择、任务卡点、结构公式、契约风险行，以及不含逐点字数的情节点表格）；本文件不再保留模板副本。新建、补建、回填都按权威模板补齐，未知字段写 `[待补充]`，不为补齐字段杜撰副线或人物关系。

`目标情绪` 与 `主角目标/关键选择` 要写实际内容，不能留 `[待补充]`：隔离实验里只补这两个字段就能复现补齐全部字段的正文收益，补满其余字段与只补这两个不可区分。其余字段未知时仍按上文写 `[待补充]`。

落盘后运行 `node scripts/check-outline-contract.js --json --project {书目录} --chapter {N}` 做结构验收：它只判字段、四个小节、五段式、四列情节点表和字数目标口径是否在场，不判内容好坏。exit 1 时只按 `repair_scope` 补报告点名的字段并复验，最多两轮；仍失败就报告检查 ID 停下，不改其他章。exit 2、脚本缺失或 node 不可用时如实报告验收未完成，不得声称细纲已合规。本检查只在新建/补建/回填时执行；既有项目的旧细纲不因此阻断写正文。

追踪产物由 `scripts/tracking_commit.py` 统一生成，完整 schema 和事务字段见 [tracking-transaction.md](tracking-transaction.md)。以下文件不得由模型各自追加或局部 Edit：

### `追踪/_tracking-state.json`

唯一结构化权威状态。记录 schema、最后提交章、导入截止章、`state_revision`、续写上下文结构，以及全部角色、伏笔和时间线当前状态。日更通过 `tracking_commit.py check` 的紧凑输出取章号和修订号，不把完整 state 加入正文 prompt。所有 Markdown 都从本文件确定性派生，程序不反向解析 Markdown。

### `追踪/逐章记录/第NNN章.md`

本章未来相关连续性记录，目标 ≤1536 字节、硬上限 3072 字节，只含：实际结果、角色变化、伏笔变化、时间/揭示、连续性约束、下一章承诺。过程日志、质检统计、参照章和提示词记录不进入。它不承诺单独无损重建全部当前状态；完整当前语义以 `_tracking-state.json` 为准。

### `追踪/伏笔.md`

每个 ID 只保留一行当前状态：内容、埋设章、计划回收章、状态、重要度、最近变更章。变化历史由对应逐章增量承担。尚未实际埋设的未来伏笔规划留在大纲；当前表只接受 `已埋 / 已回收 / 已过期 / 放弃`。

### `追踪/角色状态/{角色名}.md`

只为核心、会复用角色建立动态快照，含截至章节、身份、位置、当前目标、身心状态、能力资源、关键关系、已知信息和未结事项。目标 ≤4096 字节、硬上限 8192 字节；超过目标先合并失效能力、旧关系和已结事项，不把角色履历塞进当前快照。静态原始人设仍在 `设定/角色/{角色名}.md`；路人、一次性角色不建动态文件。

### `追踪/时间线/`

- `_tracking-state.json.timeline`：同一事件登记故事时间、客观事实、读者当前认知、实际揭示状态/章节。
- `作者真相.md`：从 `_tracking-state.json.timeline` 派生，作者侧可见全部客观事实和认知差。
- `读者已知.md`：从 `_tracking-state.json.timeline` 派生，只显示读者已经知道/相信的内容，不泄露客观真相。

未来揭示计划写卷纲/细纲，不写进既成事实登记；`未揭示` 事件的 `reveal_chapter` 必须为空。

### `追踪/上下文.md`

续写状态卡不超过 12288 字节，固定 7 栏：`当前位置 / 长期约束 / 核心角色状态 / 活跃伏笔 / 近三章速记 / 下一章承诺 / 连贯性风险`。它是当前语义检查点之一；不放文风、质量计数、普通待办、索引统计和长期概要。
