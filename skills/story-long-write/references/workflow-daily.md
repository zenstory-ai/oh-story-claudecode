# workflow-daily.md：日更续写工作流

SKILL.md 路由到「日更续写」后按本文件控制批次；每章正文走 [workflow-chapter.md](workflow-chapter.md)。写前资料、对标路径与缺失处理按 [project-files.md](project-files.md) 与 [benchmark-recall.md](benchmark-recall.md)，本文件不另立一套。

**多本对标书**：主对标取 `设定/题材定位.md` 的 `主对标书` 字段；字段指向本书自身或缺失时，用 `对标/` 下字典序第一本（排除本书同名目录）并提示用户补字段，排除后为空按无对标处理。

---

## 适用条件

- 项目已有 `正文/` 和 `追踪/`；用户明确说"日更""续写""继续写/接着写"或指定"写第 N-M 章"；上一轮在规划时，"继续写"先按 SKILL.md「规划续接」一句话确认
- 每次会话写 2-3 章。裸调用、只规划或只改细纲不进本流程

---

## Step 1：快速上下文加载

运行 `tracking_commit.py check`，取 `last_committed_chapter + 1` 作本批首章 N、`state_revision` 作修订号，并核对 `追踪/上下文.md` 的当前位置；章号不一致先修，不扫描正文猜编号。每章要读的上下文按 workflow-chapter 步骤 2；`追踪/伏笔.md`、`时间线/`、`逐章记录/` 默认不整读，缺旧信息按下方「旧信息查找步骤」定点查。

`追踪/上下文.md` 是续写状态卡（7 栏，由 `tracking_commit.py` 派生，禁止手改）；schema、修订与修复见 [tracking-transaction.md](tracking-transaction.md)，出错时才读。

**首次初始化**：

1. `_tracking-state.json` 不存在且尚无正文：完整读取 [tracking-initialization.md](tracking-initialization.md)，构造 `last_chapter=0` 的初始化事务存 `.story/work/init.json`，执行 `tracking_commit.py init`，`check` 过后删掉。
2. 不存在但已有正文：停止日更，走 `/story-import` 的「旧追踪项目迁移」重建 `追踪/`（不用重跑全书拆解）；`init` 会把旧结构整体移入 `追踪/_旧追踪存档/`。
3. `check` 报派生视图与 state 不一致：为该章提交 `mode=revision` 事务整份重建（`expected_state_revision` 取 state 文件的 `state_revision`），不手改 Markdown、不继续下一章。

**长期约束**最多 6 条，出现第 7 条先合并语义重叠项或请作者取舍，不自动删旧约束。永久生效的设定裁定进 `long_term_constraints`，短期强承诺进 `next_chapter_commitments`，过程决策不进续写状态卡。

确定范围后直接进 Step 2，不做"是否继续"确认。K 默认 2-3 章，用户说"只写1章"/"日更3章"/"逐章确认"按用户；给出 N>3 时本轮只写前 3 章并在批末提示剩余下轮继续。只在章号冲突、细纲缺失、范围超出已有细纲、要改大纲/追踪等会写错的情况暂停确认。

## Step 2：串行批量写作

多章细纲可一次加载，但**必须在主会话内串行逐章写**，不把多章并发交给多个子代理（上下文断裂、追踪覆盖、标题去重失效）。

**批量 continuation 规则**：未改变任务时，"继续/续写/日更"仍走完整批量流程，不逐章重复确认（用户要求或阻塞除外）；用户转为只规划/改细纲时退出批量。到达本轮 K（最多 3 章）后必须进入 Step 3/4 收尾并停止，不因还有细纲续写下一批。

1. **读取写作计划**：按 卷契约 → 当前剧情单元 → 章节细纲 确定；`outline_view.py --unit {单元ID}` 取一次卷级与单元级内容，本批复用，不整读卷纲。写前明确本批推进目标、可释放与严禁提前释放的信息、章尾钩子不能越过的边界，别动用本阶段还不该解锁的终局底牌。批写完检查是否超前、拖慢或偏离阶段节奏（细节适配不算；已改变卷契约、单元承诺、推进线或兑现归属的，修正文或重规划后续细纲）：下一章要补偿的进 `next_chapter_commitments`，跨章风险进 `continuity_risks`，不靠提前泄露后期信息提速。
2. **逐章执行**：每章按 workflow-chapter「单章写作流程」步骤 1-13 走完，叠加：
   - **上一章欠账**：写本章前上一章不得有未清 blocking 毒句式（写前 hook 会拦；hook 不可用时对上一章跑一次 `chapter check`），标了 `<!-- 去味:跳过 -->` 的除外。
   - **状态来源**：不把完整 `_tracking-state.json` 读进上下文，缺的信息定点查，不用来源不明的聊天记忆替代。久别核心角色读 `追踪/角色状态/{名}.md`，重新活跃后放进本章事务的 `context.active_character_names`。
   - **用 story-explorer 召回时**：`gaps` 按 [benchmark-recall.md](benchmark-recall.md)「快捷路径」分流。
   - **写后清零不拖到批末**：hook 推回的命中当轮清零。
   - **每章写完立即提交追踪**：按 workflow-chapter 步骤 12，提交成功才进下一章；只记会影响后续章节的变化，过程日志、质检计数、去味统计不进事务。narrative-writer 不写 `追踪/`。
3. **不中断但不并发**：追踪已提交即进下一章；`under` 或一次压缩后仍带外，按 workflow-chapter 的字数问法请作者选，不静默推进。

**资料研究**（按需）：需查证外部事实时暂停，spawn `story-researcher` 输出到 `参考资料/`，完成后继续。

### 旧信息查找步骤

续写状态卡没有、但本章确实需要的旧信息，由近到远查，查到就停：

1. **定点读追踪**：伏笔 `grep -n "F007" 追踪/伏笔.md`；角色读 `追踪/角色状态/{名}.md`；读者认知读 `时间线/读者已知.md`，作者真相读 `时间线/作者真相.md`。
2. **查变化原因或历史**：调 story-explorer 的 `foreshadow_status / character_status / timeline`（不可用则 `grep -R -n --include='第*.md' "F007" 追踪/逐章记录/ | tail -5`，只取最近 5 条）。
3. **读一个原文件**：对应逐章记录或埋设章正文，只读 1 个。全量读逐章记录或正文属于 `/story-review` 或作者要求的全面审计，日更不做。

单章第 2 级超过 3 次，说明细纲没写清要消费哪些旧信息：一次性让 story-explorer 查多项，并在批末提示细纲需补清回收项。

## Step 3：质量检查

逐章检查已在 Step 2 完成，批末只做**跨章**核对：

1. **标题去重**：本轮新写章与既有标题同名或明显重复时，统一改细纲与正文文件名。
2. **契约与细纲双向核对**：按 `reader-contract-and-progression.md`「契约四问」过一遍本批（答不上来的那问再读对应小节）；正文是否消费了细纲的内容概括、情节安排、人物关系变化与收益归属；爽点前有可指认的铺垫、打脸/揭露章写了在场配角差异反应、详略按目的分配而非均匀注水。不达标回 Step 2 修批准内容。
3. **伏笔盘点（仅本轮增量）**：本批新增/推进/回收的每个 ID 在 `追踪/伏笔.md` 恰好一行当前状态，并能在对应逐章记录找到本次变化；不做全量伏笔审计。
4. **一致性检查（整批一次）**：本批各章没有按需调用过 consistency-checker 的，在这里 spawn 一次，检查范围写本批全部章节，prompt 同 workflow-chapter「Agent 调用：consistency-checker」（申报栏写各章申报汇总）；各章都已单独查过就跳过。冲突照该节处置表处理。

只对本步改过的章重跑 `chapter check --fix-punctuation`，没改过的不再整批复扫。本步修文若改变了会影响后续的事实、状态、伏笔或承诺，进入 Step 4 前为受影响章节提交 `mode=revision` 事务并通过 `check`（`delta` 重算修订后该章仍成立的完整记录）；纯措辞调整不重复提交。

---

## Step 4：批末收尾

**本步不再写追踪内容**，只做：

1. `tracking_commit.py check` 通过（state、逐章记录连续与体积、7 栏、派生视图一致）；本批每章都有 `追踪/逐章记录/第NNN章.md`。缺失或超限回到该章事务修正重跑，不手补文件。
2. **「本章没写成的」汇集**：各章申报表末行只分两路——「细纲没给」进下一批排纲的供给自查（workflow-setup「排纲自查与细纲」步骤 3）作扩产候选，涉及既有设定的先查设定、有既定值补进下一章 prompt；「要先问作者」并入 workflow-chapter「写了要报」处置表的「先问作者」一行。连同细纲里状态仍为 `待裁定` 的新增物，一并随批末汇报给出；全部为 `0` 记「无」。

然后按 SKILL.md「面向作者的汇报」口头汇报，不另存文件；内部核对翻成故事话再说：

<!-- author-report -->
```md
这次写了 {K} 章，共约 {总字数} 字：
- 第{N}章《{章名}》：{一句发生了什么}
- 第{N+1}章《{章名}》：{一句发生了什么}
{偏离原计划的就一句话说偏在哪、打算怎么接，如「阿福比计划早露面一章，后面照常」；没有就删掉此行}
{要作者定的事：一句问题＋白话选项＋推荐，如「沈栀要不要在下一章就知道信的下落？1. 先瞒着（推荐）2. 这章就告诉她」；没有就删掉此行}
下一批：第{M}到第{M+2}章，{细纲已备好 / 需要先补细纲}。接着写吗？
```

## 细纲缺失补建流程

1. `outline_view.py --unit {单元ID}` 取本章剧情单元卡与卷级常任；单元卡有「对标剧情参照」时加读其指向的 1 个剧情单元文件作功能参照。整个剧情单元都没细纲时，按 outline-structure-theory.md「按剧情批出细纲」整批补建。
2. 读本章涉及角色的设定与最新一章正文。
3. 按 workflow-setup.md「Phase 3：大纲搭建」的细纲模板补齐必需字段，无法确认的写 `[待补充]`，不杜撰；补完继续 Step 2。

## 常见问题

| 问题 | 处理 |
|------|------|
| 细纲不存在或缺当前蓝图字段 | 执行上方补建流程，补齐前不写正文 |
| 用户要求改大纲 | 提醒会影响后续细纲，确认后修改并标记受影响的细纲 |
| 写到卷末 | 提示「当前卷已完成，是否开新卷？」 |
| 用户中断批量写作 | 已提交的章保留，下次从断点继续 |
