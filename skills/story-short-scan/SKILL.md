# story-short-scan：短篇网文扫榜

基于真实榜单样本分析短篇市场，从题材与简介提炼读者情绪体验、流派方向和验证办法。热度只在同一平台口径内比较（排名与互动量反映关注度而非故事质量）；短篇风口变化快，报告须注明样本日期、覆盖范围、可信度与复扫日期。

---

## 扫榜流程

### Phase 1：确认平台和方向

用户已给出平台或方向时直接采用（有具体方向做定向深扫，无方向做全榜概览，多平台做对比），只问缺项：**「想看哪个平台、男频还是女频、哪类短篇？点众可直接采集；黑岩要有黑岩后台账号、先登录；番茄短故事、知乎盐言和七猫短篇请发榜单截图、文字或链接。手里有编辑的征稿要求也可以一起发来。」**

---

### Phase 2：确定数据来源

| 模式 | 说明 | 何时用 |
|---|---|---|
| **脚本采集** | 点众、黑岩：抓取平台页面，产出结构化文件 | 有 Chrome 环境时（优先） |
| **作者提供** | 没有脚本的平台，或作者已有榜单 | 番茄短故事 / 知乎盐言 / 七猫短篇等 |
| **内置知识** | 用历史实证资料提出待验证选题 | 无法联网、作者也没有数据时 |

命令中的 `scripts/` 相对本 skill 根目录。

1. 只读所选平台那一份：[点众](references/platform-dianzhong.md) / [黑岩](references/platform-heiyan.md) / [没有脚本的平台](references/manual-rank-input.md)。其中有网址、命令、字段、故障排查、平台分析维度和作者榜单的整理格式。
2. 每次扫榜新建输出目录 `扫榜/{YYYYMMDD}/`（同日再扫加 `-2`）存本次榜单，不往旧目录追加（聚合会混进旧榜）。脚本自动命名文件，作者榜单按平台参考命名；某平台失败就跳过。对比时读上个日期目录的 `扫榜聚合.md`。
3. 聚合：`node scripts/aggregate-rank.js {输出目录} --out {输出目录}/扫榜聚合.md --sparse 10 --scale short`。**主会话只读这份聚合**，需要原始简介与人设信息时再抽样：`node scripts/aggregate-rank.js {输出目录} --sample {题材/标签/书名词} --n 5`。
4. 看聚合的「采集情况」：标了问题（书名没解出来、没采到、详情没取到）的榜单按平台参考排查重采；重采不了就在报告里说明结论不含它。
5. 作者发来征稿要求：原文存进输出目录的 `征稿要求.md`，题材、字数、截止日期当硬条件。

**内置知识：** 跳过聚合，加载 [references/real-market-data.md](references/real-market-data.md)，明确标注「以下分析基于历史市场实证数据；未完成实时榜单校验前只能作为候选假设。」并列出需要复扫的平台页面。

---

### Phase 3：数据分析

有真实样本时，以聚合结果和平台参考的「分析维度」为准。趋势需对比同口径的多期样本；仅用内置知识时只给待验证候选，不填写当前数量、占比或涨跌。

1. **情绪排行**：按本节末的情绪表把题材、标签归入六种写作情绪，按样本数量比较。优先根据简介判断读者读完的感受，只归一类；无简介或简介极短时结合书名冲突句式与标签归类，仍无法判断的计「待定」。悬疑题材按落点分：最后揭开真相的归反转震撼，留下寒意的归细思极恐。
2. **题材热点**：聚合的题材表和标签热词里反复出现的设定、场景，并映射至 14 个短篇流派包方向。
3. **篇幅分布**：聚合的字数分布与各题材字数中位。
4. **简介与书名写法**：抽样简介怎么前置冲突、留悬念，书名规格（区分知乎极短意象/概念名 vs 下沉平台两段式第一人称长标题）；可对照 [real-market-data](references/real-market-data.md) 的实证规律。
5. **结尾类型**：按实际可辨识结局归类（明账清算 / 火葬场追悔 / HE发糖 / 细思极恐留白 / 克制回甘 / 开放式，或简记 HE / BE / 开放式），仅在样本看得出结局时统计。
6. **人设模型**：抽样简介里反复出现的主角类型。

| 情绪 | 归入的题材与标签（对齐 14 个短篇流派） |
|---|---|
| 意难平 | 追妻火葬场、虐恋、遗憾、错过、白月光、死人文学、男频追夫、校园青春暗恋（BE/错过） |
| 反转震撼 | 悬疑、身份错位、反转 |
| 爽感释放 | 复仇打脸、世情打脸、总裁豪门、宅斗宫斗、年代重生打脸、男频都市反杀（世情/出轨/事业反杀）、仙侠奇幻末世（重生/弹幕反杀） |
| 治愈温暖 | 甜宠、校园青春暗恋（学霸/青梅竹马）、双男主（纯爱/ABO/病娇拉扯）、成长、亲情救赎 |
| 细思极恐 | 悬疑、民俗怪谈、规则怪谈、心理惊悚、异常机制 |
| 共鸣感动 | 世情打脸（原生家庭/婆媳/现实边界）、男频世情情感、现实职场、婚姻家庭、克制回甘 |

> 脑洞设定流（弹幕/恶毒女配对照组/系统/读心/穿书）按落点归入「反转震撼」或「爽感释放」；仙侠奇幻末世按基调归入「爽感释放」或「治愈温暖」；其余未列题材按实际情绪归入上表六类（无法归类计「待定」），流派映射兜底用「通用短篇」。

### Phase 4：输出扫榜报告

报告讲市场结论和能写的方向。脚本名、命令和采集状态不进报告；未采到的平台用一句话说明原因。模板中缺数据的项直接省略；单期样本不写「变化」一节，历史资料不填当前数量和热度。点众、黑岩采的是在架书目，并非热度榜：只有它们的数据时，「榜上数量」写「在架数量」，热度中位一列点众写「评分中位」、黑岩省略，不说哪篇火。

报告展示给作者，同时写进输出目录的 `短篇扫榜结论.md`：文件不存在就先按 [references/topic-match.md](references/topic-match.md) 的模板写文件头，再把报告作为「扫榜结论」一节写入（已存在就整节替换）。

### Phase 5：选题匹配

先读 `短篇扫榜结论.md` 的「扫榜结论」及同目录 `扫榜聚合.md` 和 `征稿要求.md`（有的话）；内置知识模式没有聚合表，只读历史候选。

作者未提供的信息集中问一句：**「打算投哪个平台（还是自己发）？手里有什么素材、擅长写什么？计划写多少字？」** 作者不想答就按样本给方向，可行性最高写「中」。

按 [references/topic-match.md](references/topic-match.md) 写进同一文件的「选题匹配」一节。优先选样本信号明确、作者素材和条件撑得住的方向。
