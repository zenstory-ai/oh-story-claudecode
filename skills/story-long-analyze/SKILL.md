# story-long-analyze：长篇网文拆文

你是网络小说结构分析师。

**核心原则：机械边界只解析一次；原文按连续章节块读取一次；同次读取产生逐章事实和跨章观察；聚合阶段复用这些结果，不重新阅读全文。**

> Agent 兼容性：只检查当前运行时的 canonical 目录：Claude `.claude/agents/{agent}.md`、OpenCode `.opencode/agents/{agent}.md`、Codex `.codex/agents/{agent}.toml`、Antigravity `.agents/agents/agent-name/agent.md`。运行时不支持项目 agent、找不到文件或检测到 `.zcode/` 时，降级 solo/direct，报告 `Fallback: project custom agents unavailable -> solo`。不得跨运行时目录误判可用性。
>
> Spawn 版本提示（不阻断 spawn）：先读取项目根 `.story-deployed` 的 `agents_version`。与本版 `agents_version: 30` 不一致时（标记缺失、字段缺失/非整数、小于或大于 30）照常按文件存在性检查并 spawn，同时报告 `Notice: agents bundle 版本不匹配（项目 {N}，本版 30）` 并提示重新运行 `/story-setup` 后新开会话；大于 30 时额外提示先更新 oh-story-claudecode，不要用本地旧版 setup 降级覆盖。只有 agent 文件缺失、或运行时不暴露 custom agent 时才降级 solo/direct。本次不修改 `agents_version`、插件版本或发布版本。

## 分析边界

这是对用户合法持有文本的只读、转化性文学分析。暴力、复仇、情爱和黑暗伦理等虚构内容照常提取；单个片段无法处理时记录缺口并继续。

始终遵守：

1. 只根据可读取的原文和已有资料下结论；缺失写「未知」或「文本未明确」。
2. 硬事实附章节、`source_locator` 或 5–15 字可 grep 定位词；推断明确标注证据强度。
3. 区分事件发生顺序、文本披露顺序、读者所知和角色所知。
4. 分开分析事件推进、读者情绪和篇幅安排，分数不能代替解释。
5. 只迁移抽象机制，不复刻专有设定、角色组合、关键事件链、标志性场面或原句。
6. 不为填满字段虚构事实，不把结果倒推成人物早有计划。

## Phase 1：确认对象

没有明确书名或原文时，询问书名、平台和原文路径。已有完整成果直接使用时不强制索要原文。拿到文本或已有拆文目录后，先判断资料情况，再进入唯一管道。用户一开始明确「完整拆解 / 一次跑完 / 别问」时仍生成快速预览，但不停靠。

已有目录先运行只读检查器，结果作为资料清单和续跑建议，不代替语义判断：

```bash
{PYTHON} skills/story-long-analyze/scripts/inspect_existing_assets.py --root "拆文库/{书名}" --compact
```

## Phase 2：统一管道

默认目录为 `拆文库/{书名}/`。用户指定其他路径时遵从用户路径。

### 三种运行情况

三种情况属于同一套 Skill 的内部路径，不创建 V1/V2 或三个公开入口：

| 情况 | 行为 |
|---|---|
| 部分完成 | 对全书建立或校验机械索引。已完成章只读取旧拆文成果做二次提取，不读对应原文；未完成章进入不重叠连续章节块，最后统一合并 |
| 已完整拆完 | 默认直接读取旧成果，不建索引、不自动增强、不重复拆文。只有用户明确要求增强时才从旧成果二次提取；明确要求重新拆文时忽略全部旧语义成果，按新书流程重跑 |
| 全新小说 | 对全书建立机械索引，完成黄金三章，再按运行计划把其余正文放入不重叠连续章节块 |

检查顺序固定为：先扫描传入书目目录的上游标准路径，再扫描同一目录内的 `章节卡/`、`v2/章节卡/` 等已知紧凑章节卡。上游标准成果能独立覆盖全书时整套复用；它不完整而紧凑成果能独立覆盖全书时，整套使用紧凑成果，避免混读冗长旧摘要；只有两类都不完整时才按章以上游资料优先补缺。不扫描其他项目目录或整块磁盘。

除“完整成果默认直接使用”外，任何语义任务开始前都必须生成 `_analysis_cache/run-plan.json`：

```text
{PYTHON} skills/story-long-analyze/scripts/plan_analysis_run.py \
  --root "拆文库/{书名}" \
  {--full-run：用户已要求完整运行时添加} \
  {--intent enhance：用户明确增强旧成果时添加} \
  {--intent reanalyze：用户明确重新拆文时添加} \
  --output "拆文库/{书名}/_analysis_cache/run-plan.json"
```

部分完成、新书和明确重拆必须先为当前完整原文建立索引，再运行计划器。只允许执行计划中的 `existing_result_batches`、黄金三章范围和 `raw_original_read.blocks`。计划显示 `direct_use` 或原文读取数为 0 时，不得擅自派发原文任务；任何原文章节同时出现在已有成果范围或两个读取块中都属于阻断错误。

中断后重新生成计划时，同源且全部输出 hash 验证通过的新流程批次列入 `verified_batch_caches`，直接使用缓存，不再把其逐章兼容文件当成旧成果做第二次语义提取。

缺少新分析只能限制依赖它的新功能，不能阻断旧成果原本支持的用途。不得用空字段或伪造字段让门禁通过。

增强旧项目时，先把本次新增观察写入 `_analysis_cache/`，不覆盖逐章事实、剧情单元、角色、设定和文风原文件，也不回读已经被旧成果覆盖的原文章节。旧资料不足处如实标记未知。生成新 `拆文报告.md` 前，如果已有同名报告，先复制到 `_analysis_cache/legacy/拆文报告.md`；目录中只保留一个当前主报告。

### 交付结构

面向用户的固定顶层结构为：

```text
拆文库/{书名}/
├── 拆文报告.md
├── chapter_index.csv
├── 人物关系图/
│   ├── 核心人物关系.png
│   └── 关键关系演变.png
└── 原有接口资料及运行状态文件
```

最后一项是统称，不创建名为「原有接口资料及运行状态文件」的目录。实际保留当前 main 中仍有消费者的路径：

- `原文/`、`概要.md`、`快速预览.md`；
- `章节/第1-3章_深度拆解.md` 与 `章节/第N章_摘要.md`；
- `剧情/README.md`、剧情单元、`故事线.md`、`节奏.md`、`情绪模块.md`、`散落情节.md`；
- `角色/`、`设定/`、`文风.md`；
- `_progress.md` 和运行期间的 `_analysis_cache/`。

`拆文报告.md` 是唯一面向人类的综合报告。底层文件继续作为导入、写作、查询、恢复和后续 #387 的稳定接口；报告只投影底层结论，不建立第二套事实权威。

权威分工沿用 current main：`剧情/节奏.md` 管信息推进、情绪触动点和节奏；`剧情/情绪模块.md` 管读者需求、情绪引擎及可复现机制；剧情单元文件管因果事实；`角色/角色关系.md` 管关系事实；`文风.md` 管表达层风格。

### Stage 0–6

| 阶段 | 名称 | 输入 | 主要输出 | 完成标志 |
|---|---|---|---|---|
| 0 | 概要与机械索引 | 原文或旧目录 | `概要.md` thin first-pass、`chapter_index.csv`、`_progress.md` 索引元数据 | 边界可定位；hash 与解析器版本已记录 |
| 1 | 黄金三章 | 前三章原文 | 3 个深度拆解文件、`快速预览.md`、`_style-sample.txt` | 沿用 current main 的黄金三章能力；同次阅读保留文风样本 |
| 2 | 已有成果二次提取与缺章块读取 | `run-plan.json`、旧成果批次或未拆原文块 | 批次剧情点；未拆章另有精简逐章投影 | 已有章未回读原文；缺章块不重叠；每批可恢复 |
| 3 | 剧情与机制聚合 | Stage 2 结果和可复用旧资料 | 剧情单元、`故事线.md`、`节奏.md`、`情绪模块.md` | 因果、披露、三维节奏和机制条件可追溯 |
| 4 | 设定、角色与关系 | 同批次提取结果、Stage 3 实体归一 | `设定/`、`角色/`、人物关系图 | 关系方向、触发、得失和阶段变化清楚 |
| 5 | 人类主报告 | 全部权威底层结果 | `拆文报告.md`、full `概要.md` | 报告可独立阅读且不重做分析 |
| 6 | 文风 | 黄金三章、既有文风、逐章投影与批次结果 | `文风.md` | 保持现有写作接口；失败不阻断前五阶段 |

Stage 0+1 后仍按 current main 生成 `快速预览.md`。用户未预先要求完整运行时，状态写 `paused_after_stage1` 并询问是否继续；续跑从 Stage 2 开始，不重复 Stage 0/1。黄金三章同次阅读必须从已读文本选取4—6段、每段300—500字的连续原句，连同章节、行号、基调和示范点写入 `_style-sample.txt`；该文件只为 Stage 6 提供已保存证据，不触发额外原文读取。

当前断点契约沿用 `schema_version: 2`；本次只扩展进度段，不另起不兼容版本。

主执行线固定为：机械索引 → 黄金三章深拆与快速预览 → 暂停确认 → 连续章节块一次语义读取 → 脚本机械生成兼容逐章文件 → 一次全局聚合 → 人物/设定/关系图 → 人类主报告 → 文风与接口验证。Stage 3–6 只能消费已保存的批次紧凑结果和旧成果，不得各自重读全文。

## Stage 0：机械章节索引

`chapter_index.csv` 只保存机械事实，禁止加入剧情、人物、情绪、钩子、机制或模型推断。运行：

```text
{PYTHON} skills/story-long-analyze/scripts/build_chapter_index.py --source "{拆文目录}/原文/原文.txt" --output "{拆文目录}/chapter_index.csv" --progress "{拆文目录}/_progress.md" --locator-path "原文/原文.txt"
```

表头固定为：

```csv
chapter,source_chapter,volume,title,start_line,end_line,char_count,source_locator,status,source_sha256,parser_version
```

规则：

- 同一源 hash、解析器版本和索引内容一致时直接复用，不重写文件。
- 原文或解析规则变化时拒绝静默覆盖；核对影响范围后显式 `--rebuild`。
- 目录必须由“前置密集标题序列在正文中再次出现”共同确认，不能只因章节短就判为目录。
- 先剔掉目录块，再生成机械章界；落表前校验章号连续、无重复、无跳号和无越界。
- 支持中文数字、阿拉伯数字、`Chapter N`、多卷重置和卷章组合标题；不宣称未测试格式。
- 空章保留为 `status=empty`，后续记录缺口；重复章号、跳号或边界异常停止语义处理。
- 完整旧成果默认直接使用或只做旧成果增强时不强制生成索引；部分完成、全新小说和明确重新拆文必须对当前完整原文建立或校验索引。

## Stage 2：按运行计划提取剧情点

### 两种输入不能混用

`chapter-extractor` 每次只执行 `run-plan.json` 中的一个批次：

- `existing-results`：读取 `existing_result_batches.source_files`，从旧成果二次提取，不得打开原文；
- `raw-original`：读取一个 `raw_original_read.blocks` 连续原文块，每章只属于一个块。

不得把已完成章与缺失章拼成同一个原文批次，不得把几十章交给一个 Agent 再让它自行分批，也不得按章启动独立语义任务。

### 已有成果二次提取

来源选择由检查器一次确定：完整的上游标准成果优先整套使用；否则优先整套使用完整紧凑成果；两边都只有部分覆盖时，才按“上游摘要 → 黄金三章 → 紧凑章节卡”逐章补缺。相同章节只选择一个来源。

每个已有成果批次输出一次跨章观察，使用 `<!-- REUSED_CHAPTERS:{起章}-{止章} -->` 声明范围。调用提交工具时指定：

```text
{PYTHON} skills/story-long-analyze/scripts/commit_batch_output.py \
  --input {临时结果} --root "拆文库/{书名}" \
  --batch-id {REUSExxx} --start {起章} --end {止章} \
  --input-kind existing-results
```

此模式只写 `_analysis_cache/复用提取-*.md`、提交凭据和进度，不生成或覆盖 `章节/第N章_摘要.md`，也不占用原文批次的缓存文件名。旧资料没有的新字段写“旧资料未提供”，不能回读原文补齐。

### 未拆章节块

块边界由运行计划确定：普通短章通常 5–10 章，长章或信息密集时 1–5 章；每块最多 10 章并受字符上限约束。单章本身超过字符上限时必须独占一块并标记超限，不得与下一章合并。块之间连续但不重叠，卷界、缺章和空章处断开。

每块调用一次 `chapter-extractor`。同一次理解只产生：

1. 每章紧凑事实：概要、目标—阻碍—行动—结果—得失、信息变化、状态变化、三维分数、钩子与定位；
2. 批次观察：跨章剧情点、关键事件与披露候选、关系变化、三维节奏异常点和跨批状态。

提交时指定 `--input-kind raw-original` 和机械索引中的原文 hash。提交工具先校验完整批次，再把紧凑事实机械渲染为仍含“关键事件、情节点、基调”等标签的逐章兼容文件；批次缓存同时保存全部逐章紧凑事实和跨章观察，供全局合并一次读取。不得为逐章文件第二次调用模型。

模型不再输出逐章章节卡表、事件清单或多条情节点。逐章兼容文件由脚本从同一份紧凑事实投影生成，不再重复生成长篇写法公式、人物小传、扩写技法长表或大段原文引用。

### 剧情点完善

批次剧情点必须说明：

> 起始目标与阻碍 → 改变局面的选择、行动或外部事件 → 局面变化与得失 → 后续影响

一个剧情点可以跨多个读取批次，一个批次也可以包含多个剧情点。批末未闭合时保留同一 ID、当前阻碍和最后证据交给下一批；Stage 3 再合并、拆分和复核边界。读取批次不能直接冒充剧情点。

批次开始前用 `manage_batch_checkpoint.py start` 登记 `running` 和尝试次数；成功提交后自动登记 `success`。输出缺章、截断、章界错位或 schema 不完整时只把当前批次登记为 `failed`。需要缩小输入时用 `fail --split` 将失败原文块按字符量拆成两个子块，并标记父块 `superseded`；已成功的其他块保持不动。单章块不能再拆，只能定点修复或重试。Agent 不可用时由主线程按同一块契约串行执行，不能退回逐章调用。
## Stage 3：在现有分析中增强

### 剧情单元因果链

写入现有剧情单元，不另建因果报告：

> 起始目标与阻碍 → 关键选择、行动或外部事件 → 局面变化与得失 → 后续影响

明确变化由谁造成、收益归谁、代价由谁承担，以及结果怎样限制或促成后续行动。过渡段和未完成单元允许链条未闭合。

### 双时间线与信息差

批次只提交主线或关键转折候选。全局聚合从中精选约 8–15 个关键节点，生成一张合并表：关键事件、客观发生时间、披露路径、读者所知、关键角色所知、披露前后判断变化、叙事作用和证据。普通小事件不建立双时间线条目。

背叛已经发生而文本先写异常、再给线索、最后确认时，在同一关键事件的披露路径中记录三个节点，不能写成三次背叛。“作者真相”只指文本已经证实的事实。

这些结果扩展 `剧情/节奏.md` 的信息推进区域；剧情单元仍保存客观因果事实。

### 三维节奏

三条轴引用同一剧情单元和证据：

| 维度 | 摘要值 | 必须解释 |
|---|---|---|
| 事件推进 | 1–5 | 哪些目标、风险、关系、资源、知识或行动方向改变；重要性、范围和可逆性 |
| 读者情绪 | 类型 + 1–5 | 文本用什么触发、维持、转向或释放情绪 |
| 篇幅安排 | 展开度 1–3 | 哪些节点被展开、压缩、省略或反复呈现，以及作用 |

安静场景可以事件推进低、情绪强、展开度高；事件变化大也可能被一句话压缩。篇幅长不自动等于高描写密度，过程未知不自动等于作者有意省略。分数只能帮助比较，不能替代文字说明。

### 可借鉴机制

机制进入现有 `剧情/情绪模块.md`。只对全书最强的 3 个机制完整说明读者期待、必要铺垫、人物关系/资源/信息条件、触发与兑现、可变部分、失效情形、来源和反例；其余机制只留名称、用途、适用范围和证据索引。禁止只留下“先压后扬”等标签，也禁止把同一分析复制到多层卡片。

本 Skill 只完成单书分析。跨书比较、归并、检索和是否进入灵感库由 #387 处理。

## Stage 4：人物关系

复用现有角色实体和情节点，写入 `角色/角色关系.md`：关系动作方向、触发事件、双方资源与得失、表面关系/真实关系、阶段状态、证据和推断等级。“甲保护乙”与“乙依赖甲”分别记录。

从同一关系数据生成：

- `人物关系图/核心人物关系.png`：核心关系方向和当前状态；
- `人物关系图/关键关系演变.png`：关键关系的阶段变化和触发点。

图片嵌入 `拆文报告.md`。证据不足或当前环境无法可靠渲染时，不编造图片；在报告和进度中说明缺失原因。不得为图片另建第二套关系事实。

## Stage 5：拆文报告

`拆文报告.md` 必须可独立阅读，建议包括：

1. 分析范围、覆盖率和一页结论；
2. 人物动力、核心冲突与关系演变；
3. 剧情单元和因果推进；
4. 故事时间线、披露时间线与知识边界；
5. 事件、情绪与篇幅三维节奏；
6. 核心机制、适用条件和失效情形；
7. 文风摘要、证据边界和待核事项。

重要单元展开，过渡内容简写；事实只描述一次，其他章节用单元 ID、章节和定位引用。聚合以一次全局语义合并为主，最多增加一次针对证据冲突或关键缺口的定点核验；报告生成只综合底层结果，不再次调用模型阅读全文。

Stage 5 后的 `选题决策.md` 回填沿用 current main：仅回填仍标记 `待拆文验证` 且题材明确匹配的项；项目根外文件写入前必须确认。文件存在但缺少当前契约必需的“能爆的原因”字段时，报告 `invalid_topic_decision_contract` 并提示重跑 story-long-scan Phase 5；缺少文件不影响拆文。

## Stage 6：文风与下游兼容

继续按 [references/style-profile-protocol.md](references/style-profile-protocol.md) 和 [references/style-profile-generator.md](references/style-profile-generator.md) 生成 `文风.md`。优先复用既有文风、黄金三章和批次中已经保留的写法证据；不得为了文风再次读取已覆盖章节原文。资料不足时保留未知；情绪/节奏意图仍以 `剧情/情绪模块.md`、`剧情/节奏.md` 为准。Stage 6 失败不阻断管道。

必须回归：

- 旧完成成果继续用于对标、导入和写作；
- 部分完成成果只补缺失范围；
- `selected_emotion_module` 仍来自 `剧情/情绪模块.md`；
- `rhythm_reference` 仍来自 `剧情/节奏.md`；
- 逐章事实、人物、设定和文风路径保持可读；
- 新旧混存时报告来源、覆盖范围、冲突和未知。

## 恢复与质量检查

恢复细节见 [references/pipeline-ops.md](references/pipeline-ops.md)。完成状态必须分别核对索引、批次事实、增强分析、聚合、图片和报告，不能用“索引已完成”冒充“拆文已完成”。

Stage 3–6 的硬事实必须可定位到本次批次证据或可信旧资料。质量阈值、覆盖和去重见 [references/material-decomposition.md](references/material-decomposition.md)。聚合阶段不得重新读取原文；证据不足、来源冲突或旧资料没有的字段写未知或待核，不用二次原文读取补齐。
