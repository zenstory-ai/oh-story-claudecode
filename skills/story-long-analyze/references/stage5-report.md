# Stage 5：主报告、完整概要与选题回填

Stage 5 时刻读本文件与 [synthesis-inputs.md](synthesis-inputs.md)。`拆文报告.md` 的模板与写法见 [author-facing.md](author-facing.md)「拆文报告.md」。

## 备份与标记

生成新的 `拆文报告.md` 前先执行：

```text
node "{story-long-analyze skill 根}/scripts/manage_analysis_run.js" mark-stage --root "{拆文目录}" --stage stage5 --prepare
```

若有旧报告，命令会完整备份到 `_analysis_cache/legacy/拆文报告.md`（不覆盖首份备份，内容变化时另存带 hash 的历史备份），其他旧产物与已有摘要不得覆盖。新报告和完整概要落盘后再运行不带 `--prepare` 的 `mark-stage` 标记完成。

## 完整概要

根据已落盘的 `剧情/故事线.md`（含故事框架）与剧情单元写 500–1000 字全书概要，涵盖主线推进阶段、核心角色作用、关键转折与因果，替换 `概要.md` 中的「首版概要」为「全书概要」，基本信息和卷段表保留。

## 报告

按 author-facing「拆文报告.md」直接写人话结论：只综合已落盘的底层结果，不为写报告重读全文，也不复制逐章摘要；每条结论写清看点与用法，再指到对应文件和章节。`source_locator`、证据等级和 `RH/TR/EM` 全量编号留在底层文件，报告里编号只在带人话名时出现。

文风尚未生成时，「文风一句话」写明待补；报告落盘并标 `stage5` 后，由 Stage 6 按 [style-profile-generator.md](style-profile-generator.md)「报告回填」补齐。

## 选题回填

长篇扫榜的 `选题决策.md` 会把「能爆的原因」标成 `待拆文验证`。报告落盘后依次查 `拆文库/` 所在工作区根目录、`扫榜/选题决策.md` 及 `扫榜/*/选题决策.md` 中日期最新的一份；都没有就跳过，不影响拆文。

1. 没有「推荐选题」一节（只扫了榜）就跳过；有推荐选题但缺「能爆的原因」等必需字段时跳过回填（不影响拆文完成），按 author-facing「选题决策缺栏目」告知作者。
2. 只看「题材组合」与本书匹配、且「能爆的原因」仍标 `待拆文验证` 的选题。
3. 拆文支持该假设时，把标记改为 `已拆文验证` 并同行补「依据：《{书名}》拆文报告·核心发现第 N 条（第 x–y 章）」；不符时改为 `拆文未证实` 并用同样格式写清哪里不符。只改这一行，不动其他栏目。
4. 向作者汇报时用一句话说明回填了哪个选题及结论。
