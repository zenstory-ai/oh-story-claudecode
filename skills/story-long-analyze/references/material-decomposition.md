# 全局拆书方法论

本文件规定当前 analysis contract 5.0 的业务逻辑。把小说视为人物动力、关系动作、冲突升级与信息调度四个相互作用的系统；机械索引只负责定位，语义分析从结构块开始。

---

## 1. 输入分级

| 输入档 | 行为 | 可声明范围 |
|---|---|---|
| 全文 | 执行完整拆解 | 可给全书结论 |
| 大部分章节 | 执行完整流程，记录缺失 | 只对可见范围给结论，说明终局风险 |
| 梗概或少量节选 | 生成暂定索引与分析 | 不声称覆盖整本，不判断终局反派/主题 |

记录书名、题材、字数、章节数、叙事人称、输入覆盖率、缺失章与抓取污染。章节边界不清晰时先建立临时边界，不能跳过定位直接分析。

---

## 2. chapter_index 机械定位

`chapter_index.csv` 每行只承担五项：全局章号、标题、原文定位、字符数、解析状态。生成时只扫描标题和边界，不理解正文，不调用模型。

硬边界：

1. 索引只生成一次；相同 `source_sha256` + `boundary_sha256` 时直接复用。
2. 源或边界变化时旧索引整体失效，显式重建；禁止增量拼接不同版本。
3. 不写核心事件、人物、节点、时间、信息差、顺序手法、强度、钩子、摘句或置信度。
4. 不以标题充当剧情摘要，不截取章节首尾句，不先做详细索引再裁列。
5. 所有下游只用它把章号映射到 `source_locator`；需要事实时必须回读原文。

## 3. 结构块

结构块是最小语义单元。一个有效块必须形成：

> 初始缺口/目标 → 压力递增 → 转折 → 兑现 → 未清阅读债

### 3.1 边界寻找

先用无语义信号选候选锚点：卷界、黄金三章、末三章、标题中的实体/地点/系统奖励/身份变化/战斗或关系词。读取锚点后只向前后扩展到循环完整为止。

- 2–5 章常见于短循环。
- 5–12 章常见于标准循环。
- 12–30 章常见于中型弧。

这些是范围提示，不是固定切片。转场或无独立状态变化的章节并入相邻块。大卷由多个结构块组成，不把整卷强行压成一块。

### 3.2 字段与证据

每块记录：块 ID、章节范围、块名、初始缺口、目标、压力、转折、兑现、剩余钩子、状态变化、主要人物、证据定位、三维强度、关系变化、块内节奏锚点、五个抽象灵感字段、置信度和状态。

`evidence_locator` 只保存短定位，不保存原句。字段必须来自真实语义阅读；禁止标题改写、首尾句拼接、机械摘句或「本段主要讲述」占位。证据不足写「未知」并降级。

结构块的缺口、压力、转折、兑现与新债已经构成关键事件节点，不再另生成一套节点摘要。`relationship_delta` 最多记录 3 条关系状态变化；`rhythm_anchors` 最多记录 4 个已核证的蓄力/峰值/释放/余波章。五个 `inspiration_*` 字段必须与结构块同次生成，并在去除原作专名后才提交；Stage 7 不允许再次逐块做语义抽象。

### 3.3 覆盖与重读

- 默认模式追求结构覆盖，不追求逐章语义覆盖。
- 每个结构块只有一个 owner；成功范围不得再次读取。
- 需要重试时在 `_progress.json.retry_reasons` 记录范围、原因和新 owner。
- 法证模式也只保存 20–30 章段级胶囊，不恢复逐章卡。

## 4. 六维拆书

### 4.1 人物设定与功能

对主要角色记录：姓名/别名、年龄性别身份、表层关键词、核心欲望、核心恐惧、致命缺陷/错误信念、能力资源、秘密、弧光、剧情重量、功能类型与反派同理点。

功能类型：

- **推动剧情型**：删除后关键事件不发生，或故事无法进入下一阶段。
- **强化主角型**：主要价值是显露主角性格、软肋、价值选择或变化。
- **双重功能型**：前后阶段功能转换，或同时承担两类功能。

### 4.2 人物关系图谱

关系使用 `主语 + 动作动词 + 宾语`：保护、控制、利用、依赖、讨好、试探、嫉妒、崇拜、隐瞒、监视、替代、背叛、赎罪、竞争、误解、拯救等。

同一对人物可有多条有向关系；必须区分表层关系、真实关系、关系资源与当前张力。核心关系还要把各结构块的 `relationship_delta` 合并为“起点状态 → 触发动作 → 新状态 → 不可逆变化”的演变链，不能只列一个转折章节。

### 4.3 冲突矩阵

至少检查：

- 利益冲突：争夺资源、位置或结果。
- 信念冲突：对「什么正确」答案不兼容。
- 情感冲突：爱、恨、亏欠、嫉妒、依赖阻碍理性目标。
- 身份/秘密冲突：曝光会改变关系或局势。
- 方法冲突：目标相似，但可接受手段不同。

同时与主角存在高强度利益冲突和信念冲突、且能持续行动者，可能是终局型对手；只作为诊断线索，不机械定论。

### 4.4 故事真实时间线

按故事世界实际先后记录：事件、时间、参与人物、原因、结果、首次披露章节、信息掌握者。时间不明写「未知」，不依据题材惯例补日期。

### 4.5 成品叙事顺序

按作者呈现顺序记录：章节、叙述时间点、核心事件、披露/隐藏信息、顺序手法、章末钩子、与真实时间的偏移。

### 4.6 题材、体量与亮点

记录主/辅类型、受众、总字数、章节数、平均章长、核心阅读承诺与最有证据的三个亮点。

核心阅读承诺回答：读者持续阅读，稳定期待获得什么体验？例如破案推理、身份升级、情感拉扯、复仇兑现或世界探索。

## 5. 双时间线与信息差（写入六维拆书）

### 5.1 顺序标签

| 标签 | 作用 |
|---|---|
| 提前 | 先展示后果或异常，立刻建立问题 |
| 延后 | 暂扣原因、身份或动机，制造悬念/反转 |
| 拆散 | 同一事件多次披露，持续修正理解 |
| 重复 | 从新视角或新增信息重看同一事件 |
| 省略 | 跳过低价值过程，加速 |
| 并行 | 交叉两条线，制造对照、倒计时或会合期待 |
| 顺叙 | 披露顺序与真实顺序一致 |

每次重要调度都回答：

1. 如果顺写会损失什么？
2. 当前顺序让读者比谁多知道或少知道什么？
3. 信息释放后，人物/事件/风险判断如何改变？

### 5.2 三层认知

分别维护读者、主角、其他关键人物的已知信息。不得把作者真相写成读者已知，也不得把读者可见线索写成角色已知。

## 6. 三维节奏（写入六维拆书）

### 6.1 剧情强度 1–5

| 分数 | 锚点 |
|---:|---|
| 1 | 日常衔接、移动、轻微信息，无明显状态变化 |
| 2 | 小障碍、小线索、小摩擦，局部状态改变 |
| 3 | 明确进展、告白、失败、联盟变化或重要发现 |
| 4 | 重大损失、关系破裂、身份暴露、计划逆转 |
| 5 | 核心真相、不可逆抉择、高潮对决、终局改变 |

### 6.2 情绪强度 1–5

先标情绪类型，再按身体唤醒、共情深度与余韵评分。剧情强度与情绪强度允许分离：安静告别可能剧情 2、情绪 5。

### 6.3 描写密度 1–3

| 分数 | 锚点 |
|---:|---|
| 1 | 概述、跳时、结果性叙述、一笔带过 |
| 2 | 常规场景，有必要动作和对话 |
| 3 | 细节、心理、环境、动作和对话重点展开 |

### 6.4 诊断问题

- 高峰前是否有低谷或蓄力？
- 连续高强度是否造成麻木？
- 低强度章节是否承担信息、人物或余波功能？
- 重点篇幅是否给了真正重要的节点？
- 高潮是否有足够铺垫与余波？

按结构块曲线识别峰值、低谷、蓄力区、喘息区和循环；再把 `rhythm_anchors` 展开为有限的章级峰谷锚点。锚点不是逐章评分，未核证章节不得补分。循环只抽象缺口→加压→释放→余波→新钩子，不复制事件素材。

## 7. 爆款机制

每个机制使用固定机制链：

> 文本设计 → 读者认知或情绪变化 → 持续阅读动力 → 可迁移原则

候选维度：高概念承诺、人物欲望、关系张力、对手压力、升级反馈、秘密与信息差、反转公平性、高潮兑现、情绪补偿、主题立意、语言辨识度。

选三个证据最强且层次尽量不同的机制。每个必须写：

1. 表层表现。
2. 叙事机制。
3. 读者心理效果。
4. 章节证据与置信度。
5. 可迁移原则。
6. 必须替换的素材位。
7. 不可照搬项。
8. 误用风险。

禁止空泛结论，如「人设好」「节奏快」「反转强」。

## 8. 灵感抽象边界

拆文管道不默认生成原创故事种子，也不在拆文目录保存灵感卡。Stage 3 已在首次语义读取中生成五个 `inspiration_*` 字段；Stage 7 由独立 `/story-inspiration-distill` 机械渲染 IA，再用一次聚合处理 NM/CBA。它不得重新读取原文、章节索引、结构块原文证据或逐块重写 IA。

抽象时按四层区分：

1. 表层元素：时代、职业、场景、具体事件。
2. 戏剧机制：背叛、误认、倒计时、身份错位、资源争夺。
3. 人物引擎：欲望、恐惧、错误信念与极端选择。
4. 主题张力：爱与控制、忠诚与自我、正义与代价。

只保存第 2–4 层的机制规律与变体边界，不自动拼装完整原创故事。第 1 层组合、原作独有事件链、专名与标志性场面不得进入可复用卡。

## 9. 证据、置信度与事实保真

### 9.1 置信度

- `A 明确`：文本直接说明或反复证实。
- `B 强推断`：多处行为与结果一致支持。
- `C 暂定`：依据有限，存在其他解释。

### 9.2 硬事实回查

等级、数值、距离、属性、势力数、角色出场章、谁对谁说了什么，写入全局文件前必须按 `source_locator` 定点回原文。命中不到时改为「文本未明确」或删除，不保留无源断言。

### 9.3 跨指代不串

坐骑等级不等于骑手等级；A 的台词不等于 B 的台词；本章数字不等于相邻章数字；同名角色没有同指证据时不合并。

### 9.4 输入缺陷

缺章、截断、抓取污染、标题重复、章节错序、别名歧义与时间矛盾都写入 `证据与边界.md`，并说明影响了哪一维。不能用合理剧情补洞。

## 10. 全局质量门

| 指标 | 阈值 | 不达标处理 |
|---|---|---|
| 索引覆盖率 | Stage 0 连续边界必须 100% 入表；跳号/重复不落表 | 修正章节格式后显式重建，不伪造失败行 |
| 定位回查率 | 所有索引行有合法 locator | 修正边界或标 failed |
| 结构块有效性 | 每个 ok 块有完整戏剧循环、状态变化与定位 | 合并空块或补读边界；不机械补句 |
| 首次读取完整性 | 每个 ok 块同时有关系变化、节奏锚点和五个 `inspiration_*` 字段 | 当前块未提交；禁止留给 Stage 7 补写 |
| 六维完整性 | 6/6 维、关系演变、双时间线与三维节奏都在 `六维拆书.md` | 缺项阻断 Stage 6；禁止外链占位 |
| 双时间线 | 关键事件同时有真实/披露顺序 | 缺一侧标未知，不混写 |
| 三维节奏 | 三指标分别存在 | 缺指标阻断 |
| 关系动作化 | 关系表 100% 使用有向动词 | 改写名词关系 |
| 爆款机制 | 3 个机制均有证据和误用风险 | 不足 3 个时如实写「仅 N 个证据充分」，不得凑数 |
| 关键证据命中 | A/B 结论的短关键词可回查 | 降级 C 或删除 |

输入不足时可以少于三个机制，但必须在一页结论和边界文件显式说明；「不凑数」优先于格式完整。

## 11. 长篇批处理

先分清：

- **结构块**：故事自身的完整循环，范围可变。
- **处理批次**：一次提交多少个候选块，受上下文限制；通常 1–3 块/批。

### 子代理并行

1. Stage 2 由确定性脚本一次完成，不 spawn。
2. Stage 3 子代理一次只拥有一个候选结构块，且必须 `fork_turns=none`；只收到本块原文和字段 schema。
3. Stage 3 的同一 owner 同时回传块级状态变化、关系转折、节奏锚点与五个灵感字段；不得再派第二个 owner抽象同一块。
4. Stage 4–6 只消费已提交结构块与必要证据定位，不重新遍历全书；不回传逐章复述或无消费者中间稿。

### solo/direct 降级

子代理不可用时按同一块顺序处理；每块提交后释放原文上下文。结果 schema 不降级。

### 跨批一致性

合并后检查姓名/别名、时间、动机、秘密、因果、强度标尺是否漂移。冲突不强行选边，写入 `证据与边界.md`。
