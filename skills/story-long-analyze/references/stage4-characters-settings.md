# Stage 4：角色、设定与关系

Stage 4 时刻读本文件与 [synthesis-inputs.md](synthesis-inputs.md)（取料、证据等级、阶段标记与事实保真）。

## 核心规则

从逐章摘要的 `涉及`、`状态变化`（`digest --part chapters --fields 涉及,状态变化`，批次输出里叫 `涉及人物`）和批次 `关系变化` 归一人物，再结合 Stage 3 剧情单元生成角色档案与设定。Stage 2 每章只记关键人物和可见净变化，跨章的人物判断、别名合并都在这里做。关系记录动作方向、触发、双方得失、表面/真实状态、阶段变化和证据；“甲保护乙”与“乙依赖甲”分别记录。

## 谁建档、建多深

按人物在故事里的作用分级，出场章节数只当线索，不用出场比例否定核心角色。拿不准时归入低一级；前期戏少、后期推动重要支线的，按后期作用定级；重要导师或伙伴即使出场少也算核心配角。

| 定位 | 标准 | 建档深度 |
|---|---|---|
| 主角 | 推动主线、有完整成长轨迹 | 完整档案＋成长弧线＋动机链 |
| 反派 | 与主角对立、推动核心冲突、有明确动机 | 完整档案＋动机链 |
| 核心配角 | 推动重要支线，或有独立人格和成长，或与主角反复直接互动 | 完整档案＋关系 |
| 功能角色 | 作用有限：提供信息、道具或一次性互动 | 简化档案：功能＋首次出场章 |
| 不建档 | 只出场一次、无台词且不推动剧情的路人；群体称呼、无名路人，以及大哥、掌柜、老师、小伙子这类亲属、身份、年龄或外貌泛称，除非原文固定用它指代某一个人 | 跳过 |

## 一人一实体与别名

- 不同人物绝不合并进同一实体；拿不准是否同一人时分开建。
- 只有本名/常用名和有同指证据（同位说明、括号别名、上下文指代或明确改名，优先查批次 `跨批状态` 的「已确认别名」）的绰号或带姓名职务称呼触发合并；描述称谓与单纯头衔职务不合并。
- 主条目用首次正式名，别名列在档案里并注明类型和依据。

## 金手指

相互关联、共同作用的元素合为一个，只有完全独立、互不依赖的能力来源才分开写。写清获取、机制、进化史和多重能力；没有金手指时注明。

## 人物关系

只从已提取的情节点和批次 `关系变化` 整理，不重读原文，只记新关系或关系变化：

- 同一有向关系的最新状态作主记录，历史写进演变轨迹（`第{N}章：{状态A} → 第{M}章：{状态B}｜触发：{事件}｜情感转变：{正面→负面等}`）；反向关系动作不去重。
- 无直接互动、仅靠第三方评价或描述支撑的关系标 `B` 或 `C` 并写明评价者与依据；只凭同场出现不确认关系。
- 复核：主角和核心配角各自有向关系数少于 3 查遗漏、多于 10 查误合并（只按原文修正，不凑数）。

## 输出模板

Stage 4 直接按主题拆成多个文件，与导入和长篇写作的项目结构对齐。等级、数值、距离、属性、势力数等硬事实核对已有批次证据或旧成果，原文没给的写「原文未明确」。

`角色/{角色名}.md`（每角色一份）：
- 定位：主角 / 反派 / 核心配角 / 功能角色
- 200–500 字档案：身份背景（1–2 句）→ 核心经历（3–5 句，按时序）→ 性格特质（1–2 句，从行为归纳）→ 能力特长 → 人际关系 → 成长轨迹（如有）
- 关键情节：3–5 个转折点，按时序
- 成长弧线：有明显变化时一句话总结，如“从普通少年成长为觉醒血脉的强者”
- 别名：列出别名、类型和依据

`设定/世界观/力量体系.md`：等级、晋升条件的文本描述，长篇注意多层级体系；不到 200 字且不成独立体系时并入 `背景设定.md`，本文件省略。

`设定/世界观/地理.md`：分布、主要区域、关键地点；不到 200 字时并入 `背景设定.md`。

`设定/世界观/背景设定.md`：世界类型（奇幻/现实/平行世界）、核心规则、特殊设定，以及不足独立成文件的力量体系、地理、势力；无特殊世界观时写“本书为现实题材，无特殊世界观设定”。

`设定/世界观/金手指.md`（统一放在 `设定/世界观/` 下）：
- 类型：系统 / 空间 / 重生 / 穿越 / 特殊体质 / 神器 / 血脉 / 其他
- 名称 | 描述（300–600 字，含能力、获取、机制、进化史、多重能力演化）| 核心机制 | 当前能力
- 没有金手指时只写“本书无明显金手指设定”

`设定/势力/{势力名}.md`（每个核心势力一份）：名称 / 类型（门派、组织、家族、国家）/ 核心人物 / 立场倾向 / 与其他势力关系 / 关键事件；不到 200 字时并入 `背景设定.md`，不丢信息。

`角色/角色关系.md`：

| 关系ID | 主体 → 客体 | 关系动作/类型 | 表面关系 | 真实关系 | 触发事件 | 双方得失 | 变化后状态 | 证据等级 | 证据 |
|---|---|---|---|---|---|---|---|---|---|

关系动作写保护、依赖、控制、服从、欺骗、竞争等，类型写家人、师徒、朋友、敌人、恋人、同事、上下级、商业或其他；证据等级填 `A`/`B`/`C`（含义见 synthesis-inputs「证据等级」）；证据写章节、情节点或 `source_locator`。同一对角色的最新状态和历史演变都保留。

## 人物关系图

关系图只从 `角色/角色关系.md` 生成，不手画、不另建关系事实：

```text
"{PYTHON}" "{story-long-analyze skill 根}/scripts/render_relation_chart.py" --root "{拆文目录}" --png
```

它总是写出 `人物关系图/人物关系图.md`（Mermaid 图＋文字清单，文字清单保留中文，是主产物）；只有装了 matplotlib 且找到能显示图中全部文字的字体时，才另画 `核心人物关系.png` 与 `关键关系演变.png`，表情等符号不画进图片。字体不够就不出图，不改画拼音或首字母版，把脚本返回的 `author_message` 转告作者。
