# Stage 3：剧情、双时间线与三维节奏

Stage 3 时刻读本文件与 [synthesis-inputs.md](synthesis-inputs.md)（取料、证据等级、阶段标记与事实保真）。

## 核心规则

剧情点按“起始目标与阻碍 → 改变局面的选择/行动/外部事件 → 局面变化与得失 → 后续影响”合并。事件发生与信息披露分开；同一事实的异常、线索、解释、确认属于一条披露路径。全局只保留约 8–15 个主线或关键转折节点。

三维节奏分别说明：事件推进 1–5 及状态变化，读者情绪类型/强度 1–5 及触发，篇幅展开度 1–3 及展开/压缩/省略/反复的作用。情绪机制写完整卡，至少展开全书最强的 3 个，不足 3 个按实际数量，值得复现的不设上限；其余进索引。

产出顺序：故事框架 → 剧情单元 → 故事线 → `剧情/README.md` → `剧情/节奏.md` → `剧情/情绪模块.md` → 散落情节与自检。两份权威文件都落盘后按 synthesis-inputs「阶段标记」标 `stage3`。

## 1. 故事框架识别

先用 digest 取前 3 章与后 3 章的概要和关键事件，结合 `概要.md` 初稿判断全书的核心驱动，写进 `剧情/故事线.md` 顶部。框架决定剧情单元怎么切：

| 框架类型 | 特征 | 剧情单元按什么切 |
|---|---|---|
| 升级流 | 等级体系清晰，按境界分段 | 等级阶段 |
| 复仇线 | 核心矛盾明确，目标驱动 | 复仇对象/阶段 |
| 日常/单元 | 每卷独立故事，弱连续性 | 卷/单元 |
| 多线交织 | 多视角/多时间线 | 线索，交叉点单独标 |
| 蜕变成长 | 主角内在变化为主线 | 成长阶段 |
| 感情流 | 关系推进是主线 | 关系阶段（相识、试探、确认、危机、和解） |

有卷、部、篇时优先按作者的划分。

```markdown
## 故事框架

| 项目 | 内容 |
|------|------|
| 框架类型 | {升级流/复仇线/日常单元/多线交织/蜕变成长/感情流/混合} |
| 核心驱动 | {一句话说清全书靠什么持续往前推} |
| 主轴矛盾 | {贯穿全书的根本矛盾} |
| 升级机制 | {力量/地位/关系的递进方式，没有填“—”} |
| 叙事节奏模式 | {铺垫→冲突→爽点→新悬念 的典型周期} |
| 判断依据 | {哪些章节/情节点支撑此判断} |
```

剧情单元数量只用来发现明显的粒度问题，不当凑数目标：<30 章约 3–6 个，30–100 章约 5–15 个，100–300 章约 10–25 个，>300 章约 15–40 个。明显低于或高于这个范围时回头检查粒度。

## 2. 剧情单元

**第一步：识别剧情大纲。** 从批次剧情点和逐章摘要合并出独立剧情，边界或证据不清时再读相关章节摘要。一条剧情必须同时有：可衡量的核心目标（获得型、解决型、创造型、探索型或关系/生活推进型，不是宏观主题）、具体的主要冲突或阻力（日常/单元剧可为待解问题、经营难题或关系拉扯，不是另一个大冲突的子阶段）、相对独立的角色群、自己的张弛节奏。

| 粒度或混乱类型 | 信号与示例 | 处理方式 |
|---|---|---|
| 过细（单一事件） | “获得神器”（1–2 章） | 是事件，并进所属剧情 |
| 过粗（宏观主题） | “主角的成长之路”（1–100 章） | 是主题，拆开 |
| 合适 | “家族觉醒与传承认知”（1–6 章） | 有独立目标、冲突、角色群和完整弧线 |
| 包含 / 大段重叠 | 剧情 A 完全包含 B，或共享过半章节 | 保留粒度适中的 B，拆开过粗的 A 或区分「剧情 vs 阶段」 |
| 首尾附庸 / 子目标 | A 只占 B 的首尾几章，或 A 的目标是 B 的子目标 | 降为 B 的一个阶段 |

**第二步：分配情节点。** 对每条剧情，用 `digest --part chapters --points brief` 按章节窗口扫情节点，挑出直接服务、推动或阻碍其目标的节点：先找起点（触发事件）和终点（完成或失败），再补中间的关键过渡，按时间排好，最后据此补全概要和结构分布。判断归属看主题、因果和目标导向；同一角色出现不等于服务同一目标。

覆盖分三层：主线剧情推动整体故事；支线（感情、成长、战斗等）；补充剧情（过渡、日常），用来接住剩下的情节点。

输出 `剧情/{标题}.md`，字段以本表为准：

| 项目 | 内容 |
|------|------|
| 标题 | 15 字以内 |
| 类型 | {主线/爱情/成长/复仇/寻宝/悬疑/战斗/权谋/修炼/危机/谜团/日常/其他}；「悬疑」指主动推理调查，「谜团」指世界观或身世等未解之谜 |
| 概要 | {150–300 字，按时序连贯叙述起承转合与因果，不靠同一连接词反复串联；含核心角色及定位、关键地点、关键道具（如有）、对主角或世界的影响} |
| 起始目标 | {谁起初想做什么；目标在本单元前已建立时引用首次建立位置} |
| 主要阻碍 | {人物、规则、资源、信息或环境造成的具体阻碍} |
| 关键变化来源 | {谁的选择/行动，或什么外部事件改变了局面；不默认由主角主动造成} |
| 局面变化 | {目标、风险、关系、资源、知识或行动方向从什么状态变成什么状态} |
| 得失与承担者 | {谁得到什么、谁失去什么或承担什么代价} |
| 后续影响 | {结果如何促成、限制或迫使后续行动；未完成标 open} |
| 关键信息功能 | {这条剧情让读者获得/等待/误判/确认什么信息} |
| 读者需求 | {安全感/优越感/期待感/情感补偿/认知反转/陪伴感等} |
| 情绪模块ID | {引用 `剧情/情绪模块.md` 的 EM-001 等，不重复完整卡} |
| 套路框架位置 | {退婚打脸/迟来追悔/升级试炼/掉马震惊/以小搏大/其他；说明它怎样在本书框架里运转} |
| 桥段标签 | 从下方桥段词表选命中项，逗号分隔；表外确有的桥段照实写；没有就留空，不硬凑 |
| 主题 | {不超过 3 个} |
| 章节范围 | 第{X}-{Y}章（共{N}章，约{M}万字） |

结构分布：铺垫期 | 发展期 | 高潮期 | 收尾期（各含章节范围）

情节点索引：| 序号 | 章节 | 描述 | 归入把握（明确 / 待复核） |

### 跨批次合并

只看相邻批次边界附近的剧情对，四条同时满足才合并（同一核心事件或目标、主要人物相同、B 是 A 的自然延续、不是两个有因果关系的独立事件）；拿不准时不合并。
- **应合并**：“竞选县长秘书（准备阶段）”+“竞选县长秘书（投票阶段）”；“修炼突破（前期）”+“修炼突破（后期）”。
- **不合并**：“在办公室立足”+“竞选县长秘书”（两个目标）；“炼气期修炼”+“筑基期修炼”（不同阶段）；“东域修炼”+“中州历练”（不同地图）。

## 3. 故事线

多条剧情聚合成故事线，写进 `剧情/故事线.md`（故事框架之后）：

| 项目 | 内容 |
|------|------|
| 标题 | 15 字以内 |
| 类型 | {主线/感情线/成长线/复仇线/夺宝线/冲突线/谜团线/其他} |
| 描述 | {300–600 字，以关键转折为界分 3–8 个发展阶段，每段写核心冲突、关键角色及作用、能力/资源/地位演进；追踪伏笔与回收；标注与其他故事线的交织关系} |
| 情绪引擎摘要 | {1–2 句：这条线怎样制造缺口、延迟满足、释放和余波；详情指向 `剧情/情绪模块.md`} |
| 套路运行方式 | {套路怎样嵌进故事框架而不是孤立桥段；详情指向模块 ID} |
| 主题 | {不超过 3 个} |
| 包含剧情 | {剧情标题，按时序，至少 1 个} |
| 模块引用 | {EM-001, EM-002；只写引用} |

故事线关系：并行 / 交织 / 依赖

## 4. 剧情目录与权威分工

`剧情/README.md` 是轻量索引：

```markdown
# 剧情目录索引

| 文件 | 权威范围 | 下游用法 |
|---|---|---|
| `节奏.md` | 关键信息推进、爽点循环、情绪触动点、爆发节奏 | 产出 `rhythm_reference` |
| `情绪模块.md` | 读者需求、情绪引擎、套路框架、可复现模块卡 | 产出 `selected_emotion_module` |
| `故事线.md` | 故事框架与故事线摘要 | 投影摘要，不覆盖权威文件 |
| `拆文报告.md` | 人类阅读报告 | 投影摘要，不覆盖权威文件 |

冲突时以 `节奏.md` / `情绪模块.md` 为准；两个文件用 EM/RH/TR ID 互相引用。

## 剧情单元清单

| 剧情单元 | 类型 | 桥段标签 | 章节范围 | 体量 |
|---|---|---|---|---|
| `{标题}.md` | {类型} | {桥段标签} | 第{X}-{Y}章 | 共{N}章，约{M}万字 |

清单只是检索索引，各列取剧情单元已有字段；剧情定义以各剧情单元文件为准。
```

## 5. 节奏.md

输入：批次关键事件与披露候选、三维节奏峰谷、逐章紧凑事实、剧情单元和故事线。只选改变主线、关系、核心风险或读者判断的事件；客观事件只登记一次，异常、线索、解释和确认写进同一事件的披露路径。每条 `EV/RV/AX/RH/TR` 都能回指章节、情节点或定位；过程没有展示时写“文本未展示”，不推断作者有意省略。爽点循环拆解铺垫层（缺口/误判）、释放层（兑现/打脸/情感满足）、反应层（旁人递进反应：男频常见「质疑/轻视→震惊→强者重新评价→扩散传播」，感情流常见「误会/冷待→动摇→维护/表态→关系公开」，反应篇幅比以 1.5 为经验参照）与衔接层（新钩子：打完小的来大的、胜利后发现隐患、身份暴露、利益升级、关系突变）。

```markdown
# 节奏索引：{书名}

> 权威范围：信息披露、读者/角色知识边界、事件/情绪/篇幅三维节奏、爽点循环和情绪触动点。`拆文报告.md` 只引用本文件摘要。

## 全书情绪节奏总览

- 情绪折线：{压抑/期待 → 紧张/加压 → 爽感/反转 → 余波/新危机；标注关键章节区间}
- 爽点频率：{每 N 章一次小爽点；每 M 章一次中高潮；大高潮位置}
- 高潮分布：小高潮：第 {X/Y/Z} 章；中高潮：第 {X/Y} 章；大高潮：第 {X} 章
- 冲突升级路径：{低级矛盾 → 中级矛盾 → 高级矛盾 → 终局矛盾；标注触发章节}
- 伏笔跨章地图：{伏笔内容 | 第X章埋入方式 → 第Y章回收效果；只列跨度超过 2 章或影响主线的伏笔}

## 循环单元

- 小循环（常见 2–4 章，按本书实际跨度写）：{缺口/误判 → 加压/试探 → 释放/新钩子；可变项是什么}
- 中循环（常见 5–10 章，按本书实际跨度写）：{阶段目标 → 多轮阻碍 → 中段反转 → 阶段爽点 → 更大问题}
- 大循环（常见 12–25 章，按本书实际跨度写）：{卷内目标 → 资源/关系/敌手升级 → 核心冲突爆发 → 余波与转场}

## 关键信息推进表

| 章节/范围 | 关键信息 | 扩写方式 | 推进功能 | 节奏效果 | 关联剧情/模块 |
|---|---|---|---|---|---|
| 第{N}章 | {读者必须获得/误判/等待的信息} | {对话铺垫/事件验证/反应层/延迟揭示/多段回扣} | {立目标/加压/释放/转场/埋钩} | {加速/减速/蓄力/爆发/冷却} | {剧情标题 / EM-001} |

## 关键双时间线（全书约 8–15 个节点）

| 关键事件ID | 客观发生时间/顺序 | 事件事实 | 披露路径与章节 | 读者所知 | 关键角色所知 | 披露前后判断变化 | 叙事作用 | 证据位置 |
|---|---|---|---|---|---|---|---|---|
| EV-001 | {书内时间或相对顺序} | {只登记一次的关键事件} | {RV-001异常→RV-002线索→RV-003确认；对应章节} | {各披露阶段的边界} | {关键角色在各阶段知道/不知道什么} | {读者或角色从何种判断变成何种判断} | {悬念/误导/反转/共情/期待} | {章节+source_locator+定位词} |

一个事件的多次披露合并进同一行的披露路径，不算成多次客观事件；“作者真相”只填文本已经证实的事实。

## 情绪触动点索引

| 触动点ID | 章节 | 触发事件 | 目标读者情绪 | 爆发点 | 余波/冷却 | 复现提示 |

| TR-001 | 第{N}章 | {触发读者情绪的具体情节} | {期待/心疼/愤怒/爽/甜/热血/恐惧} | {情绪最高句/段或事件} | {角色反应/关系变化/新悬念} | {保留情绪链，不搬运具体事件} |

## 爆发节奏总结

```

## 6. 情绪模块.md

输入：故事框架、剧情单元、`剧情/节奏.md`、读者需求判断、桥段标签。先抽象“读者为什么期待兑现”，再把具体剧情抽成情绪链和功能位；尽量给每张卡标来源（`剧情/节奏.md` 的 RH/TR 条目或章节情节点），没把握就留空，不硬凑、不删卡。不把原文专名、独特事件顺序、标志性台词写成可复用模板。

```markdown
# 情绪模块：{书名}

> 权威范围：读者需求 / 情绪引擎 / 套路框架运转 / 可复现模块。禁止把原文具体桥段当模板照搬。

## 读者需求 / 情绪引擎

| 读者需求 | 本书满足方式 | 证据章节/情节点 | 持续追读机制 | 可迁移边界 |
|---|---|---|---|---|
| {优越感/安全感/被理解/替代性复仇/关系补偿/认知惊喜等} | {故事如何持续交付} | {第N章/Px} | {下一层期待如何被立起} | {可保留情绪逻辑；必须替换具体设定/人物/事件} |

## 故事框架与套路运行图

| 框架/套路 | 在本书中的位置 | 运行方式 | 为什么有效 | 失效风险 |
|---|---|---|---|---|
```

## 7. 散落情节与收尾自检

剧情单元写完后，用 `digest --part chapters --points brief` 收集未归入任何剧情单元的情节点：
1. 孤立情节点 < 总数 5% 时直接写进 `剧情/散落情节.md` 标「少量散落，无需再归类」。
2. 目标与因果归属明确的归入现有剧情单元标 `[孤立情节归入]`；仅角色/主题相关、目标待确认的归入标 `[低置信归入]`；更弱的不硬归，按主题满 5 个情节点聚成候选剧情单元标 `[聚类生成]`，其余按章写进 `剧情/散落情节.md` 注明原因（拆文报告统计散落数量与占比）。

写完全部产物后自检一次（自检结果不落盘，`剧情/故事线.md` 不写自检表）：

| 检查 | 标准 | 不达标时 |
|---|---|---|
| 覆盖率 | 已归进剧情单元的情节点÷总情节点，85%–95%（<30 章单主线节选可近 100%） | 低于 85% 回第 2 步复核遗漏，证据不足就留在散落情节；高于 95% 复核是否过度归并 |
| 重叠 | 被多条剧情单元共用的情节点不超过总数的三分之一 | 边界模糊，考虑合并 |
| 粒度与独立性 | 没有上方粒度混乱表里的情况，每条剧情都满足四项独立标准 | 拆分、合并或降为阶段 |
| 关键信息 | 每章都有信息行或明确“无独立信息变化” | 按原输入类型回到 Stage 2 补提取；旧成果章不回读原文 |
| 披露引用 | 每个 `RV-*` 属于同一行 `EV-*` 的披露路径，同一事件不因多次披露重复建档 | 回到批次观察合并 |
| 三维解释 | `AX-*` 三轴都有理由与证据 | 补“无明显变化/文本未展示”及依据，不用分数占位 |
