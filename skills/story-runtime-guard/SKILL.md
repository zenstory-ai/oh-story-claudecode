# story-runtime-guard：长任务运行守卫

这是运行契约，不是创作模块。它只决定“如何跑”，不改变拆文或写文的业务 schema。

## 启动前预算

先输出并写入任务进度：

- 源文件哈希、边界哈希、预计章节数。
- 需要语义阅读的结构块/锚点数，不用总章节数冒充工作量。
- 每批 owner、输入范围、唯一消费者和落盘产物。
- 默认模式或用户明确要求的法证模式。

没有消费者的中间稿不生成；不能说明用途的全文重读不执行。

## 子代理纪律

1. 支持历史分叉参数时强制 `fork_turns=none`；不支持时只传最小任务包。
2. 任务包只含：一个明确范围、原文片段、固定 schema、必要边界。不得复制主会话、全文 skill、已完成块或无关参考。
3. 一个范围只有一个语义 owner；一个 agent 只交一个产物，提交后退出。
4. 子代理不得自行再读全文、再拆章节、创建长期笔记或生成第二套索引。
5. 并行只用于相互独立的结构块；依赖前块状态的任务串行。

## 读取账本

`_progress.json` 至少维护 `completed_ranges`、`pending_ranges`、`failed_ranges`、`retry_reasons`。

- 已成功范围不得重读。
- 同一范围重试前先记录原因；只允许执行失败、定位失败、schema 失败、证据冲突。
- “更准确”“再看一遍”“上下文丢了”不是合法原因；上下文丢失时读状态快照恢复。
- 机械索引、边界、哈希只生成一次并复用。

## 落盘纪律

每批执行：临时文件 → schema 校验 → 校验和 → 原子替换 → 最后更新进度。禁止：

- 直接追加半个 CSV 批次。
- 把机械摘句当语义产物。
- 保存逐章临时摘要等没有下游消费者的文件。
- 用对话历史代替 `_state_snapshot.json`。

## 中断恢复

恢复时只读取进度 JSON、状态快照和待处理范围。先校验源/边界哈希与产物校验和，再从最近未提交范围继续。成功范围不重新加载进上下文。

## 完成回执

报告实际语义块数、重试范围、复用范围、生成产物和未覆盖边界；不以“处理了多少章”暗示逐章语义阅读。
