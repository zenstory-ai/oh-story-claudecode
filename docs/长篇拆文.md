# 长篇拆文

## 功能请求

### 真实使用问题

旧流程在黄金三章之后继续生成逐章详细摘要、人物卡、剧情卡和设定卡。面对几十万到数百万字作品时，同一章会在索引、逐章分析和全局聚合阶段被重复读取，运行时间与上下文消耗随章节数快速增长；中断后又缺少可校验断点，容易从头重跑。写作消费者真正需要的是全局机制、结构块、证据边界，以及能够回到原文的稳定定位，不需要一套重复的逐章正文分析。

### 可验收结果

- 保留黄金三章深度拆解与快速预览停靠点。
- Stage 2 对全文只做一次机械索引，固定为五列 `chapter_index.csv`。
- Stage 3 只对可变长度结构块做语义读取，固定为 20 列 `structure_blocks.csv`，记录完整因果循环、关系迁移和节奏锚点。
- Stage 4–6 仅生成三个当前契约文件：`六维拆书.md`、`爆款机制.md`、`证据与边界.md`。
- 不重新生成非黄金三章的逐章详细正文、人物卡、剧情卡或设定卡。
- 中断后只从最近一次已校验的 JSON checkpoint 继续；源文件、章节边界或产物校验和变化时拒绝静默续跑。
- 写作与导入只把五列索引用作原文定位，不从 CSV 推测或重建历史事实。
- 自定义 `设定/文风.md` 始终保持最高风格优先级。

## 六维拆书设计

### 输出契约

```text
拆文库/{书名}/
├─ 原文/
├─ 概要.md
├─ 快速预览.md
├─ 章节/第1-3章_深度拆解.md
├─ chapter_index.csv
├─ structure_blocks.csv
├─ 全局分析/
│  ├─ 六维拆书.md
│  ├─ 爆款机制.md
│  └─ 证据与边界.md
├─ _progress.json
└─ _state_snapshot.json
```

`六维拆书.md` 是自包含主报告，统一承载故事模型、人物、关系图谱、冲突、双时间线与信息差、三维节奏，不要求消费者再拼接多个分散报告。`爆款机制.md` 固定提炼三个机制，记录读者需求、表层表现、因果链、心理机制、可替换项、成立条件和误用风险。`证据与边界.md` 统一记录 A/B/C 置信度、证据定位、反例、不可泛化条件和模仿风险。

### 一次索引与结构块

五列索引字段固定为：

```text
chapter,title,source_locator,char_count,status
```

索引只负责章节边界和原文 locator，禁止写入事件、人物、情绪、钩子或推测性摘要。结构块字段固定为：

```text
block_id,chapter_range,block_name,initial_gap,goal,pressure,turning_point,payoff,remaining_hook,state_change,main_characters,evidence_locator,plot_intensity,emotion_type,emotion_intensity,description_density,relationship_delta,rhythm_anchors,confidence,status
```

结构块以一个完整的“缺口—目标—压力—转折—兑现—剩余钩子”循环为边界，不按固定五章或十章切分。关系迁移和峰谷锚点在首次语义读取中同步保存，后续全局聚合直接消费该结果，不再二次阅读全文。

### 断点与运行边界

- `_progress.json` 保存 schema、契约版本、源文件哈希、章节边界哈希、已提交批次、待处理范围与所有主产物校验和。
- `_state_snapshot.json` 保存章节边界、别名、结构块进度、未决信息和证据 locator。
- 写入采用临时文件后原子替换；只有文件存在、表头正确、行数与校验和一致时才标记批次完成。
- 续跑前校验源哈希、边界哈希、schema、契约版本与已有产物；不接受旧 Markdown 进度文件或历史 schema 的隐式混合迁移。
- 长任务使用空历史 worker 和已落盘 checkpoint 传递状态，禁止把上轮全文或聊天历史复制给下一批。

## 消费方调整

### story-long-write

- 先读 `爆款机制.md` 与 `六维拆书.md` 的三维节奏，再用结构块选择剧情单元。
- 只有需要事实核证或临时文风时，才用五列索引把章号映射到 `source_locator` 并定点读取主对标原文。
- 副对标最多读取两本书的三个全局文件，不读取副对标原文。
- `设定/文风.md` 含实质内容时仍是权威风格基，不被对标机制覆盖。

### story-import

- 复用 schema v4 / contract v5.0 的完整分析产物。
- 从结构块选范围，用五列索引定位并回读原文后恢复状态。
- 禁止从索引标题或 CSV 字段凭空重建角色历史、伏笔状态或叙事事实。

## 兼容与迁移

旧逐章摘要、旧角色/剧情/设定目录、旧报告及拆分的时间线、节奏和关系文件可作为只读遗留保留，但不属于当前契约，也不会被当前消费者优先读取。已有项目升级后应重新运行 `story-setup` 并新开会话；旧 checkpoint 不会自动混入 schema v4。
