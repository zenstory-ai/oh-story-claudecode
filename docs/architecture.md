# 工作原理：Agent、Hooks 与项目结构

[English](architecture_EN.md)

Oh Story 把长篇写作拆成「文件系统当记忆 + 专业 Agent 分工 + 自动化门禁」三层。
概览见 README 的[这是什么](../README.md#这是什么)。

## Agent 体系

写作 skill 按需调用 7 个专业 Agent；当前工具未注册这些 Agent 时，按 skill 规则由当前对话直接完成。表中模型为 Claude Code 默认配置，其他编程 Agent 按各自适配设置运行：

| Agent | 模型 | 职责 |
|:------|:-----|:-----|
| **story-architect** | Opus | 故事架构 · 题材定位、大纲结构、钩子/反转设计、情绪弧线 |
| **character-designer** | Sonnet | 角色设计 · 角色档案、语言风格、动机链、对话创作 |
| **narrative-writer** | Opus | 叙事写手 · 正文写作、去AI味、格式合规 |
| **consistency-checker** | Haiku | 一致性检查 · 事实冲突扫描、伏笔追踪、S1-S4 分级报告 |
| **story-researcher** | Sonnet | 资料研究 · CDP 搜索+正文提取、多源交叉验证、结构化参考文件输出 |
| **story-explorer** | Haiku | 故事查询 · 角色/伏笔/设定/进度只读查询，日更上下文快速加载 |
| **chapter-extractor** | Haiku | 章节提取与旧成果整理 · 章节事实、逐章情节点与跨章剧情线 |

Agent 按任务读取 `references/` 中的角色设计、对话、反转等资料；未读取的文件不进入上下文。

## 自动化 Hooks

`/story-setup` 为 Claude Code 部署统一 Node.js 18+ Hook 运行时（`run-story-hook.sh` + `story_hook_cli.js` + 与 Codex/OpenCode/ZCode/Antigravity 共享的 `story_hook_core.js`），覆盖 8 个自动化事件：

| 事件 | 触发时机 | 功能 |
|:-----|:---------|:-----|
| `session-start` | 会话开始 | 显示分支、进度快照、拆文状态与部署自检 |
| `detect-story-gaps` | 会话开始 | 检测设定缺口、大纲缺失、伏笔断线与跨批连续性 |
| `session-end` | 会话结束 | 按需记录会话日志到 `追踪/session-log.txt`（需 `STORY_SESSION_LOG=1`） |
| `pre-compact` | 上下文压缩前 | 保存进度快照路径和行数摘要 |
| `post-compact` | 上下文压缩后 | 提示读取进度快照恢复上下文 |
| `pre-tool-commit-advisory` | git commit 时 | 检查硬编码属性、设定必填字段（仅警告，不阻断） |
| `pre-tool-prose-guard` | 写正文前（Bash/Write/Edit） | 检测到未展开 shell 变量、缺对应细纲/空壳细纲（<30 字）、缺 `小节大纲.md` 或 `_tracking-state.json` 缺失损坏时硬阻断；上一章未清毒句式、跳章未提交或手改 `上下文.md` 状态修订改为非阻断写前提醒 |
| `post-tool-prose-check` | 正文写入后（Write/Edit） | 轻量扫描截断、工程词和毒句式（提醒，不阻断；字数由写作流程交付前统一测量） |

## 项目文件结构

长篇项目将设定、大纲、正文与追踪分开维护。每写一章只读取本章用得上的文件，写完把实际发生的变化提交到追踪，不用靠越滚越长的聊天记录记事。

仅 `story-long-write` 与 `story-short-write` 管理和查询作者记忆；`story` 只路由相关请求，去 AI 味与审查沿用写作流程传入的文风要求。

作者记忆独立于单本小说的事实追踪，分两级存放、记忆随书走：工作区 `.story/作者记忆/` 存全局、题材、流程偏好（编号 `AP`），每本书目录下的 `.story/作者记忆/` 只存这本书的偏好（编号 `BP`）。两级目录结构相同：

```text
.story/作者记忆/
├── _author-memory-state.json  # 作者记忆主数据
├── 作者画像.md               # 已确认、可用于创作的偏好
├── 待确认.md                 # 作者原话范围含糊的候选与冲突候选
└── 变更记录.md               # 可查的替换与撤回记录
```

只记作者明确表达的偏好，不从反复修改或成稿推断。

**长篇：**

```
{书名}/
├── 设定/
│   ├── 世界观/          # 背景、力量体系等，按主题拆文件
│   ├── 角色/            # 每个人物一个文件（江晨.md、钟嘉嘉.md）
│   ├── 势力/            # 每个势力/组织一个文件（火箭军文工团.md）
│   ├── 关系.md          # 角色关系映射
│   └── 题材定位.md      # 题材核心梗+对标分析
├── 大纲/
│   ├── 大纲.md          # 全书卷级结构
│   ├── 卷纲_第一卷.md   # 每卷一个：爽点节奏+情绪弧线+人物弧线+伏笔+反转
│   ├── 细纲_第001章.md  # 每章一个：内容概括+多线情节+人物关系/出场顺序+钩子
│   └── ...
├── 正文/
│   ├── 第001章_章名.md
│   └── ...
├── 对标/                # 对标参考（结构化子目录从拆文库同步）
│   └── {对标书名}/
│       ├── 原文/            # 对标书原文章节
│       ├── 角色/            # 结构化角色卡（从 analyze 输出同步）
│       ├── 剧情/            # 结构化剧情线/节奏/情绪模块（从 analyze 输出同步）
│       ├── 设定/            # 结构化设定（从 analyze 输出同步）
│       ├── 文风.md          # 日更前读取，用来贴近对标书文风
│       └── 拆文报告.md      # analyze skill 输出的拆文报告
├── 追踪/                # 文件优先的连载状态
│   ├── _tracking-state.json # 追踪主数据（不直接放进正文提示词）
│   ├── 上下文.md        # 自动生成的续写状态卡
│   ├── 逐章记录/        # 每章影响后续连载的变化记录
│   ├── 角色状态/        # 自动生成的核心角色状态卡（江晨.md、钟嘉嘉.md）
│   ├── 伏笔.md          # 自动生成的伏笔当前清单
│   └── 时间线/          # 自动生成的作者真相.md + 读者已知.md
├── 参考资料/            # story-researcher 输出的研究资料
│   └── {topic}.md       # 按研究主题拆分
```

**短篇：**

```
短篇/{标题}/
├── 设定.md              # 故事核、人设、平台基调与反转设计
├── 小节大纲.md          # 8 节结构 + 情绪曲线
├── 正文.md              # 完成稿
└── 拆文库/              # 如有参考小说（analyze 输出）
    └── {书名}/
        ├── 拆文报告.md
        ├── 情节节点.md
        └── 写作手法.md
```

短篇目录里的 8 节只是示意，实际节数按确认好的设定和篇幅要求定。

**拆文库：** 拆文 skill 默认写到项目根目录 `拆文库/{书名}/`，按角色、剧情、设定、章节分目录存放；长篇的 `剧情/` 下含 `节奏.md` 和 `情绪模块.md` 两份核心底稿。写作 skill 优先从本书 `对标/{书名}/剧情/` 等子目录读取，本书没有时再去项目根的 `拆文库/` 读取；始终以本书自定义的文风为准，对标书只补没写到的地方。

**`.active-book`：** 项目根目录的文本文件，内容是当前活跃书目的**相对路径**（如 `长篇/我的小说`），hook 和写作 skill 据此定位当前项目。
