# 三层灵感库

## 功能请求

### 真实使用问题

六维拆书能够解释单本作品的结构与爆款机制，但写作阶段如果直接读取多本拆文报告，会重复占用上下文，也很难稳定检索“当前题材、情绪、关系动作和剧情功能真正需要哪条机制”。如果在拆文完成后再次读取原文或逐块重新概括，又会把已经节省下来的运行时间和 token 重新消耗一遍。

### 可验收结果

- 每个有效结构块对应且只对应一个原子灵感，不增加第二次结构块语义读取。
- 同一本小说的相似原子合并为单小说层，保留来源闭包和反例，不把相邻结构块简单拼接。
- 跨书层只聚合可能复用的机制，并使用受控标签供写作按任务召回。
- 写作只读 Top 3–8 张 active 跨书卡，不把原子层或单小说层整库塞入上下文。
- 原子层和单小说层的公共索引标签留空，避免写作绕过跨书层。
- 所有卡片能回链来源，小说数、原子数、状态和标签可以机械验证。
- 中断后从最近已提交层继续；结构块哈希不变时复用原子层。

## 三层模型

| 层级 | 英文名 | ID | 输入 | 作用 |
|---|---|---|---|---|
| 原子灵感 | Inspiration Atom | `IA-001` | 一个 `status=ok` 结构块的五个灵感字段 | 保存最细机制链、读者效果、迁移边界与风险 |
| 单小说灵感合并 | Novel-level Merge | `NM-001` | 同一本书内机制同构的多个 IA | 合并单书重复规律，保留变体、反例与完整来源闭包 |
| 跨书灵感聚合 | Cross-Book Aggregation | `CBA-001` | 不同小说中可能同构的 NM | 形成可按标签检索、可直接供写作决策的公共机制卡 |

目录契约：

```text
灵感库/
├─ 原子灵感/{书名}/IA-*.md
├─ 单小说灵感合并/{书名}/NM-*.md
├─ 跨书灵感聚合/CBA-*.md
├─ 灵感索引.csv
└─ _progress.json
```

## 一次语义读取

三层灵感库不重新读取原文或 `chapter_index.csv`。六维拆书 Stage 3 在首次结构块语义读取中同步写入：

```text
inspiration_title
inspiration_mechanism
inspiration_reader_effect
inspiration_transfer_boundary
inspiration_risk
```

五个字段必须去除原作角色名、独有设定、原句和具体事件链。`render-atoms` 只做确定性机械渲染：一个有效结构块生成一个 IA，缺字段即回到对应结构块修复，不允许后处理阶段调用模型补写。

## 聚合边界

### 单小说层

- 一次读取本书全部 IA 后完成聚类，不为每个簇分别调用模型。
- 只有机制因果链、读者效果和成立条件同构时才合并。
- 每张 NM 保存变体参数、成立条件、反例、不可照搬边界及来源 IA。
- 来源闭包必须包含全部成员 IA；新增、删除或拆分原子后重新核对统计。

### 跨书层

- 先用 NM 的轻量索引筛候选，只读取可能匹配的 active CBA，不遍历全部卡片。
- 单书支持的 CBA 最多激活 3 张并标注“单书假设”；两部及以上独立来源才标“跨书重复验证”。
- 每张 CBA 必须自包含机制链、可变参数、成立条件、反例、迁移边界和风险，写作不需要沿链接下钻。
- CBA 来源必须覆盖成员 NM 及其 IA 闭包；`novel_count` 与 `atom_count` 由来源集合机械计算。

## 标签与召回

CBA 使用受控轴，不使用无边界自由散词：

- 题材
- 读者需求
- 情绪
- 关系动作
- 剧情功能
- 节奏位置
- 适用阶段
- 风险

索引按精确轴值匹配优先，再按匹配分、小说数、原子数和 CBA ID 稳定排序。设定/卷纲最多读取 8 张，正文单章默认读取 3 张；候选不足时如实少读，不以 IA/NM 凑数。自定义 `设定/文风.md` 仍是最高风格优先级，CBA 只影响机制选择，不作为文风样本。

## 索引与断点

`灵感索引.csv` 固定字段：

```text
item_id,layer,title,source_book,path,source_ids,novel_count,atom_count,tags,status
```

- IA/NM 的 `tags` 必须为空；只有 CBA 可被公共标签召回。
- `validate` 检查路径、ID 前缀、悬空来源、来源闭包、计数、标签轴与 active 状态。
- `_progress.json` 保存输入结构块校验和、已渲染 IA、已合并小说、已更新 CBA、索引校验和与下一操作。
- 每层先写临时卡并验证链接，再原子替换；中断只重跑未提交层。

## 验证

- Skill frontmatter、references 可达性与无跨 Skill 路径引用检查。
- 25 列结构块表头与五个灵感字段非空检查。
- 一个结构块只生成一个 IA、重复渲染幂等和索引单次写入回归。
- IA/NM 禁止公共标签、CBA 必填轴、active 过滤、稳定 Top-K 回归。
- CBA 来源闭包、`novel_count`、`atom_count` 与悬空链接检查。
- Codex / OpenCode / ZCode / Antigravity / OpenClaw / Reasonix 的 15 Skill 映射与生成文件同步检查。

Windows 本地无 Bash 或 Node 时运行 Python 子项；完整适配检查交由上游跨平台 CI 执行。
