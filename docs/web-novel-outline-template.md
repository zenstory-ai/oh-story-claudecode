# 网文大纲怎么写：长篇小说大纲模板与分卷范例

网文大纲不要从第一章一路顺写。先用一句话定下主角要完成的事，再确定结局和各卷高潮，倒推每卷必须改变的局面；最后才安排可调整的场景。全书方向要稳定，分卷路径可修，具体对白和小场面留到写作时决定。

## 长篇大纲先写哪一层？

大纲用来稳住长篇方向，不用提前把正文写出来。一般分三层，叫什么名字随作者习惯：

| 层级 | 用途与调整范围 |
|---|---|
| 全书骨架 | 主角最终要办成什么事、为什么非他不可；定下大方向，中途要改时先核对已写章节和读者期待。 |
| 分卷路线 | 这一卷要把局面推到哪一步、卷末高潮怎么见分晓；具体走法可调，前面立住的前因别推翻。 |
| 场景备忘 | 打算用哪场戏、哪条线索或哪段对话过节点；随写随改，还没写进正文的设想不算既定事实。 |

这与[细纲模板](https://zenstory.ai/zh/oh-story/chapter-outline-template)分工不同：全书大纲管大方向，细纲管近期几章怎么下笔。本文推荐先定高潮再倒推，你也可以从人物或开篇试写摸索起步，写顺了再收拢终点；别为了填满表格硬编用不上的秘密、能力或支线。

## 可复制的长篇小说大纲模板

按下面顺序填，不必一次填满所有支线：

> **核心卖点**：读者持续追更图的是哪口独特体验？
>
> **主角起点**：他眼下缺什么、受什么掣肘、最怕失去什么？
>
> **全书目标**：他最终要办成的一件能看出成败的事。
>
> **终局选择**：全书高潮时他得在什么之间二选一？这一选怎么看出他跟开篇不一样了？
>
> **结局状态**：外部局面、核心关系、主角自己的想法最后各落到哪儿？
>
> **分卷卡**：本卷目标｜主要障碍｜新策略｜高潮对决｜局部兑现｜遗留压力。
>
> **跨卷线**：主线怎样升级；哪条关系或秘密在哪卷推进、在哪卷揭晓。
>
> **当前写作窗口**：只细化接下来几章的目标、阻力、结果和章尾悬念。

先写终局选择与每卷高潮，再倒推需要提前建立的人物、能力、关系和证据。这样伏笔来自结局需要，避免写到哪儿临时塞到哪儿。

## 原创分卷范例：《潮汐修复师》

**原创设定《潮汐修复师》**：许澄能从接触过的旧机械听见故障前后的声音，不能直接知道谁换了零件或为何换件。沿海城市的大潮将至，她想修复主闸并查清连环故障的换件经过。维修组负责施工资格、配件与停闸安排；档案管理员提供已登记记录；市政议事会决定采用怎样的维护办法。许澄不能靠能力自行取得这些权限。

下面是待写的四卷设计。先定最终需要完成的动作，再把条件分到前卷：

| 卷 | 目标、高潮与下卷承接 |
|---|---|
| 盐湾旧闸 | 挤进维修组。许澄指出支闸有异常，维修组查过才同意她上手；支闸修好，组长点头让她进后续项目。可拆下来的零件编号和登记对不上，线索指向泵站记录。 |
| 城南泵站 | 查清零件是怎么换的。她和档案管理员把借出、采购、实际装配三份记录摆在一起，再请维修组复核，证实这批零件没按记录安装；为什么这么换，还说不准。承包方撤回了原先的推荐，主闸旧图却缺了一页，下一卷得去补齐来源。 |
| 退潮档案 | 找回缺页和当年的处置记录。同伴坦白缺页一直在自己手里，交给管理员入档；许澄这才知道，父亲当年按临时防线的安排扛下维修责任，才被人误解，但要接着追查还缺完整记录。两人约好以后一起核对资料，信任能不能回来，看后面怎么做。大潮偏偏提前，施工时间更紧。 |
| 封潮之夜 | 维修组备齐匹配的配件、批准停闸窗口，许澄选择先下去抢修，完整记录留到会后公开核对。维修、试闸、撤离都办完，议事会才听她说明，讨论通过公开维护记录的办法；结尾落在下一次检修的实际登记上。材料交上去，不等于所有责任都有了定论。 |

父亲当年的经历、替换配件、停闸工期，以及谁有权拍板新维护办法，都要在前面各卷提前铺好。听见机械异响只是查线索的由头，代替不了装配台账、现场复核与旁人的表态。终局把她的手艺、核实的记录和攒下的合作关系拧到一处用，别等最后一场才凭空送权限、送资源。

眼下只需把第一卷的“申请参与—核查误判—拆件发现—支闸抢修”排细；后面的对白、现场动作和小波折留到写那一卷细纲时再定，不用现在把第四卷填满。

## 从空白到可写：从结局倒推关键情节

先定主角的起点和终点，拉开前后反差；再想清楚全书最大冲突里他得做什么取舍，别只写一句笼统的“终极决战”。接着倒推：他凭什么敢做这个决定？眼下还缺的本事、人脉和铁证，就拆成前面各卷要拿下的节点。

每卷也照这个路子排：先定卷末高潮，再给卷初立一个够得着的阶段目标，中间摆上逼主角换打法的硬钉子。支线只有帮得上主线、给主角添代价或最后并回主线时才留。写到中途跑偏了，先看当前行动还在不在推进本卷目标，不用动不动推翻整卷重来。

## 长篇大纲常见失败与改法

| 问题 | 检查与修正 |
|---|---|
| 把“升级变强”当主线 | 为什么会卡：升级只是手段，看不出终点在哪；改法：写清“变强之后到底要办成哪件事” |
| 从开头顺推到哪算哪 | 为什么会卡：写到后段高潮发现缺铺垫；改法：先定高潮抉择，再往前倒推条件 |
| 每卷只是换地图重来 | 为什么会卡：打完一轮回到原点，没有积累；改法：让上一卷的结果引出下一卷的新麻烦 |
| 支线很多但彼此不碰 | 为什么会卡：字数涨了，主线原地踏步；改法：写明每条支线最后帮了、挡了还是改写了主线 |
| 大纲写成场景全文 | 为什么会卡：写正文冒出好点子却塞不进去；改法：大方向定死，具体场面留出腾挪余地 |

判断大纲是否够用，只需看你能否回答：下一阶段追求什么、谁在阻挡、失败会失去什么、高潮将改变什么。

## 用 Oh Story 怎么做

装好本仓库的 skill 后（对应 [story-long-write](../skills/story-long-write/SKILL.md)）：在 Claude Code 里说：“用 /story-long-write 只做长篇大纲：先定核心卖点、全书目标与终局选择，再倒推分卷高潮和阶段节点；具体场景只细化当前写作窗口，不写正文”（Codex 里写作 `$story-long-write`）。

## 常见问题

**细纲和章纲有什么区别？**

细纲把每章要交付的目的、效果和可执行情节点写清，是 Oh Story 正文写作的章节蓝图；章纲是分配近期关键事件、伏笔与章末期待的粗纲。已有大纲和细纲足够时，可以省略额外的章纲，不能用分卷路线代替所需细纲。

**长篇大纲写完还能改吗？**

可以。具体路径和场景应随正文修订，但核心卖点、全书目标和已建立的因果不能无代价改掉。先判断变化发生在哪一层，只改必要层。
