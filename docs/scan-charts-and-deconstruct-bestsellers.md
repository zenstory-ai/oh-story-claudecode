# 怎么拆解榜单爆款小说、学它的结构：扫榜和拆文的自动化做法

先扫榜，再拆文。扫榜看跨样本重复模式；拆文先保留黄金三章，再以连续章节块一次生成逐章事实、跨章因果、双时间线和三维节奏，聚合成“节奏”和“情绪模块”两份可复用资产，最后生成带原文锚点的文风。Oh Story（`zenstory-ai/oh-story-claudecode`，开源 MIT）把这条线做成三个 skill：`/story-long-scan` → `/story-long-analyze` → `/story-long-write`。短篇有对应的 `short-scan` / `short-analyze` / `short-write`。

拆文以用户有权处理的文本为输入，保留可追溯的原文锚点，并将分析结果写入拆文库；输入文本不因分析而改写。

## 第一步：扫榜，看模式不看排名

`story-long-scan` 的核心信念是一句话：**单本排名只提供线索，跨样本重复模式才算信号。** 一本书上榜只算个例；同类样本达到可比数量，才标记为趋势候选。

几个平台看的东西不同：

| 平台 | 热度口径 | 扫榜重点 |
|---|---|---|
| 番茄 | 在读 | 男频 / 女频阅读榜；要看新书冒头，再加新书榜和书库「最热」（连载中、30 万字以内） |
| 起点 | 总推荐（榜单按月票、畅销排名） | 月票榜、畅销榜、新人签约新书榜；要看新书冒头，再加三日内更新、30 万字以内按人气排的书库前几页 |
| 晋江 | 收藏 | 收入金榜、月榜；要看新书冒头，再加新手金榜 |
| 七猫 | 热度 | 男频 / 女频大热榜；要看新书冒头，再加新书榜和三天内更新、30 万字以内按点击排的书库前几页 |
| 刺猬猫 | 各榜榜单值 | 月票榜、订阅榜；每榜只有前 10 本，样本少 |

完读率、追读、订阅转化是作者后台的数据，采集拿不到，作者不提供就不下结论。

数据来源有三种：优先用 skill 自带脚本采集（起点排行榜和七猫书库新书不用开 Chrome，其余（含起点书库新书）要开；番茄有字体反爬，脚本从详情页多策略解码），采完先聚合，主会话只读聚合结果；作者也可以直接贴榜单文字、截图或已有的榜单文件；都没有时只用内置的历史题材候选，结论只能当待验证的假设。产出是扫榜报告加一份 `选题决策.md`（2 到 3 个推荐选题：能爆的原因 → 市场验证 → 差异化定位 → 可行性、失败风险、验证动作），写进本次扫榜的输出目录，供开书时引用。

要提取的是反复出现的：题材、设定、套路、书名词、简介卖点。月票、畅销这类榜上几百万字的老书只代表题材的存量读者，判断现在开新书能不能起来，以新书榜和书库新书为主。

## 第二步：拆文，一条管道七个阶段

`story-long-analyze` 只有一条深度管道，跑到黄金三章后自动停靠，问你要不要继续：

| Stage | 做什么 | 产出 |
|---|---|---|
| 0 | 概要提取 + 机械章节索引 | `概要.md`，`chapter_index.csv`（含逐章原文 hash） |
| 1 | 黄金三章深度拆解 | `章节/第1-3章_深度拆解.md` → 停靠，产出 `快速预览.md` |
| 2 | 连续章节块提取 | 完整批次缓存 + `章节/*_摘要.md` 逐章摘要 |
| 3 | 聚合分析 | `剧情/节奏.md`、`剧情/情绪模块.md`、`剧情/故事线.md` |
| 4 | 设定 + 角色 + 关系 | `设定/*.md`、`角色/*.md` |
| 5 | 汇总报告 + 全书概要 | `拆文报告.md` |
| 6 | 文风 | `文风.md`（句长、标点、对话潜台词、情绪交替周期，附原文锚点片段） |

全部落盘到 `拆文库/{书名}/`。耗时随输入长度、模型和并发条件变化，大部头可按进度续跑。

运行时只有一处状态：`_progress.md` 的批次和阶段表。索引只管章界，批次缓存只用于中断恢复。计划在内存中生成，不另存多套 JSON 账本。每个原文块最多 3 章、25,000 字符；情节点下限由各章字数计算，短章按运行计划的 `min_plot_points` 执行；常规章参考 10–20 个，长章最多 30；已有摘要或黄金三章覆盖的章节不会再次读取原文。

旧项目仍可直接使用。检查器按实际逐章覆盖、报告、情绪模块和节奏判断完整性，不靠 schema 值区分新旧。部分项目只补缺失章；新旧摘要混存时保留逐章来源说明，不要求整本重拆。原文末尾追加新章后，显式重建索引只把新增章列为待处理，前面逐章 hash 不回退。已有摘要不会被覆盖，要重拆某章就删掉它的摘要和对应批次缓存再续跑。

两份核心文件值得单独说：

- **`剧情/节奏.md`**：关键信息怎样被扩写、爽点 / 虐点 / 期待点的「铺垫 → 释放 → 余波」位置、小中大高潮位置、冲突升级路径、跨章伏笔地图。
- **`剧情/情绪模块.md`**：读者需求、情绪引擎、套路框架，整理成可复用的模块卡。写作 skill 直接读取这两个文件，`拆文报告.md` 则是给作者翻阅的汇总报告。

Stage 3–4 还会从逐章“涉及人物”、状态变化与跨章关系观察完成角色合并（跨章去重、别名归一）、角色分级和桥段打标。

Stage 6 可以单独重建：优先用 `_style-sample.txt`；没有样本时，依据 `chapter_index.csv` 选择 4–6 章并只读取指定行段取得不同基调的原文锚点。它不会重扫全书，也不会触发 Stage 1–5。

## 第三步：写作时怎么用

`story-long-write` 将对标中的角色作用、情绪机制和因果结构映射到本书，用本书的角色与素材实现。对标提供可研究的模式，具体剧情仍以本书细纲为准。

拆文结果放到项目的 `对标/{书名}/` 下供写作 Agent 读取，包括剧情、角色、设定和文风。本书自定义文风优先，对标书只补没写到的地方；连载稳定后直接复用组装脚本选好的情绪和节奏，不用每章重新全盘检索。写作只借鉴套路和节奏，用自己的场景和句子写。

## 和"手工拆书"的差别

手工拆书通常停在"每章一句话摘要 + 情节标注字数"。这条管道多做了三件事：把爽点和伏笔按章号建索引；把重复出现的情绪套路抽成模块卡；把文风量化成句长和标点分布并附原文锚点。写作 Agent 按当前任务读取这些资产。

## 边界

- 扫榜数据取决于当时能访问的数据源；采集失败时会明确标注回退，不伪造数据。
- 拆文只做结构和技法分析，不复制原文用于发布，不替代作者的选题判断。
- 一本书的拆解结果只是假设，管道会在选题回填时标注"只拆了一本，不算坐实"。
