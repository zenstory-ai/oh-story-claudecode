# 小说人物设定集怎么整理：角色、时间线与人物已知信息模板

长篇的设定集要把稳定事实和随剧情变化的状态分开放。角色卡存身份、底线和长期目标；当前状态只记位置、资源、关系、已知信息和未结事项的最新情况；时间线按客观顺序记事件，角色知道什么、读者知道什么另外记。剧情一变，只改对应的那一处，免得几份文件各说各的。

## 一套够用的设定集

| 模块 | 存什么 | 什么时候改 |
|---|---|---|
| 角色卡 | 身份、经历、能力边界、长期目标 | 设定被正式改动时 |
| 当前状态 | 位置、资源、关系、已知、未结事项 | 每次发生有效变化时 |
| 关系表 | 双方的承诺、债务，公开和私下的立场 | 关系上的行动落地时 |
| 作者时间线 | 客观事件的顺序与日期 | 新事实确认时 |
| 读者已知 | 正文已经揭示的内容 | 一章写完时 |
| 世界规则 | 适用条件、例外、代价 | 规则建立或修订时 |

每条事实只在一个地方定准，其他文件要么引用它，要么只记最新结果。

## 可复制的角色状态模板

```md
截至章节：
当前位置与正在做的事：
当前目标：
能力与可用资源：
关键关系：（每个重要对象写承诺、债务和边界）
本人已知 / 误信 / 隐瞒：
未结事项：
本次变化来源：（正文哪一章哪一段）
```

只给后面还会出场的角色建状态页，一次性的路人留在章节记录里，设定集才不会越写越肿。修订旧章时，从改动的那一章往后重算受影响的状态。

## 原创填写示例：旧水站管理员

```md
截至章节：第十二章
当前位置与正在做的事：旧水站值班室，准备关闭北线阀门
当前目标：在检修队到达前，证明污染来自回流管
能力与可用资源：值班钥匙、过去三日的压力表；没有取样权限
关键关系：欠居民代表一次公开说明；和站长的口头保密约定已破裂
本人已知 / 误信 / 隐瞒：已知北线夜间压力异常；误信检修队已收到完整记录
未结事项：谁删掉了凌晨的数据；钥匙为什么被人复制过
本次变化来源：第十二章值班室一场
```

这张卡没写童年和外貌，只留下一章会限制主角行动的事实。

## 更新一条变化，别把其他事实清空

接着上面的例子。第十三章正文里，居民代表在值班室伸手要钥匙，主角递过去，压力表留在自己面前，说公开说明还欠着、自己继续核记录。这场交接只改变了钥匙在谁手里：

| 状态 | 第十二章 | 第十三章 |
|---|---|---|
| 钥匙 | 主角持有 | 已交给居民代表，注明正文交接处 |
| 位置与权限 | 在水站，没有取样权限 | 仍在水站，权限没变 |
| 关系与未结事项 | 保密约定破裂，复制钥匙的事没查清 | 两项都保留，不会因为交了钥匙就自动和解 |
| 已知与误信 | 仍误信检修队有完整记录 | 本章没有纠正，照旧保留 |

更新时只改钥匙那一行，其他各项原样带到第十三章。同样，居民代表拿到钥匙，不等于居民都知道了完整调查；只记已经发生的交接、谁在场、实际说了什么。大纲里打算以后发生的事，另外存在大纲，不写进状态。

## 发现冲突时怎样分级

先找正文里的明文事实，再核对规则条件、时间顺序、因果和代价。直接互相矛盾或破坏主线的冲突先处理，隐藏的因果断裂其次，外貌上的小差异单独记下，伏笔超期只算提醒。每条问题都写清前提、触发它的事件和矛盾点。设定集负责提供证据，哪条剧情更好由作者判断。

## 用本仓库的 skill 怎么做

上面是手工维护的做法。用 Oh Story 写长篇时，这些状态由 [story-long-write](../skills/story-long-write/SKILL.md) 维护：每写完一章，Agent 只提交这一章的变化，脚本据此更新唯一的底账文件，再自动生成书目录 `追踪/` 下的角色状态、伏笔、作者时间线和读者已知等文件。这些自动生成的文件不要手改，手改后会在核对时报错。四层文件怎么分工，见 [AI 写长篇小说怎么不崩人设](ai-long-novel-character-consistency.md)。

书稿不是在 Oh Story 里写的，先用 `/story-import` 导入，它会把已有章节整理成带设定、大纲和追踪的项目。已经在 Oh Story 项目里、想对着正文核一遍设定时，在 Claude Code 里可以这样说（Codex 里把 `/` 换成 `$`）：

> 用 /story-long-write 对照已写的正文核对设定集，分成稳定设定、截至第 12 章的完整状态、客观事件和各方已知。每项变化都引用正文，只更新变了的部分，其他仍然成立的事实保留。本轮不写正文。

核对工具能确认各个追踪文件和底账一致，但不能替你判断小说本身有没有漏写或记错，最后仍要作者读一遍。
