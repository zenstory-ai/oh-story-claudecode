# 长篇规划范围与正文切换验证（#419）

这是有界真实 Claude CLI 验证记录，不是默认 CI 单测。没有用源码或 Markdown 关键词断言冒充行为回归；自动 CI 另验证引用、预算、部署及现有写手/追踪脚本。

## 方法与环境

- Claude Code `2.1.267`，本次 init 返回模型 `claude-sonnet-5`，启动参数为 `--model sonnet --effort low`。别把别名当成跨日期固定模型。
- 每个项目使用临时副本，只装本次 `story-long-write`；`--setting-sources project`、空 MCP 配置、`disableAllHooks: true`，无专业 agents。init 的 `plugins=[]`；CLI 内置技能仍可见，大纲/转正文用例实际调用本地 Skill，讨论/局部修改用例显式读取副本。
- 测试副本启用 Bash sandbox，配置禁网络、个人路径读取和 unsandboxed 命令；设置读取之外，授权工具为 Read/Glob/Grep/Write/Edit/Bash/Skill。纯讨论没有 Bash/Skill，Write/Edit 仍可用，因此“没有写入”不是靠禁用写工具得到的。
- 大纲主链基线前两轮预算为 `$0.45 / $0.38`，候选首轮为 `$0.55`；各例设子进程超时及费用上限，首章修复复测为 360 秒 / `$1.4`。预算截断记为截断，不记为成功；实际消费可能超过上限一个请求。
- 不比较 token、速度或正文质量。有限模型样本也不等于所有 Runtime 的硬权限保证。

## 请求与验收

主链首轮原话：

```text
请实际执行 $story-long-write，帮我给一本长篇悬疑升级流写大纲，先不要写正文。书名《雾港回声》：主角能听见旧物残留的一句话，核心矛盾是追查姐姐失踪并揭开港城记忆交易；目标约120万字，三卷。信息足够，不要向我提问，缺失细节按 skill 的创作自主权处理。请把产物落到当前测试工作区内的同名项目目录。
```

在同一 session 用 `--resume` 依次输入 `继续`、`按这个来`，不是新开无上下文会话。每轮记录实际工具调用和产物清单，禁止将“不写正文”的模型自述代替文件验证。

| 用例 | 检查的实际行为 |
|---|---|
| 大纲主链 | 只产出设定/大纲/卷纲；不自动细纲、正文、追踪；完成后的确认不扩范围 |
| 结构讨论 → 按这个来 | 实际讨论两种结构；所有文件 SHA256 不变、Write/Edit 调用为 0 |
| 修改第 12 章细纲 | 只改目标约束；其他细纲、卷纲、正文、追踪全部字节不变，无正文备份 |
| 已有纲、无正文/追踪 → 明确写首章 | 首次正文写入前完成 references 和 tracking init/check；写后有有效追踪提交，不仅是正文可达 |

结构讨论请求：

```text
我想先推敲一部长篇的故事结构，暂时不建项目。题材是都市职场，主角是维修工，冲突是老厂改造中有人想低价卖掉设备。只讨论“主角靠维修知识识破骗局”与“主角组织同事保住生产线”两种结构怎么取舍。没有对标书，不需要市场研究。
```

局部修改使用仓库 `demo/长篇/让你管账号，你高燃混剪炸全网/` 的临时副本（剔除 `.omc/.omx/.git`），请求：

```text
修改第12章细纲，把“本章禁止提前释放”改为“预告引发的争议、歌曲成片与传播结果；本章只推进到预告发布，不提前展示网友评论。”保留全部已定事件和结果。
```

显式转正文使用基线生成的《雾港回声》三卷及前十章细纲的副本，删除副本中的正文/追踪后，换入待测 Skill；不是修改真实书稿。请求：

```text
请实际执行 $story-long-write。现在明确从规划切换到正文：根据《雾港回声》现有卷纲和细纲写第1章，只写这一章，正文控制在1000—1500个非空白字符。不要提问。
```

## 已观察结果

脱敏事实与规则 SHA256 见 [results.json](results.json)。

- **基线 `fde1754`**：首轮预算截断，已建三卷；下一轮“继续”实际新增十章细纲后再次预算截断。没有复现自动直出正文，不把范围扩展冒充该现象的已证实根因。
- **候选主链**：首轮预算截断，已建前两卷；“继续”正常结束，只补第三卷；“按这个来”正常结束，0 工具调用、文件集合不变。始终没有细纲、正文、追踪。
- 主链候选运行在 `97f09ee` 前的中间快照；随后仅增加“新的明确请求可调整规划范围”和“已有正文缺追踪时先停止”两处边界。结果按快照标记，不冒充最新提交的完整复测。
- **`97f09ee` 结构讨论两轮**：正常结束，0 写调用，文件哈希不变；人工核对确为结构比较/卷级里程碑推演，非报错或空响应。
- **`97f09ee` 局部细纲修改**：正常结束，唯一 Edit 命中第 12 章细纲，所有其他书文件哈希不变。这是路由与局部编辑验证，不是完整重建细纲验收。
- **`97f09ee` 首章切换失败**：CLI 正常结束并落一章正文，但未执行完整 Reference Gate 或任何追踪初始化/提交。不能算首章流程通过，也没有证据将其归为既有问题。独立审查据此撤回通过结论；修复在转正文权威点紧邻声明“先完成全部正文 Gate 和 tracking check，否则不落正文”。

**首章修复复测仍失败，PR 保持 Draft**：相同素材与原提示词、最新 Skill，179.2 秒后 CLI 正常结束并写了首章，但没有追踪 state；首个正文写入前仍未读完必需 references、未尝试 tracking init/check。日志确认实际 Skill 注入包含最新转场前置，本轮也没有权限拒绝，因此不能将失败解释为未加载修复或权限拒绝。费用为 `$0.5323296`，未触发本轮 `$1.4` 上限。

复测后只将“规划不写追踪”恢复为“不把规划模式写入追踪”，避免误禁首次细纲完成后的既有初始化；该单句澄清仅做静态审查，未再跑 CLI，原复测 SHA 保留不变。

正文切换的强制前置验收尚未满足；其他规划/路由样本通过不抵消此失败。继续修复可能涉及运行时控制，而非继续堆提示词，本 PR 未扩大到新 Hook 或跨端权限机制，也不应合并为“全部验证通过”。

## 重放提示

只在临时目录复制待测版本的完整 Skill 到 `.claude/skills/story-long-write/`。使用显式项目 settings 禁个人 hooks，空 MCP；真实 book fixture 来自上述合成链或仓库 demo。不要把 `.claude` 认证、个人配置、原始 session 日志发布到仓库。

CLI 核心参数（替换提示词与预算；用子进程超时包裹）：

```sh
claude -p --setting-sources project --strict-mcp-config \
  --mcp-config '{"mcpServers":{}}' --permission-mode dontAsk \
  --tools 'Read,Glob,Grep,Write,Edit,Bash,Skill' \
  --allowedTools 'Read,Glob,Grep,Write,Edit,Bash,Skill' \
  --model sonnet --effort low --max-budget-usd 0.55 \
  --output-format stream-json --verbose '<提示词>'
```

检查 stream-json 的 `result.subtype`、权限拒绝、实际 Write/Edit/Bash 顺序及文件快照。超时/预算截断必须与正常成功分开；首章验收还须运行 `tracking_commit.py check`，不能只看正文存在。
