# 作者记忆、文风与 references：实验记录

基线：main `1e2488b80190197bc352bb3f5d852f5d7f251100`。候选：本 PR。

运行环境：Codex CLI 0.148.0，使用 CLI 默认模型；`--ephemeral --ignore-user-config --skip-git-repo-check -s workspace-write`。每次使用独立目录、相同合成样稿和用户请求，复制受测 skill，不加载个人 skills、不调用其他 agent、不做网络研究。后续批次在开始时冻结候选 skill 副本。未指定模型名，不用耗时或 token 数推断质量。

## 验收标准

- 当前请求、本书文风、本书记忆、全局记忆与通用参考按适用维度裁决；一次性要求不修改长期文件。
- 作者明确选择的功能性写法在去味和程序收尾之间保持一致。
- 没有授权豁免的真问题继续清理；白名单不跨书、不影响事实与文件协议检查。
- 人工核对正文 diff，脚本通过不等于语义正确。

## 首轮：5 组配对、10 次真实执行

| 用例 | main | 候选 | 结论 |
|---|---|---|---|
| `book_style`：本书短句、对白停顿、指定修辞，与全局长句/禁停顿记忆冲突 | 保留三项表达，但深扫仍有 2 个 blocking；主动跳过标点落盘步骤 | 保留三项表达，登记有来源的白名单，深扫 0 blocking，标点整理不改获准表达 | 创作判断与程序验收的矛盾消除 |
| `omniscient`：本书有限全知，通用参考默认限知 | 保留母女内心，去掉模板总结 | 同样保留母女内心，去掉模板总结 | 本样本未观察到原版抹平视角；候选保持了已有能力 |
| `memory_only`：无文风文件，本书记忆覆盖全局记忆 | 正确采用本书有限全知 | 同样采用本书有限全知 | 窄范围例外可生效；两版长期输入均未修改 |
| `default`：无文风、无记忆、无白名单 | 清理否定翻转、声音反差、否定排比与预告结尾 | 同样清理，未创建白名单，0 blocking | 默认检查未被全局关闭；金额、退款申请及十分钟到账条件保留 |
| `current_request`：本次切换到周宁限知，覆盖长期有限全知 | 执行限知，但新增“洗完碗后看见便笺”的观察经历 | 执行限知，但新增“进门时已经发现换锁” | 优先级选择正确，视角改写的语义忠实度仍有问题 |

前四组不能据此宣称整体文笔提高。最明确的改进是 `book_style`：同样被模型保留的作者选择，从“程序仍阻断/跳过整理”变为“按规则验收通过”。

## 视角边界的迭代

第一次补充：共用裁决明确，切换视角可以暂不叙述不可得信息，不能为了保全原文信息而补观察经历。两次候选独立复测中，1 次仍新增“进门时看到换锁”，说明只在写前声明还不稳定。

第二次补充：在去味交付前增加仅限视角转换的原文对照，逐项核对新增的感知/认知句；区分原有物件状态与自行补出的观察时点。

最终两次独立重测都未再新增“进门时知道换锁”或“洗碗后看到便笺”的经历，均以返回桌边后的钥匙状态呈现当前可见信息；母亲的私下想法没有被改成新台词，长期文风和记忆保持不变，深扫均为 0 blocking。见 [第 1 次正文](outputs/current_request-candidate-verified-1.md) 与 [第 2 次正文](outputs/current_request-candidate-verified-2.md)。这只说明该具体语义问题在两个重测中未复现，不能视为模型绝不会增写事实。

第 1 次重测仍在正文段落间插入空行，未遵守既有无空行约定；深扫没有报告这个格式问题。保留原始输出并单独记录，不把本轮 14 次执行标成全面通过，也不扩大本 PR 去重写格式检查器。优先级选择与获准表达的验收一致性是本 PR 的验证目标。

## 确定性与集成回归

- `scripts/test-style-precedence.py`：7 个行为测试，覆盖默认阻断、同一行局部豁免、标点检查/写入/幂等、书目录隔离、非正则匹配、短篇定位、JS/Python 写后与下一章门禁一致性；占位符、截断、缺细纲等继续检查。
- `scripts/test-writer-pipeline.py`：14 个测试，包含一句话有效文风、纯标题/注释占位不生效、旧摘要不能替代全文。
- 49 项仓库本地检查通过：静态链接、共享源同步、文档预算、句式与标点、作者记忆事务、追踪与字数、各端 hook parity、适配与部署等。系统 Python 3.9 无法运行的两项，使用现成的新版本 Python 重跑通过。

14 次运行数据见 [results.json](results.json)，逐次正文保存在 [outputs/](outputs/)。其中 `initial` 为首轮 10 次，`boundary` 为仅补写前知识边界后的 2 次，`verified` 为加入交付前原文对照后的 2 次。输入、用户请求与隔离执行脚本见 [run.py](run.py)。首轮及失败复测全部保留，不只展示成功样本。

## 复现

先把基线版本导出到独立目录，再运行：

```bash
python3 demo/style-precedence-eval/run.py --baseline /path/to/baseline --out /path/to/new-results
```

单测视角边界、候选重复两次：

```bash
python3 demo/style-precedence-eval/run.py --baseline /path/to/baseline --out /path/to/new-results --cases current_request --arms candidate --repeat 2
```

需要本机已安装并登录 Codex CLI；输出目录必须新建。模型是非确定性的，此处结果用于验证这些具体冲突与发现回归，未测长篇连续生成的总体文学质量。
