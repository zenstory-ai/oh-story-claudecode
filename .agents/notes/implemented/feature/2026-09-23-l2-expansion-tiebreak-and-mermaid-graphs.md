# Agent Note: 匹配章平票改比篇幅展开度；关系图默认 mermaid

Status: implemented

## Problem

两件收尾：①匹配章挑选（benchmark-recall (e) 与 explorer L2）的平票信号「摘要情节点数量≈章容量」在新格式摘要下恒为 1，失去区分度；chapter_index.csv 已被裁定为拆文前置产物不进写作段，需要别的信号。②人物关系图固定产 PNG，环境无渲染能力时只能记录缺失，写作侧审计确认 PNG 零消费、纯为拆文报告展示，重资产收益低。

## Decision

- L2 平票信号按摘要形态分叉（口径术语定为**单情节点摘要/多情节点摘要**，不写新旧）：**单情节点摘要比「三维节奏」篇幅展开度与本章计划展开度的接近度**（目标字数相对本书常规章长映射高/中/低≈3/2/1），多情节点摘要维持情节点数量/原文章节估算字数。本 skill 的写作口径本就对字数与情节点解耦，篇幅展开度比原始字数更贴 L2 本意——「该章给技法留的展开空间与要写的章相当」。翻转此前审计笔记「钝化维持现状」的记录（互链 `simplification/2026-09-23-benchmark-consumption-audit.md`）。
- 人物关系图**默认 mermaid**：落盘 `人物关系图/核心人物关系.md` 与 `关键关系演变.md`（graph 代码块），拆文报告嵌入 mermaid 块；仅用户明确要图片时才渲染同名 PNG，渲染失败降级回 mermaid 并记录原因。analyze 与 import 两处口径同步。

## Alternatives considered

- **拆文投影里嵌章字数行**：最强理由是信号精确且写作段仍只读摘要；但要改投影契约与夹具、存量摘要不覆盖拿不到该行，为一个平票信号扩契约性价比低，记为拆文侧远期可选。
- **平票直接落 L3（章节号最小）**：零成本；但同基调候选多时匹配质量随机，匹配章技法是正文参考主输入，弃用。
- **PNG 保持默认、失败才 mermaid**：最强理由是图片直观；但 PNG 依赖渲染环境且写作管道零消费，默认走重资产方向不合理，倒转为 mermaid 默认、图片按需。

## Consequences

收益：新格式书匹配章平票恢复区分度且零新增读取（三维节奏行在必读摘要内）；关系图产物在任意环境可产出、可 diff、可被报告直接嵌入。代价：篇幅信号仅 3 档，同档并列仍落 L3；已按旧口径产出 PNG 的存量书不迁移（新旧并存，报告以在场者为准）。
