# Agent Note: 书级正文存储配置

Status: implemented

## Problem

分卷查找已支持一层卷目录，但新章路径仍写死在正文直属目录，写作组装在重复章号时静默取第一份。

## Decision

以 `.story/storage.json` 记录 flat 或 volumes 布局和全书章节范围；写作组装及字数工具共用配置解析、章节枚举、重复章号和路径校验。老书无配置时只允许兼容读取，新章落点须有配置。初始化只登记既有布局，不移动正文，不覆盖已有配置；大纲、追踪、设定和对标不开放路径配置。

目录扫描按章号数值排序，默认排除点号目录、备份、临时稿及 `_原稿_` 文件。读取失败提供可重试的诊断，不因一个卷不可读而让宿主 hook 崩溃；目录配置冲突或同章号多份文件交由作者决定，Agent 不自动移动、删除或改配置。明确要求查看备份只授权单独读取，不自动将其纳入正式章节。

## Alternatives considered

从目录名推断布局可免配置，但新章所属卷和跨会话决定不可靠；改用持久化配置。自动移动冲突文件省去人工处理，但没有备份恢复工具前会扩大风险，因此本阶段只报冲突。

## Consequences

读取与写作路径一致，重复章号不再随机取文件；老书首次续写需登记布局。各宿主 hook 的配置约束和带备份迁移由后续阶段接入，本阶段保留其既有一层分卷识别。

2026-11-04 起老书首次登记支持自动识别，替代手工登记要求，见 [老书自动登记正文布局](2026-11-04-legacy-storage-discovery.md)。既有配置仍保持权威，不因目录变化重建。
