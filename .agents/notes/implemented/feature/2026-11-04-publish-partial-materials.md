# Agent Note: 发布资料即时保存与短故事无简介

Status: implemented

## Problem

字段未确认会推迟资料落盘，短故事还被统一模板要求提供平台不需要的简介。

## Decision

交付底线：每次调用至少保存一份可读的资料文件，缺项不阻塞，也不得仅提问结束。有覆盖冲突时先另存草案；仅在写入失败或无写入能力时改为回复全文，明确未落盘。未适配平台也先交付通用草案，不冒充平台校验已通过。

调用即生成和保存资料，缺失值留空并列待办；平台和书目录未知时先保存通用草案，不猜作品。用平台规则 synopsis 控制简介小节，番茄短故事不输出简介，也不以简介阻塞封面准备。旧文件的手工内容受保护，冲突时另存草案。此决定替代 2026-10-29-story-publish.md 中等字段都有结论再保存的要求。回归覆盖缺书名笔名的资料、长篇保留简介与短故事省略简介。

## Alternatives considered

统一保留空简介能保持旧格式，但会继续暗示短故事需要简介，因此按平台规则分流。等所有值确认再保存可减少中间文件，但不便作者逐步补齐，因此允许未完成资料落盘。

## Consequences

核对 story-cover Step 1–3：书名与笔名为必需输入，风格主要来自题材和平台；简介仅为可选题材推断材料。发布流程传递长篇题材/核心梗或短篇梗概/题材招式/目标情绪，不把平台是否填写简介与封面素材来源绑定。

作者可在同一资料文件逐步完善；资料已生成不代表准备完成或可提交。已有文件仍保护手工修改，暂存草案的最终位置和平台须确认。
