# Agent Note: Markdown 正文段落间距

Status: implemented

## Problem

正文格式规范要求段间单换行，Markdown 将相邻文本行合并为同一段，预览和复制时丢失作者期望的段落间距。短篇交付检查器还会把正确的空行判为错误。
首版修复遗漏审查、导入和范例中的旧规则，且新检查器会阻断历史短篇；作者还反馈正文缺少两字首行缩进，阅读和上传前需手工整理。

## Decision

长短篇正文段间统一使用 `\n\n`，即空一行；写作模板、格式规则与短篇交付检查器同步采用该格式。标题和小节标记相邻处维持各自规则。
新正文段首默认使用两个全角空格 `　　`，标题与小节标记不缩进；平台明确要求无前导空格时按平台导出。审查与导入同步新格式；交付检查器接受整篇沿用单换行的历史短篇，不追溯阻断。

## Alternatives considered

- 只在复制时转换：能保留现有正文文件格式，但各 Markdown 阅读器的预览仍会合并段落，且复制入口不唯一。

## Consequences

新正文在 Markdown 中呈现真实段落，复制后保留间距；旧正文不会自动迁移，需在后续修改时按新规范整理。
历史短篇可以继续交付；混合新旧段间距的正文仍须统一。缩进采用正文文件中的全角空格，上传平台若自动缩进，导出时需遵循平台格式。
文档预算中七条长篇路径原有余量不足，按本次检查结果各上调 20–35 字；单次加载仍低于 35K 硬上限。
ClawHub 的长篇、短篇、部署包各递增一个补丁版本，路由包同步更新精确依赖并递增版本；使用工作流固定的中央工具重生成包摘要锁，离线校验通过。
