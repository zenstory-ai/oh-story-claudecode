# Agent Note: 拆文旧库遇楔子时的章号核对与出路

Status: implemented
Date: 2026-09-24
Issue: 发版前复审（合成书复现脚本 + 真实 Claude Code 运行）
Related: [2026-09-23-long-analyze-runtime-takeover](../simplification/2026-09-23-long-analyze-runtime-takeover.md)（该篇「身份守卫只看旧摘要」「不做逐章身份比对」的决定在旧版拆文库这一场景被本篇翻转）、[2026-09-24-long-analyze-author-facing-report-and-chart](../feature/2026-09-24-long-analyze-author-facing-report-and-chart.md)

## Problem

v0.7.10 的章节正则不认「楔子」，它写的「第1章 深度拆解」其实是正文第一章；新索引把楔子算作第 1 章。
一本楔子开头、只拆到黄金三章就停下的旧拆文库升级后，计划排出 REUSE-1-3 + RAW-4-6，而新索引的
第 4 章是「第三章」：楔子永远没人拆，第三章拆两遍，第 1–3 章摘要整体错一位，全程没有任何报错。
原因是身份守卫（`inspect_existing_assets.py` 与 `build_chapter_index.py`）只看旧 `_摘要.md`，
旧的黄金三章深拆不参与。

同一类书若旧库已有逐章摘要，守卫能拦住，但只返回 `chapter_mapping_ambiguous`，计划随后报
`chapter_index_required`，文档只写「停止并报告」，作者没有任何往下走的办法。

另外 `build_chapter_index.py` 没把 stdout/stderr 设成 UTF-8：cp1252 控制台在错误路径上直接崩（退出码 1），
GBK 控制台输出乱码。

## Decision

- **核对对象**：旧摘要一律核对；黄金三章在 `_progress.md` 来自旧版（有 v0.7.x 的「章节边界」表，或
  没有运行状态受管区）时也核对。本次 Stage 1 按索引写的黄金三章、运行时投影不参与，序章开头的新书
  不会被自己的产物卡住。
- **核对方法**：有旧「章节边界」表时逐章定位——旧起始行正好是新索引某章的标题行就直接认定；否则按标题找：
  先 NFKC 统一全半角，去掉「第X章/卷/楔子/1.」前缀、标点和括号，精确相同优先，其次去掉「（求收藏）」「【二合一】」
  这类尾注后相同或互相包含；标题只剩章号时比章号；多个候选取离旧起始行最近的，并列就算找不到；旧表连标题
  都没有时才用包含旧起始行的那一章。全部落在同一章号才放行，旧表已把楔子算作第 1 章的库因此不再误拦，标题
  只差尾注、括号、全半角或「1.」式章号的库也不误拦。没有旧表时沿用原规则：原文首章不是第 1 章就无法确认。
- **两道门同一个函数**：核对逻辑是 `inspect_existing_assets.legacy_mapping_check`，`build_chapter_index.py`
  写新索引前调用（对不上就不写索引），检查器和 `plan` 对已建好的索引再查一遍。
- **出路**：错误同时返回 `author_message`，用作者的话说明错位后果并给三个选项，默认推荐①：
  ① `--fold-prologue` 重建索引，开头的楔子/序章/引子/前言/第0章并进第一个正式章节，章号回到旧口径，
  旧成果原样复用，输出 `folded_into_first_chapter`；② 把除 `原文/` 外所有按旧章号写的产物（`章节/`、
  `剧情/`、`角色/`、`设定/`、`人物关系图/`、快速预览、概要、拆文报告、文风、`_analysis_cache/批次-*.md` 和旧
  `_progress.md`）挪进 `_analysis_cache/legacy/旧章号/`，按新章号重拆，不留旧章号文件和新结果混在一起（挪文件
  由模型按文档做，脚本不动用户文件）；③ 换新目录整本重拆。索引已按错误口径建好时先删掉
  `chapter_index.csv`（纯机械表）再重建。
- **重建沿用口径**：`--rebuild` 时若已有索引第 1 章是正式章节、而原文开头有楔子/序章/第0章，即判定上次用过
  `--fold-prologue`，自动照样并入，无需再加参数；并入决定就记在索引本身（第 1 行的来源章号），不另加列或状态。
  重建出的前面各章与已有索引对不上（`position=N` 或 `index_would_shrink`）时不写索引，返回带两个出路的
  `author_message`（换回原来的原文 / 换新目录）。
- **UTF-8 输出**：三个运行时脚本和新增的关系图脚本在 `main()` 开头、解析参数之前把 stdout/stderr 都
  reconfigure 成 UTF-8，`--help` 和参数错误在 cp1252 控制台下也不崩。
- 顺手修正：chapter-extractor 模板旧成果模式示例从 `REUSE-1-20` 改为 3 章上限内的 `REUSE-1-3`，输出前检查
  第 2 条与「有摘要缺口时必须输出章节块」对齐；两处过期注释（「explicit reanalysis」「six stages」）改正。

## Alternatives considered

- **自动按旧表把旧文件映射到新章号，不问作者**：最强理由是零打扰；但文件名 `第1章_深度拆解.md` 会从此
  指向新第 2 章，下游（导入、对标挑章、文风取样）都按文件名取数，映射只在拆文运行时里成立，别处读到的仍是
  错位，而楔子照样没有拆。
- **索引支持第 0 章**：楔子编为第 0 章，正文章号不动，最贴近「楔子不算一章」的直觉；但索引、范围 hash、计划
  和检查器都假设章号从 1 连续，改动面远超一个并入选项，也会让新书多出一种编号形态。
- **只靠标题核对**：不依赖行号、原文改过也能对；但网文标题重复（「（上）」「（下）」、同名番外）很常见，
  行号定位加标题确认更稳。
- **并入决定写进 CSV 新列或 `_progress.md`**：最显式；但 CSV 列集和解析器版本是索引复用的判据，加列会让所有
  已建索引失效、每个用户都得重建；建索引脚本按设计不写运行进度。已有索引第 1 行本身就能区分两种口径。
- **起始行落在某章范围内就认定**：实现最简单；但旧表行号常差一两行（空行、CRLF），落进上一章会误报错位，
  所以只有正好落在标题行才直接认定，其余交给标题。
- **无旧表时一律要求作者手工提供映射**：最保守；但 v0.7.10 之前的库本来就没有表，作者也答不上来，
  实际可行的出路仍是并入或重拆。

## Consequences

收益：楔子开头的旧库不再静默错位；已有摘要的旧库从「停下报错」变成有推荐默认的三选一；旧表与新索引一致时
不误拦；标题带尾注、括号或全半角不同的旧表不误拦；并入楔子后追加章节再重建不再卡死；Windows/GBK 控制台下错误
路径和帮助也能输出可读 JSON。

代价：选①时楔子内容不会单独拆，需在报告「还不确定的地方」说明；旧表缺失的更老库仍只能靠首章是否为
第 1 章判断，书中插入番外导致的中途错位（无旧表时）依旧查不出；检查器多读一次 `_progress.md` 与章节目录；
标题允许包含关系后，同一本书里标题互相包含的章节要靠旧起始行远近区分；作者在已建索引后才给原文补上楔子时，
重建同样会把它并进第一章（章号不变，第一章进入待处理）。
