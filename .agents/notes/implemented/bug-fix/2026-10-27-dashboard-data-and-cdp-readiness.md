# Agent Note: 工作台稿件安全与 CDP 就绪判定

Status: implemented
Date: 2026-10-27
Related: [Dashboard 测试边界](../../implemented/testing/2026-09-25-test-audit-detectors-scan-dashboard.md)、[CDP 复用与重建](../../implemented/bug-fix/2026-10-14-polish-browser-cdp-docs.md)

## Problem

删除甲稿时切到乙稿继续写，甲稿请求完成后仍会清空乙稿缓冲区并标成已保存。保存流程已有文稿身份检查，删除流程缺少同样的约束。

工作台把非 UTF-8 原稿按 UTF-8 宽松解码，坏字节变成替换字符，随后保存会覆盖原字节。版本号也基于有损文本计算，不能保护这种情况。

CDP 探测仅检查 HTTP 请求是否成功，普通 HTTP 200 文本也会被报告为 ready 或复用成功，不能证明存在可连接的 Chrome 调试端点。

## Decision

- 删除响应只清理本次删除的那个文稿实例；无论当前打开哪份，都刷新目录并提示真实删除目标。
- 工作台严格验证文件 UTF-8，在读取和保存/删除的版本校验入口统一使用。非法编码明确拒绝、不自动转码；有效 UTF-8 的 BOM 与已有换行行为保留。
- CDP 就绪要求有效版本 JSON、浏览器标识与可用格式的浏览器 WebSocket 地址；端口占用仍由独立 TCP 探测判断，不能把非 CDP 监听当成可破坏 profile 的空闲端口。
- 界面用运行中的临时工作台复验切稿与保存；文件 API、采集与 CDP 通过隔离的公开入口做回归，不触碰用户浏览器、账号或真实站点。

## Alternatives considered

- **删除期间禁用全部切稿和输入**：状态最简单；不采用，因为保存期间已允许继续工作，身份校验能保住草稿而无需冻结编辑器。
- **自动猜测 GBK 并转码**：作者能直接编辑旧稿；不采用，因为无可靠通用编码猜测，静默转换仍可能破坏原文。明确拒绝让作者选择转换。
- **把 TCP 监听直接当 CDP 就绪**：探测便宜；不采用，因为任意本地服务都可能占用端口，监听只证明占用、不证明协议正确。

## Consequences

- 收益：慢请求不能丢掉另一份草稿，未知编码不能静默覆盖，CDP 的 ready 与复用成功有协议依据。
- 代价：旧编码稿件需要作者显式转换后编辑；CDP 模拟服务和旧测试夹具必须提供真实形状的版本响应，不能再用任意 JSON 冒充成功。

## Verification

- 运行中的真实 Dashboard：延迟甲稿 DELETE、切乙稿并输入，再释放请求；乙稿内容、身份和待保存状态不变，随后保存成功；截图已目检并清理。
- 文件 HTTP API 29 项通过，新增 GBK、UTF-16LE、截断 UTF-8 的读取/保存/删除拒绝，以及有效 BOM、U+FFFD 与 CRLF 字节保留。独立 CLI 启动的服务返回三次 415，原稿字节不变。
- `node scripts/test-scan-runtime.js` 通过，覆盖合法元数据、普通 HTTP 文本、缺字段/错类型/错协议/页面级 URL、重定向与已有重建身份/进程归属场景。独立 CLI smoke 验证非 CDP 不能复用、合法元数据可以复用，原 profile 哨兵保留；不启动或终止真实用户 Chrome。
- 本机验证为 Linux；没有运行 Playwright 测试套件，界面用实际浏览器操作和断言验证。
