# Agent Note: 灵感库登记管道加固——泄漏门定位、一次报全与增量导航

Status: implemented
Related（接手收口）：[2026-09-23-inspiration-library-takeover](../simplification/2026-09-23-inspiration-library-takeover.md)——逐章挂点与子串近义判定已在该篇撤回

首个真实规模灵感库（20 本书、150+ 原子）建库实测暴露的一批管道缺陷，在 #439 分支上收口。

## Problem

- 泄漏门按 `root.parent` 隐式取角色名单：灵感库不在 `拆文库/` 同级时名单恒为空集，专名检查静默空跑——沙箱试跑全绿、挪到真实工作区当场被拦，同一批书两个结果。
- 没有 `角色/` 目录的书完全绕过泄漏门，卡里满是专名照样绿灯。
- 角色卡按职能命名（如「剑客」「大夫人」）时，抽象机制里的通用词被子串匹配判成专名；但实测同类命中也存在真泄漏（卡自己的「不可照搬」点名了该词，其他字段却在用）。
- 字段值写在字段名下一行（列表型字段的自然写法）被解析成空串，报「缺字段」，排查方向被带偏。
- `可替换项` 大量写成「原书专名→任意X」——看似在声明可替换，实际把专名写进了被扫描的抽象字段，是实测泄漏的主要来源。
- 首错即 raise：修一处、重跑、报下一处，一本书要试跑多轮才看全问题；也没有只读检查模式。
- `SKILL.md` Stage 3 段自造了一套七字段名，与脚本门禁五字段一个都对不上；写手照顶层文档产卡，整本无法入库。
- 已建库后的增量：跨书聚合层没有机械信号指出哪些原子是新的、哪些已被覆盖，LLM 只能重扫全库。
- 标签值没有受控词表落盘：首轮聚合自定的词表只存在于会话约定里，跨会话/跨宿主必然漂移；query 是精确字符串匹配，漂移即静默零命中，validate 对值零校验，写作侧组标签也在自造词。

## Decision

- 工作区从 `--root` 向上探测含 `拆文库/` 的目录（`--workspace` 可显式指定），定位失败报 `workspace_not_located`；输出恒带 `character_roster` 数；书目录在而 `角色/` 缺失报 `character_roster_missing` warning。`validate` 的 EM 集合校验走同一定位。
- 专名检查分两级：本卡「不可照搬」已点名该词却仍在抽象字段使用、或 `可替换项` 命中「专名→任意X」反模式（`replaceable_antipattern`），维持 error；仅角色卡文件名子串命中而无佐证的降 `leak_suspect` warning 并列出命中字段。判据取自卡内自证矛盾，不引入职能词表。
- 粗体字段支持多行值（吸收到下一字段/标题为止）；错误码拆分 `em_field_value_empty` 与 `em_fields_missing`。
- `register-atoms` 收集全部卡的全部问题一次报出（`errors` 数组），有任一 error 即不写盘；新增只读 `check-atoms` 作为 Stage 3 落盘后的自检入口。
- 新增只读 `coverage`：列出未进入任何 active CBA 闭包的原子与现存单书假设卡，跨书聚合的 LLM 工作只处理 uncovered 增量。
- 标签值受控于库内 `灵感库/标签词表.md`（每轴一节、一行一值）。validate 在词表存在时拒表外值（`tag_value_not_in_vocabulary`）、同轴互为子串的近义值对（`tag_vocabulary_near_duplicate`，同义膨胀的机械拦截）与缺必填轴（`vocabulary_axis_missing`）；词表缺失不查，旧库兼容。扩表口径要求先做同义判定：语义重合或从属用现有值，确属新维度才追加。`query` 返回 `unmatched_tags` 与 `axis_inventory`，消费口径改为零命中先纠词重查一次；写作侧（cross-book-recall、story-explorer 模板）组标签的值一律取自词表，适配层已再生成。
- 口径统一：五门禁字段点名进 `SKILL.md`（同义名不识别），索引节标题定为字面量 `## 其他机制索引`；解析器不放宽该标题——口径刚把字面量定死，再放宽解析恰是接纳刚禁掉的漂移。完整卡数量从「最强三个」改为「至少覆盖前三强，不设上限」（用户裁定），与脚本行为一致。
- 解析体裁按实拆样本放宽：EM 编号两位起、接受 `·/-/—` 分隔、表格粗体字段名、粗体列表体裁、同义字段名归一。

## Alternatives considered

- **放宽索引节标题解析**（接受「其余机制（索引）」等变体）：最强理由是宽进严出、少改存量文件；但口径同时把标题定为字面量，放宽解析等于接纳口径刚禁掉的漂移，改为修文件侧标题。若将来翻转，须口径与解析器同改。
- **泄漏嫌疑一律维持 error**：最强理由是不放过任何真泄漏；但职能命名在长篇角色卡里常见，误报会持续阻塞入库，且实测的真泄漏案例都带卡内自证矛盾（「不可照搬」点名）或反模式箭头，两个高置信判据已覆盖，余下降 warning 人工复核。
- **职能词白名单**：最强理由是实现最简单；但词表永远追不上命名花样，且会把「角色确实叫这个通用词」的真泄漏放过去，弃用。
- **coverage 并进 validate**：最强理由是少一个子命令；但 validate 是门禁（有错必红），coverage 是导航（uncovered 不是错误状态），语义不同分开。

## Consequences

收益：沙箱与真实工作区行为一致，泄漏门结果可信；一本书的全部问题一轮看全；只读自检与增量导航使建库/扩库不再逼出临时脚本；写手照顶层口径产卡即可入库。

代价：无佐证的名单命中从硬拦降为 warning，依赖人工复核收尾（`check-atoms` 输出命中位置降低复核成本）；解析器接受多体裁后，模板之外的写法存活空间变大，靠门禁字段与字面量标题守住下限。
