# Agent Note: 作者记忆并发写入与基准评估完整性

Status: implemented
Date: 2026-10-27
Related: [作者记忆两级 store](../../implemented/architecture/2026-09-18-author-memory-two-level-store.md)、[真实会话基准](../../implemented/architecture/2026-09-24-v0-8-lean-writing-loop.md)

## Problem

作者记忆的两个并发进程都能读到同一修订并返回成功，后写者覆盖先写者。单文件原子替换不能保护读取、修订检查和提交的整体事务；初始化、迁移以及查询触发的单书布局归位也会写入。

基准严格评估输出 `render`，比较器却只读 `status`，把完整场景记零分；缺少越界检查不能当成零越界。评委两次无效响应被聚合成平局，缓存只看文件是否存在，不能区分普通/严格模式或输入变化。

## Decision

- 在作者记忆公开命令入口按固定顺序锁住工作区与存在的书目录，覆盖读取到写入及跨 store 迁移；锁文件不初始化记忆目录。沿用追踪事务的独占建文件、有限等待和显式陈旧锁错误，不自动删除未知锁。
- 基准显式区分评估模式，验证模型响应；缺数据和无效评估不折算为成功、零越界或平局。严格评估只度量场景呈现；比较器的 Q1/Q2 只接受完整有效的普通 coverage，配对只读取本次输入身份匹配的两轮评估。
- 缓存绑定评估协议、模式、模型、运行身份及原文/细纲内容，只复用完整且有效的匹配结果。
- 回归使用隔离目录和受控评委，不消耗外部模型额度；真实 CLI 烟测验证作者记忆的并发提交及错误恢复。

## Alternatives considered

- **只锁最终 state 文件写入**：修改最少，能避免字节交错；不采用，因为覆盖仍由旧状态生成，成功事务仍会丢失。
- **只在 CLI main 加锁**：覆盖常见调用且无需装饰器；不采用，因为现有 Python 调用公开 command 函数时仍会绕过保护。
- **严格结果直接映射到原有全部指标**：比较器改动少；不采用，因为严格评估没有越界新增观察，不能伪造该指标。
- **缓存仅按模式换文件名**：足以避免普通/严格冲突；不采用，因为同一文件名下文本、模型或协议变化仍会复用旧结论。

## Consequences

- 收益：成功回执对应保留的事务，评估结论不再混淆失败、缺失与平局。
- 代价：同一工作区的记忆命令串行执行，跨书目录命令按固定顺序多拿一把锁；崩溃后锁需确认无运行进程再移除。旧基准缓存不能证明输入身份，需重新评估，不迁移为可信结果。
