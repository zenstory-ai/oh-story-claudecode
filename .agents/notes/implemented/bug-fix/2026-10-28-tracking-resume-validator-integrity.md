# Agent Note: 追踪保全、拆文替代批次与结构门禁

Status: implemented
Date: 2026-10-28

## Problem

旧追踪初始化只存档退役文件名，同名的伏笔等资料会被新视图覆盖。修订先写逐章记录，后续写入失败却留下未提交内容，另一笔提交后草稿会读到它。拆文检查把已被新有效批次完全覆盖的旧 RAW 批次继续判坏。长篇细纲的空意图字段会吞下一行，空表或错列事件不阻断；短篇反派占位符、只有标签的推进、负数与数字前缀混杂目标会被误放行。逐章记录用允许出现在角色名里的分隔符读回，修订草稿会改名并漏快照。

## Decision

1. `init` 在持锁时原样移走旧追踪的全部直接子项，仅排除本次锁与已有存档；先查全部存档碰撞，再搬运。校验失败不动旧资料，已搬走部分的存档可续做。
2. 修订先保留原记录字节；派生视图或权威写入异常时，在同一锁内恢复原记录，未提交的导入覆盖记录则撤销。append 的同事务重跑规则不变，不引入恢复状态机。
3. 检查器用当前有效 RAW 的章节并集识别完全替代的历史范围；部分覆盖仍待续跑，不让失效范围 hash 被状态行掩盖。
4. 长篇意图字段复用 `fieldValues`，空白和占位符不跨行取值，其余允许未知的字段保持。
5. 只消费「情节细化」中的一张连续事件表，至少一个编号数据行，逐行列数一致；放行边界也只取该表。既有 Markdown 转义竖线与偶数反斜杠不误计列。
6. 短篇反派五字段须非空且非占位，功能标签不单独充当推进；仍不判断故事内容好坏。
7. 逐节预算完整解析为正整数，保留千分位、字、约数与括号备注；不截取负数、小数、区间或杂字前缀。整篇单值/区间及合计容差不变。
8. 逐章记录转义角色名里的 `｜` 为 `\｜`，按未转义的核心/临时分类边界读回并还原原名；变化正文可含分隔符。普通既有未转义别名也按同一分类语法识别，不另开旧版分支。JSON、state schema 与快照文件名不变，三份运行时和审稿 reference 同步。

## Alternatives considered

- **只扩充退役文件名列表**：改动最少；不采用，因为现行视图同名旧文件及以后新增视图仍可能漏保全。
- **引入多文件事务状态机**：可以覆盖更广泛的崩溃恢复；不采用，本次只修已复现的写入失败污染，用现有锁与原记录恢复即可。
- **让模型判断空设计是否足够好**：能覆盖更多故事质量；不采用，当前缺口都是确定性的字段和表格结构，不应把质量评分混进门禁。

## Consequences

收益是旧资料保留、失败修订不污染已提交历史、重分组后的拆文可复用，未填完或坏格式输入不会被宣告完成。代价是以前误通过的输入会被明确拒绝，存档冲突需先处理；不扩大故事质量裁定范围，不引入依赖或第二套持久状态。
