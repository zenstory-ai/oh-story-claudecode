# Agent Note: 扫榜与部署审查发现的一批修正

Status: implemented
Date: 2026-09-26
Related: [扫榜先聚合再读](../feature/2026-09-26-scan-aggregate-and-handoff.md)、[story-setup 按宿主拆分](../architecture/2026-09-26-setup-by-host.md)

## Problem

v0.8.2 两处改动（扫榜聚合与落盘、story-setup 按宿主拆分）合入后审查发现几处断链与静默失败：

- 长篇扫榜 Phase 4 总写 `选题决策.md`，但只扫榜不选题时文件里没有「推荐选题」；开书把它当选题起点、拆文回填把它判为契约无效，两边都会走错。
- 已部署项目读到 sentinel 的 `target_cli` 就跳过宿主判断：作者换了软件再跑部署，新宿主永远装不上。判断不出宿主时，项目里恰好一个宿主标记就直接当成当前宿主，可能装错一整套文件。
- 番茄书库一本没抓到也写出空文件，`--channel all` 某频道被跳验证页只打一行日志、退出码仍是成功；聚合脚本直接跳过没有条目的榜单文件，「采集情况」里看不到它没采到。详情页解析在整页里找第一个 `readCount` / `lastChapterTitle`，详情页先出现推荐书时会把推荐书的数字记到这本书头上。
- 扫榜没规定每次用新目录，第二次扫榜写进同一目录，聚合会把旧榜单混进来；短篇写作只在项目根和上一级找 `短篇扫榜结论.md`，与交付语「同级目录也能看到」不一致。
- 落在作者文件夹里的 `扫榜聚合.md` 末尾带 `--sample … --n 5` 命令，「采集情况」写 `[OK]`、`[标题解析异常]` 这类标记。OpenCode 部署版本门要求「报告首行写未部署」，与安装报告「先写现在可以做什么」冲突；手动配置模型的指引放在部署明细里、写着文件路径与字段名。

## Decision

- **选题决策缺推荐选题**：story-long-write 定方向读到没有「推荐选题」的 `选题决策.md` 时当作还没选题、走常规提问；story-long-analyze 跳过回填、不判文件无效（有推荐选题但缺「能爆的原因」等字段才返回契约错误）。
- **宿主判断**：sentinel 里的端照常重部署、不再让作者选，但第 4 步照样判断当前宿主；判断出来且不在已部署列表里时问「要一起装上吗」，选装上就加进 `target_cli`。判断不出宿主时项目标记只当候选：恰好一个就问「上次是给 X 装的，这次还是它吗？」，其余情况问在哪个软件里对话。`check-story-setup-deployment.sh` 加断言锚住这两处。
- **采集失败计数**：番茄采集（榜单与书库两种模式）一个频道/榜单一本没采到、CDP 无响应或被跳到验证页时抛错，不写文件，计入失败；主流程按 `runCli` 的 `{planned, written, failed, partialReasons}` 报结果，部分失败退出码 2 并列出哪个频道、为什么，全部失败退出码 1。聚合脚本把首行像榜单但没有条目的文件列进「采集情况」的「没采到：整份榜单一本都没有」，不进题材统计；输入只剩空榜单时报错并列出文件名。
- **详情页只取正文书**：详情解析抽成自包含的 `parseDetailHtml`，以函数源码拼进浏览器端脚本。先按 `bookId` 定位包住它、且含 `bookName` 的最内层 JSON 对象（字符串感知的括号匹配），定位不到再按 `<title>` 里的书名定位；书名、作者、简介、题材、数字和最新章节只从这个对象取，最新章节按 JSON 字符串解转义；都定位不到时书名作者退回 `<title>`/meta，数字留空。
- **扫榜目录**：长短篇扫榜每次新建 `扫榜/{YYYYMMDD}/`（同日再扫加 `-2`），不往旧目录追加；对比读上一个日期目录的 `扫榜聚合.md`。短篇写作改为从项目根及其上一级往下 3 层找 `短篇扫榜结论.md`，多份取最新，与长篇开书查找 `选题决策.md` 同口径；两边交付语改为「小说项目建在扫榜时的文件夹里或和它同级」。短篇聚合命令固定加 `--scale short`。
- **作者可读**：`扫榜聚合.md` 不再写命令参数；「采集情况」的质量标记翻成白话（正常、书名大多没解出来、没有数据等），`--json` 的 `quality` 字段保持原始标记。OpenCode 版本门拦下时，安装报告「现在可以做什么」只写装上的端，「你还需要做的事」用白话说 OpenCode 没装上及原因；读不到模型列表时的指引移到「你还需要做的事」、改成作者能照做的白话（标了作者报告模板），文件路径与字段名只在部署明细留一行。
- **测试**：`test-scan-aggregate.py` 新增书库 `--channel all` 女频被跳验证页（exit 2、只写男频）、书库一本没抓到（exit 1、不写文件）、空榜单列进「没采到」且质量标记翻成白话、聚合文件不含命令参数，以及用 `vm` 给假 `XMLHttpRequest` 喂夹具 HTML、实际执行 `buildDetailJS` 生成的脚本：推荐书排在前面时数字取正文书，数字与字符串两种 `readCount`/`wordNumber`，最新章节带转义引号，没有 `bookId` 时按书名定位，定位不到时数字留空。

### 2026-10-27：刺猬猫缺榜按部分失败处理

2026-10-27：刺猬猫 `--type all` 缺榜或单榜写入失败时也按既有 `runCli` 契约统计 planned / written / failed / partialReasons，保留成功文件并退出 2；全无产物仍退出 1，全部成功才退出 0。复用现有传输替身从公开 CLI 覆盖缺榜、全成功和全失败，不新增测试专用运行时导出。

公开 CLI 回归覆盖仅一个榜成功（exit 2、保留文件并报告 1/9、失败 8）、九榜全成功（exit 0）、只请求一个成功榜（exit 0）、完全无数据（exit 1、不写文件）。独立脚本从模拟 DOM 运行真实提取与 CLI，也得到 exit 2 和完整缺榜原因；未访问真实站点。


## Alternatives considered

- **只扫榜时也写一节空的「推荐选题」**——最强理由：消费方不用改，文件形状永远一致。不采用：空节会被开书当成「有选题」去取第一条，也会让拆文回填找不到可回填项却不知道原因；让消费方按「有没有这一节」判断更直接。
- **sentinel 有值时完全不判断宿主（原做法）**——最强理由：重部署零打扰，skills-only 三端也无从探测。不采用：作者换软件是真实场景，漏装新宿主后写正文守卫等整套缺席且无人提示；判断不出时仍按 sentinel 部署、不问，零打扰只在判断得出且确实是新宿主时让一步。
- **书库没抓到时写出 `[无数据]` 空文件、只靠聚合标出**——最强理由：文件在盘上，作者能看到这次跑过。不采用：采集脚本退出码仍是成功，主会话看不到失败；不写文件加退出码 1/2，采集时就能发现，聚合侧再兜底列出空文件，两层都不静默。
- **短篇写作查找不改、只改交付语**——最强理由：短篇写作入口预算很紧。不采用：扫榜改为写进 `扫榜/{日期}/` 后，只查项目根和上一级根本找不到结论文件；改查找只多十几个字，入口仍在预算内。

## Consequences

- 收益：只扫榜不选题、换宿主重部署、频道被拦截、推荐书数字串位这几种情况都不再静默出错；重复扫榜不再混进旧榜单；作者文件夹里的聚合文件和安装报告不再出现命令参数与内部标记。
- 代价：番茄一次采集部分失败时退出码是 2 而不是 0，调用方要把 2 当「有结果但不全」；详情页结构若改成既没有 `bookId` 也对不上 `<title>` 书名，书库的在读数与字数会显示「未知」而不是可能错的数字。扫榜目录多一层日期，旧的平铺输出目录需要作者自己挪。几处热路径文件为放下新规则删了等量旧字（开书定方向、部署入口与 OpenCode 部署、长短篇扫榜入口），没有调高预算。
