# Agent Note: 出卷纲时回填题材定位的「题材框架」并清理模板标题流程括注

Status: implemented
Date: 2026-11-19
Related: [长篇写作审查与开书实测发现的一批断链](2026-09-26-long-write-review-fixes.md)、[0.10.0 长篇清理](../architecture/2026-11-03-long-write-0-10-cleanup.md)

## Problem

Issue #556 反馈：完成「出卷纲」后，`设定/题材定位.md` 末尾的「题材框架」始终没有补上，每次稳定复现。

根因在开书按时刻拆分（v0.8.2）留下的单向约定断链：

1. `workflow-setup.md` 的 `template=题材定位` 把末节写成 `## 题材框架（出卷纲时补）`（含 `- 关键转折节点：{列出}`），同时 `build_architect_brief.py` 要求「模板里的小节名、字段名照抄，不改名」，因此定设定时刻会把带流程括注的空节原样落进 `设定/题材定位.md`（同模板的 `## 核心设定（定设定时填）` 也会把流程括注带进作者文件标题）。
2. 到「出卷纲」时刻，`build_architect_brief.py --task volume` 的任务包头写死「只交付 `大纲/大纲.md` 的分卷表……和 `大纲/卷纲_第X卷.md`」，直接禁止 `story-architect` 修改 `设定/题材定位.md`；`workflow-volume.md` 的「交付物与锁定」与 `workflow-setup.md` 时刻表同样只列两份大纲文件，主会话自己排纲和收回子代理产物时都不会回填或核对「题材框架」。

## Decision

- **出卷纲交付补齐回填闭环**：
  - `workflow-volume.md`「交付物与锁定」新增 `设定/题材定位.md「题材框架」`：把分卷转折与本卷 1/4、中点、3/4、卷末关键情节写进「关键转折节点」（开新卷时追加本卷节点；标题统一写 `## 题材框架`，去掉旧文件的「（出卷纲时补）」，缺该节则在文末补上），其余小节不动。
  - `build_architect_brief.py` 的 `--task volume` 任务包头明确要求补齐 `设定/题材定位.md`「题材框架」的「关键转折节点」；`--task world` 任务包头与 `workflow-setup.md` Phase 2 写明「题材框架」留到出卷纲补。
  - `workflow-volume.md`「谁来排」与 `agent-calls.md` 在收回 `story-architect` 卷纲产物时，除 `outline_view.py --check --strict` 外一并核对 `设定/题材定位.md`「题材框架」已补齐，仍留占位时交回同一子代理补齐。
  - `workflow-setup.md` 顶部时刻表「出卷纲」行同步注明补 `设定/题材定位.md`「题材框架」。
- **清理模板标题里的流程括注**：`workflow-setup.md` 的 `template=题材定位` 将 `## 核心设定（定设定时填）`、`## 题材框架（出卷纲时补）` 改为纯白话标题 `## 核心设定`、`## 题材框架`（与 `story-import` 题材定位模板同名），填写时机放进阶段说明与字段占位 `{出卷纲时按分卷与本卷关键情节补齐}`；`convert_outline_format.py` 的 `convert_genre` 顺带剥掉存量书这两处标题括注。
- **回归测试**：在 `scripts/test-writer-pipeline.py` 断言 `--task volume` 任务包要求补齐 `设定/题材定位.md`「题材框架」与「关键转折节点」、`--task world` 模板标题不再带流程括注，以及格式转换脚本能清理旧括注。

## Alternatives considered

- **直接删掉 `设定/题材定位.md` 的「题材框架」小节**：最强理由是 `设定/全书梗概.md` 已有「前几次大转折」、卷纲已有 1/4·中点·3/4 关键位置，删掉可省去跨时刻回写设定文件。不采用：① 作者在 `设定/题材定位.md` 里期望看到本书落定后的题材骨架与关键转折节点总览（#556 明确预期出卷纲后补齐）；② `story-import` 的长篇题材定位模板与外部对标同步（`benchmark-sync.md`「在『题材框架』之前追加两节」）都以 `## 题材框架` 为固定锚点，删除会让新建书与导入书结构分叉，也会让 v0.8.2–v0.10.5 存量书在开新卷时永远留着半截占位。
- **改在 Phase 2「定设定」时刻直接填完「题材框架」**：最强理由是把 `设定/题材定位.md` 的写入收敛在前两步，出卷纲只写 `大纲/`。不采用：定设定时还没有分卷与卷内 1/4、中点、3/4 关键位置，强填只会重复全书梗概或提前编造卷章节点（这正是 v0.8.2 实测把它推迟到出卷纲的原因），且已走完定设定的存量项目在出卷纲时仍不会被修复。
- **只让主会话在 `story-architect` 返回后自己补写「题材框架」**：最强理由是不改任务包交付边界。不采用：主会话遵守「卷纲不整读」，手里没有刚排好的完整卷内转折上下文；而 `story-architect` 本就先读 `设定/题材定位.md` 并拥有 `Edit` 权限，在排完卷纲当场回填最准确，主会话做收回核对兜底即可。

## Consequences

- **收益**：无论走 `story-architect` 子代理还是主会话自己排纲，「出卷纲」都会把分卷与本卷关键转折节点回填进 `设定/题材定位.md`「题材框架」，并清理存量书留下的 `（出卷纲时补）` 占位；新建书的题材定位小节标题不再泄漏流程括注，与 `story-import` 完全一致。
- **代价**：`--task volume` 任务包与 `workflow-volume.md` 各增加约数十字符说明（均在 `doc-budget.json` 现有余量之内，无需抬高预算）；出卷纲时子代理除写 `大纲/` 外会多一次对 `设定/题材定位.md` 末节的编辑。
