# Agent Note: 部署、导入与正文守卫的保全边界

Status: implemented
Date: 2026-10-27

## Problem

Antigravity 物化拒绝已有备份后，finally 仍删除该备份；回滚失败也会丢掉恢复数据。项目指令合并把块外空白和行尾一起整理，并用临时文件权限覆盖原权限。正文命令守卫未把外层 cd 的目录传给子 shell，会查错书。导入任务包只要求找到一张相交单元卡，既不核对缺章和重叠，也把空摘要当作无需回看正文。回炉原稿备份进入正文兜底网，被要求改写。

## Decision

按审查优先级逐项修正：部署只在成功替换后删除本次备份；子 shell 目标继承有效目录；项目指令仅替换管理块并保留块外字节与现有权限；导入逐章要求唯一单元，并为缺少必需摘要证据的章节计算补读正文；正文活跃文件选择统一排除既有 `_原稿_` 备份约定。同步已登记副本与各宿主的对应逻辑，复用现有校验和合并约定，不新增依赖或持久状态。

## Alternatives considered

- **遇到任何备份先清理再重试**：能减少残留阻断；不采用，因为无法证明备份属于本次运行，且可能是唯一恢复数据。
- **遇到子 shell 就放行或全部拒绝**：实现最短；不采用，因为已支持的写入语法可以沿既有递归解析传递目录，既不放过错书写入也不误拦正常写入。
- **只有摘要文件缺失时计算补读量**：判断便宜；不采用，因为存在文件不等于字段可用，空文件和缺字段仍需要回看正文。

## Consequences

收益是失败不损坏恢复资料，重部署不改作者内容和权限，跨目录写入查对书，导入不把无依据的范围交给执行者。代价是旧卷纲缺覆盖/重叠会先报错，空或残缺摘要可能使批次缩小；原稿备份仍保留但不作为活跃正文检查。

## Verification

- 真实部署 CLI 拒绝已有备份，目标与备份字节均保留；永久回归注入安装和回滚双重 rename 失败，确认恢复数据仍在、staging 清理。
- 真实 Bash guard 对正确书目里的嵌套写入放行，对切去无细纲的另一书阻断；Python 同时验证子 shell 与命令替换的目录继承。JS 三副本同步，跨宿主 parity 覆盖相对/绝对目录、cd 进正文与递归命令。
- 合并 CLI 保留 CRLF、作者空行与原有权限；部署守卫覆盖 BOM、混合行尾、代码块空行、其他宿主块、旧版迁移及幂等。
- 导入 CLI 对缺覆盖 11–12、重叠 10–12 均退出 2，补成唯一覆盖后成功。空摘要原场景按补读量从 20 章缩到 1–3，next=4；回归覆盖空文件、仅标题、无情节点和占位字段，所选正文原字节不变。missing_summaries 仍仅指缺失文件，不改公开字段语义。
- 真实写后 hook 对原稿备份静默，Codex Stop 不报告备份，原稿字节保留；活跃正文检测仍由既有正例保护。
- 集成时发现 no-node 夹具依赖 /usr/bin 没有 Node；复用部署守卫的显式失败 shim，并发送真实 UTF-8 路径，避免环境变化及转义路径导致假结论。本机为 Linux，未调用模型或修改用户项目。
- 删除仅匹配导入预算原句的部署断言；缩批由公开 CLI 的行为测试覆盖。旧连续性场景覆盖掉了上下文修订字段，实际触发版本冲突，删除该 staleness 文案断言和无关时间夹具，保留撞名、坏/缺 state 与干净工程验证。删除无追踪短篇的旧文案检查；它并非干净工程，当前实际会报告缺小节大纲与缺 state，不要求产品对其静默。
