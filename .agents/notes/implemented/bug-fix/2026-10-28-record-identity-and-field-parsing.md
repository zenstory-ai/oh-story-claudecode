# Agent Note: 旧记录身份消歧与统一字段识别

Status: implemented
Date: 2026-10-28

## Problem

[前一轮保全修复](2026-10-28-tracking-resume-validator-integrity.md) 对新增转义名有效，但未转义旧记录 `Bea｜核心｜Alias｜核心｜alive` 仍会读成 Bea 并漏快照。仅靠分类文字不能分清名字和变化正文里的分隔符。短篇字段校验接受冒号前空格，查占位符却要求字段名紧贴冒号，未填原因和五字段仍能通过。

## Decision

先修历史身份，再统一短篇字段读取。新记录的角色名改用标准 JSON 字符串作为第一个字段，使名字与变化正文边界明确；现有记录枚举可能边界，用当前权威身份唯一消歧，不能唯一确定时在任何草稿写入前拒绝，不覆盖历史、state 或已填草稿。成功的显式修订把该章记录写为新格式，不新增状态库或批量迁移入口。短篇契约字段用同一个逐行读取结果完成实际校验和占位检测，统一空格、冒号和 Markdown 标记，不再按紧贴冒号的字面子串判定。

交接守卫执行平台解析行为，不再从 JS 源码提取指定形状的正则。导入夹具先确认预留题材字段阻断门禁，再仅补题材参考与核心招式并要求完整门禁通过，避免把新增占位诊断简单加入白名单而漏掉其他未填项。

## Alternatives considered

- **把分类正则改成贪婪匹配**：能保住长别名；不采用，变化正文也可含分类文字，会把正文拼进名字。
- **始终选第一个匹配的已知角色**：代码短且常见名字能恢复；不采用，短名与长别名可能同时存在，必须拒绝歧义。
- **为记录增设 JSON sidecar**：身份完全结构化；不采用，只给现有记录的名字加 JSON 引号已能唯一读取，不必引入第二份持久数据。

## Consequences

收益是旧记录不再静默改名，歧义不会污染已填草稿，新记录不再产生同类歧义，合法排版不改变占位检查结果。代价是歧义旧记录需要作者确认完整身份后显式提交修订；角色变化行的名字增加 JSON 引号，但 state、事务 JSON 与快照文件名不变。该记录编码决定接替前一篇的反斜杠写法，前一决定保留为历史。
