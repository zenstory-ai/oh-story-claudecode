# Agent Note: 写作管道对拆文产物的消费面审计与去重

Status: implemented

## Problem

拆文契约换代（单状态机＋薄摘要投影）后，写作管道的消费面没有整体核对过：可能存在指向已不存在产物的孤儿引用、新产物无人消费、以及同一流程位置的重复读取。

## Decision

对开书/建纲/逐章全链 × 新拆文产物清单做交叉盘点，处置如下：

- **删除化石条目**：逐章材料清单原 (6) `对标/{书名}/原文/第{N}章_*.md`——新旧两代拆文都只产单文件 `原文/原文.txt`，该路径从不命中；删除并重排 (7)-(13)→(6)-(12)（无外部编号引用）。
- **防重读注记**：材料清单情绪模块/节奏两项补「读取与选取在 3(a)/3(b) 一次完成，本项只列路径与阻断链」，对齐题材卡条目的既有写法，消除清单读一遍＋召回再读一遍的双读风险。
- **(f) 范围限定**：结构化模块召回限定为角色/设定子目录——剧情单元已由材料清单按故事线选定，不再重复检索。
- **chapter_index.csv 定性（用户裁定）**：拆文前置产物，**不作为写作段消费内容**——后续不得为它接写作侧消费。(e)/explorer L2 情节点数量信号在新格式下钝化的处置，随后由用户裁定翻转为篇幅展开度信号，见 `feature/2026-09-23-l2-expansion-tiebreak-and-mermaid-graphs.md`。
- 排除的孤儿嫌疑记录在案：`_meta.json.structure_counts`/`reversal_type` 属短篇导入管道契约；故事线.md 保留「包含剧情」行，材料清单按故事线选单元在两代下均成立；爽点类型平票信号两代等效（读关键事件判断）。
- 无消费者但 by design 不接线：快速预览（用户交付物）、`_analysis_cache`（恢复证据）、散落情节（兜底归账）、概要（人读入口）、人物关系图 PNG（报告嵌入）。候选新功能未做：角色关系.md 接卷纲对手侧/关系线设计，另行立项。

## Alternatives considered

- **保留 (6) 加「如存在」继续护身**：最强理由是零风险；但死条目每章进 prompt 白花预算且误导维护者以为存在分章原文契约，删除。
- **L2 改用 chapter_index 的 char_count 救钝化**：最强理由是一处接线两得；用户裁定 chapter_index 是拆文前置产物不进写作段，且引入它会把机械索引变成跨技能契约面，弃用。
- **(f) 整条删除**：最强理由是角色/设定也可并入材料清单；但 (f) 的按情节检索语义与清单的按细纲列举不同，且承担冲突裁决职责，保留并缩范围。

## Consequences

收益：逐章热路径少一个死条目、少一处双读风险、剧情子目录单一入口；chapter_index 的边界从此有明文可依。代价：benchmark-recall 与两条路径预算小幅上调（+20~+30，why 已记）。L2 钝化在本篇曾记为维持现状，该决定已被后续笔记翻转（见上方互链）。
