# Agent Note: 细纲必填收到九个核心字段，阅读体验字段改为可选

Status: implemented

## Problem

细纲模板累积到二十多个字段：核心事件、字数、单元位置之外，还有阶段位置、章节定位、本章结构公式、本章标价、闭环状态、写手自由区、契约风险、镜头准入、信息差触发点，情节点表还有「分辨率」列。`check-outline-contract.js` 把其中十六个列为必填，`current-contract.json` 的 `required_outline_sections` 又要求阶段位置与结构公式。作者和 agent 每章都要填满，排纲耗时和 token 都花在这里，也是「概念过多」这一痛点的主要来源之一（[v0.8 瘦身笔记](../architecture/2026-09-24-v0-8-lean-writing-loop.md) Problem 第 2 节）。

已有证据只支持其中两个字段：#383 的消融实验（固定第 20 章、只改细纲、成对盲评）里，只补 `目标情绪` + `主角目标/关键选择` 对不补 3:0，对补满全部字段 2:1 打平；`单元ID/位置`、`章节定位`、`契约风险` 测不出差别。

## Decision

- `check-outline-contract.js`（story-long-write 与 story-import 两份副本）必填字段收到九个：核心事件、字数目标、字数口径、单元ID/位置、目标情绪、主角目标/关键选择、章首钩子、爽点、本章禁止提前释放。前三个与单元位置是脚本和工作流消费的结构字段，目标情绪与主角目标有 #383 撑腰，钩子、爽点、禁止提前释放是已有规则和事故对应的底线。
- 情节点表默认四列 `# | 情节点（谁做了什么） | 功能标签 | 执行边界（禁＋放）`，需要时可在功能标签后加「分辨率」列；「每章至少一个点写了放」的检查对四列与五列表都生效。
- `workflow-setup.md` 细纲模板末尾新增「可选：需要时再写」块，收纳阶段位置、章节定位、结构公式、本章标价、闭环状态、写手自由区、镜头准入、信息差触发点、分辨率列；契约风险只在本章让单元卡风险等级变化时写。
- `current-contract.json` 的 `required_outline_sections` 去掉阶段位置与结构公式；项目规则模板 `story-outline.md`、story-architect 模板同步，story-architect 删掉「每章必须满足五项驱动之一」的硬规则（outline-methods 里本来就是每 3–5 章查一次）。
- narrative-writer 铁律 4 改为「细纲写了才消费」，writer-prompt-fallback 只在细纲写了阶段位置、结构公式时传。

## Alternatives considered

- **保留全部字段必填**：最强理由是这些字段各自对应过一个具体问题（每章像短篇、配角没台词、奖励不可见），必填能保证每章都被想到。否：#383 只有两个字段测出收益，其余字段必填的代价是每章都要付的排纲时间和写手 prompt 长度，且模型会为了填表编内容；可选后需要的书仍可写，写手照样消费。
- **把阅读体验字段整块删掉**：最强理由是删得最干净，概念数下降最多。否：这些字段在高压章、群戏章里确实有用，作者手里已有的细纲也在用；删掉会让写手不认旧细纲的字段，改为可选不影响兼容。
- **只改模板文字、检查器不动**：最强理由是改动面小。否：检查器仍拦，agent 会照检查器补字段，模板上的「可选」形同虚设。

## Consequences

- **收益**：新细纲少填约十个字段，排纲和写手 prompt 都变短；检查器只拦有证据的缺项。
- **代价**：可选字段失去强制，个别书可能出现每章像短篇、镜头分配失衡等老问题回流，需要靠卷纲的章节定位分布和审稿清单兜底。
- **兼容**：旧细纲写全了字段照样通过；五列带分辨率的表仍被接受。
- **验证**：本改动未单独跑基准（Codex 额度不足），依据是上文引用的既有实验；复测待办记在 [v0.8 瘦身笔记](../architecture/2026-09-24-v0-8-lean-writing-loop.md)「未做与结案」。
