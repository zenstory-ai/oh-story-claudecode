# Agent Note: 短篇拆文的情节节点清单只存一份，拆文报告只写摘要

Status: implemented
Date: 2026-11-08

## Problem

短篇拆文 Stage 2 的两处规范对情节节点清单的落盘说法不一致：

- `stage2-3-structure-emotion.md` 的「情节节点」段写的是 `情节节点.md` 独立成文，`拆文报告.md` 再放一份「情节节点清单段镜像」。
- `output-contract.md` 的 Stage → 文件映射表只列了「`拆文报告.md`（题材/故事核/结构/梗概段）+ `情节节点.md`」，没提报告里要有节点。v0.10.3（#535）只给文件树那一行补了「并在拆文报告镜像」，表格没动，同一个文件里上下两处仍对不上。

这处分歧从 v0.6.11（#107）建输出契约时就存在，当时没留下要求两处都放的理由。「镜像」字面上是整份复制：每个节点带最长 300 字的原文引用，一篇短篇几十个节点，报告会多出几千字和单独文件完全一样的内容，两份还容易改了一份忘了另一份。下游 `story-short-write` 和 `story-import` 都只读 `情节节点.md`，不读报告里的副本；验收和质量清单也从来不查报告里有没有这份。

`demo/拆文库/曾将爱意私藏/拆文报告.md` 是真实跑出来的产物，那里的「情节节点清单（镜像）」段其实没有整份复制，只写了一句「完整 54 节点见 情节节点.md」，再按结构段列关键节点编号和事件。

## Decision

- 完整情节节点清单只存在 `情节节点.md`。
- `拆文报告.md` 在 Stage 2 写「情节节点摘要」段：一句「完整节点见 情节节点.md」，再按结构段列关键节点编号和事件，不抄原文引用。写法和 demo 已有的产物一致。
- `stage2-3-structure-emotion.md` 的 output to 注释、`output-contract.md` 的文件树行和 Stage 2 映射行按上面统一措辞；demo 报告的小标题由「情节节点清单（镜像）」改为「情节节点摘要」，正文不动。
- 不加检查项，摘要段不进 Stage 6 的阻断条件。

## Alternatives considered

1. **只把映射表补上「镜像」，保持两份完整清单**
   - **最强理由**：改动最小，作者只开报告一个文件就能看到全部节点和引文。
   - **弃用原因**：没有任何下游读报告里的副本，整份复制只增加篇幅和两份不同步的风险；真实产物也没有这样写，规范按字面执行反而比现状更差。
2. **报告里完全不提节点，只写一句指向 `情节节点.md`**
   - **最强理由**：最简单，彻底没有重复。
   - **弃用原因**：报告的情感曲线等后续段落按 N 编号引用节点，作者读报告时需要一个按结构段排好的节奏摘要来对照；demo 产物已经证明这段摘要短而有用，删掉是倒退。

## Consequences

- 两处规范说法一致，拆文报告的篇幅不会因整份复制而翻倍，也不再有两份节点清单对不上的问题。
- 作者想看节点原文引用时需要打开 `情节节点.md`，报告里只有编号和事件概括。
- 旧版本跑出、报告里整份复制了节点清单的拆文库仍然可用，下游读取不受影响，不需要迁移。
