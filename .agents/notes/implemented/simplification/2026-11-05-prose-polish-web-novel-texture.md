# Agent Note: 消除 skill 与案例中的晦涩术语、电报体和公文腔，补齐网文质感

Status: implemented
Date: 2026-11-05
Related: [写手热路径技法与去味方法对齐](2026-10-17-writer-hot-path-align-deslop.md)

## Problem

尽管仓库此前已经做过几轮结构与字数预算瘦身，但在创作类 skill（`story-long-write`、`story-short-write`、`story-deslop`、agent 模板）、`demo/` 示例项目以及 `docs/` 创作指南中，仍存在四类破坏网文质感的问题：

1. **自造术语与工程化黑话扎堆**：创作参考文件与拆文/设定案例中频频出现“二级结构化装逼技法”“装逼犯”“任务战果量化器”“三轨叠加”“长线递进器”“正向/反向势能”“高转发的意难平模因”“赌代入复利”“三级功能跃迁”“归一化位置 0.00–0.55”“W 形局部震荡”等生造概念，把本该鲜活的网文叙事手感讲成了晦涩的工程说明书。
2. **电报体短碎句与镜头流水账**：`demo/长篇/让你管账号，你高燃混剪炸全网/正文/第021章_离别怎么会开花.md` 与 `demo/去AI味对照/改后.md` 为了规避 AI 套话，把原本连贯的动作与情绪切成了 90 多行一句一行的短碎句（平均每段仅十余字）；`story-deslop` 与 `story-long-write` 中的“改后/正面示范”也多呈干瘪的相机台本感（如“他看向她。她没说话。屋里安静下来”），缺乏真实连载网文的呼吸节奏与画面咬合。
3. **防御性免责补丁与公文/SOP 腔混入小说案例**：`docs/` 的黄金三章、单章细纲、章末钩子、全书大纲模板，以及 `demo/` 的细纲与设定文档里，把防御性约束话术直接塞进了小说正文或细纲示范（例如在黄金三章正面示范里写“刘老板在报价旁写下确认：‘按这个修。’许青禾收回记录，才将这块表列入待修订单。修复完成后，刘老板按约检查交付的表，确认收下并付了八十元”，在章末钩子示范里写“父亲失踪一年，昨天有人用这个名字订票——两件事并不能直接合成‘他回来了’”，在大纲示范里写“按既定程序修好后，组长批准她进入后续项目”“提交材料不直接等于所有责任已被裁定”），读起来像物业报修单或行政审批流，毫无网文张力。
4. **样板书与拆文原文残存 AI 套话与录入瑕疵**：`demo/拆文库/曾将爱意私藏/原文/原文.txt`（及同名 txt）开头存在重复段落，且夹杂“周身散发出可怕的威压”“高大的身躯如同一座冰冷的山峰，令人心生绝望”“恐惧攫住了我的心”等典型翻译腔/AI 套话；拆文报告与设定文档也存在主语悬空、指代不清的句式。

## Decision

结合 MongoDB `novel` 库（起点、番茄、七猫、知乎盐言、黑岩、点众等真实连载与短篇样本）的网文行文特征，按 `prose-gap-polish` 五步法对 `skills/`、`demo/` 与 `docs/` 进行全量润色：

1. **消除自造词、工程黑话与晦涩句式**：
   - 将 `skills/story-long-write/references/`、`skills/story-short-write/references/`、`skills/story-deslop/references/` 及 `skills/story-setup/references/templates/` 中的生造概念改为网文作者与编辑日常使用的行话（如铺垫、捧杀、接招、翻底牌、算账反应、钩子、拉扯、信息差、场面调度）。
   - 合并规则说明中的电报体碎句，删掉“注意避免……”“需要说明的是……”等防御性元说明，直接给出可执行的写法判断。
2. **重写 `skills/` 与 `docs/` 中的正面示范段落**：
   - 对照真实网文的叙事颗粒度，重写 `story-deslop`、`story-long-write` 以及 `docs/`（黄金三章、单章细纲、章末钩子、全书大纲、设定圣经、去 AI 味指南）中的正反例，彻底清除“列入待修订单”“按既定程序”“并不能直接合成”等 SOP 公文腔，用具体的行当细节、人物算盘、动作反馈和干脆的对白立住网文质感。
3. **打磨 `demo/` 全部案例文案**：
   - 重排并润色 `第021章_离别怎么会开花.md` 与 `demo/去AI味对照/改后.md` 的段落呼吸，把割裂的逐句换行合并为有起承转合的网文自然段，只让关键台词、系统提示与情绪重锤独立成行；同步保持 `check-ai-patterns.js` 零命中与字数口径一致。
   - 清理 `demo/长篇/让你管账号，你高燃混剪炸全网/` 设定、卷纲、细纲中的工程黑话与机械免责条文（保留 `outline_view.py` 与契约测试要求的锚点与字段名）。
   - 修复 `demo/拆文库/曾将爱意私藏/` 原文开头的重复段落与翻译腔套话，并润色《曾将爱意私藏》《盘龙》拆文报告、写作手法、情节节点、节奏与情绪模块中的生造词。
4. **同步共享文件与多端适配层**：
   - 运行 `shared-references.py sync`、`sync-opencode.py`、`generate-codex-agents.py`、`generate-zcode-agents.py`，确保所有宿主适配层与热路径字数预算、跨 skill 契约测试全部通过。

## Alternatives considered

1. **只修改 `skills/` 规则文本，不动 `demo/` 和 `docs/` 中的案例**
   - **最强理由**：改动面最小，不会触碰 `demo/` 的字数校验和 `outline_view.py` 守卫。
   - **弃用原因**：LLM 与用户在阅读 skill 和文档时，受“正反例示范”的影响远大于抽象规则。如果正面示范本身还是“列入待修订单”“按既定程序批准”的公文腔，或者样板章本身是一句一行的电报体，写出来的网文依然会模仿这种僵硬语感。
2. **大幅改写 `demo/` 前 20 章正文结构与字数**
   - **最强理由**：可以对前 20 章做更大幅度的文学重塑。
   - **弃用原因**：`test-handoff-contracts.py` 严格校验 `demo/` 前 20 章细纲 `字数目标` 与正文 `visible_chars_v1` 的一致性及各项追踪状态。对第 21 章（去 AI 味对照样板章）、设定、大纲、细纲、拆文库报告与短篇原文进行精准润色，既能彻底解决电报体、工程黑话和 AI 套话，又能保证全部契约守卫与跨文件引用严丝合缝。

## Consequences

- **收益**：
  - `skills/` 的写作指导更通俗地道，正面示例真正具备连载网文的画面感、对白张力与爽点节奏；
  - `demo/去AI味对照/改后.md` 与 `第021章` 摆脱了一句一行的电报体，兼具“零 AI 套话”与“流畅网文呼吸感”；
  - `demo/` 的设定、卷纲、细纲、拆文报告以及 `docs/` 的全部示例彻底告别公文腔与生造词。
- **代价**：
  - 修改 `skills/` 共享参考文件与 agent 模板后，必须同步重新生成 OpenCode、Codex、ZCode 等适配层产物，并逐一核对 `doc-budget.json` 与 `test-handoff-contracts.py`。
