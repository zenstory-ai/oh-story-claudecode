# Agent Note: 灵感库接手收口——撤回逐章挂点、剥离无关改动、补登记门缺陷

Status: implemented
Date: 2026-09-23
Issue: PR #387 / #439（维护者接手）
Related: [2026-09-22-inspiration-library-em-pipeline](../feature/2026-09-22-inspiration-library-em-pipeline.md)、[2026-09-22-inspiration-pipeline-hardening](../bug-fix/2026-09-22-inspiration-pipeline-hardening.md)、[2026-09-23-long-analyze-runtime-takeover](2026-09-23-long-analyze-runtime-takeover.md)

## Problem

灵感库管道的方向（并入拆书、IA 只是索引行、EM 卡单点维护、卡内禁路径）成立，但接手复测
发现三类问题：

1. **逐章热路径变重**：写前召回新增 (a0)，降档短路径也照常执行，写手 prompt 新增「跨书
   灵感」槽，story-explorer 的逐章 `benchmark_style_load` 也附带 CBA 召回——工作区一旦有
   `灵感库/`，每一章都要多读最多 3 张 CBA 全卡。
2. **夹带无关改动**：同一分支还改了人物关系图默认格式、把 `节奏.md` 四个小节接进建纲、
   做了消费面审计，并把对标挑章平票与结构关键点锚改成适配「单情节点摘要」——而拆文侧
   已决定恢复多情节点。
3. **登记门静默出错**（均已复现）：`### EM-002` 无标题时 ID 被截成 `EM-00` 仍通过；
   `#### EM-002` 或 `### **EM-002**` 让下一张卡整张并进上一张且 `ok:true`；`--book` 与
   `--module` 可以指向不同的书；角色卡在子目录或带编号前缀时泄漏门名单为空；单书 active
   CBA 上限按自由文本列 `source_book` 计数，留空即绕过；列数不对的索引行让 `validate` /
   `coverage` 崩溃；同轴子串近义判定把「高潮前/高潮」这类正常词表拦成错误。

## Decision

- **灵感库只在规划阶段消费**：开书（适用阶段=设定）、卷纲、细纲三处可选召回保留；删除
  写前召回 (a0)、写手 prompt「跨书灵感」槽、story-explorer 的 CBA 召回及对应契约检查。
  灵感经细纲进入正文。热路径文档预算不再为灵感库上调。
- **不带入**原分支的节奏四节接线、关系图 mermaid 默认、消费面审计与平票改造（整笔提交
  未 cherry-pick），需要的话另开 PR 单独评审。
- **登记门修复**：卡头正则锚定编号并允许粗体与全角分隔，缺名称报 `em_title_missing`；
  认不出的 EM 标题行报 `em_header_unrecognized`，同卡重复字段报 `em_field_duplicate`；
  `--module` 必须在 `拆文库/{--book}/` 下；角色名单递归读子目录并去掉数字前缀，索引条目
  标题也做泄漏提示；单书 CBA 上限按来源闭包计数；列数不对的行报
  `column_count_mismatch` 且不进入后续校验；CLI 输出统一 UTF-8，I/O 异常返回结构化错误；
  `coverage` 对 NM 成员的口径与 `validate` 一致；词表接受 `* 值`。
- **删除**同轴子串近义判定（`tag_vocabulary_near_duplicate`），同义判定回到扩表时的人工
  比对。
- **新增门禁只拦真问题**（复审后收窄）：`em_header_unrecognized` 只认以 EM 编号开头却不是
  `### EM-xxx` 的标题（含 `## EM-002`），提到 EM 编号的普通标题不拦；`em_field_duplicate`
  只查五个门禁字段；表格分隔行、字段名行后缩进的续行、`***字段***`、粗体卡头标题都按
  原意解析；`--book` 拒绝 `.`、`..` 和带路径分隔符的值；坏行按文件实际行号报告；I/O
  错误同时给 `error` 与 `errors`。
- 并发登记不加锁，文档写明逐本串行运行。

## Alternatives considered

- **(a0) 只在全量召回时执行、降档时跳过**：保留逐章灵感入口、同时减一点成本；但灵感卡
  是设计层抽象，细纲已经承接它，逐章再查一遍收益小、每章都付上下文。
- **把无关改动留在本 PR 里一起评审**：少开一个 PR；但它们与灵感库无依赖，其中平票改造
  还建立在已被推翻的单情节点前提上，混在一起只会让评审和回滚都变难。
- **子串近义判定降级为 warning**：保留同义膨胀的提示；但子串关系和同义关系本来就对不上，
  warning 也会成为常态噪音。
- **登记加文件锁**：能挡住并行登记丢行；但登记是低频的维护操作，串行即可，锁文件还要处理
  遗留锁的清理。

## Consequences

收益：逐章写作的上下文与 prompt 结构不因灵感库改变；本 PR 只含灵感库本身；登记门不再
静默吞卡、截 ID 或空跑泄漏检查。

代价：正文阶段不能直接召回 CBA，只能经细纲间接使用；原分支的节奏接线等改动需要另行
评审；并行登记仍会丢行，靠文档约束；词表同义膨胀只靠人工把关。
