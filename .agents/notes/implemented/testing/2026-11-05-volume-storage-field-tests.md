# Agent Note: 正文存储人工测试记录（PR 证据）

Status: implemented

## Problem

作者在 2026-11-05 提供三个真实测试目录。核对完整 JSONL 日志、实际配置与正文文件，区分真实成功、流程遗漏和仍需人工重跑的项。原始日志、小说正文和作者数据不提交仓库。

## Decision

| 样本 | 证据与实际结果 | 判定与修正 |
|---|---|---|
| book_7 写书测试 | 日志 d02aaff5：读取卷1、卷2正文；第3章写入卷2、第4章写入卷3。随后转平铺，当前4章直属正文。 | 跨卷路径读取及按配置创建正文可见实际调用；不据此声称所有叙事上下文语义正确。 |
| book_7 迁移说明 | 原备份位于 `.story/backup_body_volumes_20261105`；转换后模型发现测试说明仍为旧结构，却另问是否修改。 | 关联资料未一次完成；统一 `.backup`，同轮扫描和核对说明，未完成时不能报告整体完成。 |
| book_8 创书测试 | 日志 ba1ee0f3 中6组交互问题没有存法选择；模型直接表示已建平铺配置。实际前三章均已生成，配置为 flat。 | 创建章节成功，存法确认未通过；加强“方向已给也不能默认 flat”。模型是否按修订流程正确提问，仍需作者新会话重跑，静态检查不能替代行为验收。 |
| book_9 旧改测试 | 日志 08b76067：第167章任务已带布局配置和上一章结尾；后续把分卷称为多“本”，只重排卷纲。当前配置仍 flat，167章均直属正文，无迁移备份。 | 不能认作分卷迁移成功。拆书、剧情分卷、正文目录分卷分别处理；按实际目录及哈希验收。 |

真实日志时间以其 UTC 时间戳为准；本记录日期按 Asia/Shanghai。这里只保留复核所需的会话短标识、数量和现象，不摘录小说内容。

修复后仅在临时副本验证：

- book_7：从已有分卷备份还原4章副本，迁移到 flat；4章哈希一致，正文与旧配置均有备份，测试说明进入待核对，未误报整体完成。
- book_7：将副本恢复为3卷配置，组装第4章写作任务成功，任务包含卷2第3章结尾，目标仍为卷3第4章。
- book_8：3章副本移除配置后自动登记 flat 成功；这不能证明创书提问已修复，提问仍待宿主新会话复测。
- book_9：167章副本移除配置后自动登记 flat；转换为六卷范围后，前五卷分别45、25、30、42、25章，第六卷尚无已写正文。章节总数与全部字节哈希一致，直属正文无剩余正式章节。
- 工作区外层 `CLAUDE.md` 与书内修订说明均被发现，不只扫描预设文件名；对标来源排除，不改其他作品资料。人工说明核对完成前状态为 `needs_reference_review`。
- 原项目的正文路径与哈希在测试前后相同，未移动实际小说。自动化测试额外覆盖中途写失败回滚、计划过期、目标冲突、关联资料新增后的复扫和核对登记不能掩盖精确旧路径。
- book_9 副本迁移前后追踪检查均通过，最后提交章号保持167，状态修订号保持305；不把存储分卷误改成叙事状态重置。

## Alternatives considered

把原始日志作为 PR 附件便于复查，但包含正文、对话和环境信息；保留本地原件，仓库仅记录匿名化事实。只依据模型最终汇报最方便，但 book_9 的完成声明与实际文件不符；以目录、配置、工具调用和哈希为准。

## Consequences

后续 PR 应明确列出开书提问待人工重跑、迁移副本验证结果，以及关联说明待核对状态，不把工具单测等同于宿主端到端测试。真实项目保留原状，修复后迁移只在临时副本执行。
