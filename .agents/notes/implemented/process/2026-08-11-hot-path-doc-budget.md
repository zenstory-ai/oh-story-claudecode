# Agent Note: 热路径文档字数预算门禁

Status: implemented

## Problem

skill 文本是每个用户每次会话都要付的 token。逐条加规则每次只贵一点点，累积起来就是日更路径翻倍；PR #228 一次净删 32.9KB 之后热路径又回涨。需要让膨胀变成一次显式决定，而不是无声累积。

## Decision

- `scripts/check-doc-budget.sh` + `scripts/doc-budget.json` 进 CI 强制清单。度量 = 去掉所有空白后的字符数，中英文都算，改标点 / 换行 / 缩进不影响读数。
- 只登记「每次会话或每章都进模型上下文」的热路径文件；冷路径（story-setup 部署、UPGRADING、拆文库模板）不登记、不受限。新增热路径文件 must 登记，否则不受任何约束。
- `files` 每项带 `budget` 与 `why`；`paths` 是一次会话真正付的路径合计，可用 `branches` 表示条件分支（如悬疑 / 反转参考）。迁出的文件保守全额计入，拆分不计作同阶段总量节省。
- 超预算即红，处理顺序固定：① 先删同一文件里等量的旧文本（重复指令、已被脚本确定性拦住的规则、设计理由旁白、极少数场景才用的分支）；② 确实必须加的新规则，在 `doc-budget.json` 调高 budget，并在 PR 里写清为什么这段值得每个用户每次会话都付。调 budget 允许，但必须是一次显式决定。
- 余量 ≥5% 时脚本提示可下调 budget 锁住这次精简（棘轮，不阻断）。
- never 为预算删手艺规则（细纲边界、爽点铺垫、去 AI 味 Gate）：PR #228 盲评实测删那些会退步。

来源：1eae178 (#352)、9c40276 (#401)

## Alternatives considered

- **靠 PR review 把关**——最强理由：零工具成本，reviewer 能判断规则值不值。否：每条规则单看都合理，累积效应在 review 里不可见，1eae178 之前正是这样涨上去的。
- **一次性大精简、不设门禁**——#228 做过，之后又回涨；1eae178 明确要「让膨胀变成一次显式决定」。
- **按行数或字节计**——最强理由：现成工具。否：改标点、换行、缩进都会动读数，去空白字符数只对增删正文敏感。

## Consequences

- **收益**：每次加热路径规则都要付等量删减或显式说明；多轮精简（开书 -30% / 回炉 -41%，短篇按阶段加载）被棘轮锁住。
- **代价与已知上限**：每次加规则都要动 `doc-budget.json`，`why` 字段变成第二份变更说明；预算数是人定的，只防增长不证明够精简；条件分支多时 `paths` 表本身膨胀。若发现团队习惯性调高 budget 而不删文本，说明门禁已空转，应回到逐路径重审。

## Verification

`bash scripts/check-doc-budget.sh`（支持 `--root` / `--manifest` 指向临时工程）；`python3 scripts/test-doc-budget.py` 验证路径求和、超限与缺失文件失败。
