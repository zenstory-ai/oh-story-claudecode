# Agent Note: 短篇写作照长篇思路清理写法与机制，段落长短规则按短篇人类基线不动

Status: implemented
Date: 2026-11-03
Related: [长篇写作在 0.9.2 上清理](2026-11-03-long-write-0-10-cleanup.md)、[短篇构思与写正文分两个时刻](../../implemented/architecture/2026-09-26-short-write-by-moment.md)

## Problem

长篇写作做完清理后，短篇写作（story-short-write）还留着同一批问题：

- 作者每天打开的 `设定.md`、`小节大纲.md` 里有文件路径、除法算式、花括号功能标签、英文阶段名，共 30 处。
- 几套跟长篇一起长出来、短篇用不上的机制：文风裁决、跨书召回、三份去味方法副本、参考索引、汇报技术备注行。
- 引号内省略号已经放宽，但短篇还有十几处说「停顿用短句、换行」或「只许标点台词用省略号」，规则自相矛盾。
- 「第 8 节」「执行规则 3」这类数字引用有十几处，守卫管不到；模板字段被构思检查、审稿、封面、导入按名读取，模板里一处没标。
- 精修去味该不该派写手、节尾钩子要不要每节都下、情绪走向怎么选，各有两到四种说法。
- 精修实际读 banned-words 却没登记加载预算，最重组合约 35.1K，超过 35K 上限。

审查报告逐条带了行号证据。

## Decision

照长篇的四条原则做：作者文件用白话、删用不到的机制、同一规则一处写、参考资料按时刻和读者划分。

- **白话**：30 处全换（如「构思要点」「题材：追妻火葬场」「反转在：第 X 节（共 Y 节）」「这篇用的套路」「节尾停在哪」）。被脚本或别的 skill 按名读的字段，解析层新旧名都认，老书不迁移也能续写；模板改用 `template=短篇设定`、`template=小节大纲` 围栏，模板外注释标出谁在读。
- **删**：文风裁决（优先级一句进 short-craft，`.deslop-whitelist` 规则进 short-format）、跨书召回（并进对标召回两句）、参考索引与「按需技法」清单、短篇里的三份去味方法副本和主会话那份 deslop-gates（完整去味转 /story-deslop）、汇报技术备注行、设定.md 的情绪强度打分。
- **降级**：构思检查去掉功能标签和反转百分比算式两项没有证据的硬检查（文档自己写着百分比「不是通过线」），题材只写题材名，「场景形态」「对白作用」改为可选列；平台、字数、节数、付费点、反派五字段、占位符这些有事故来历的检查保留。character-designer 只在作者要细化人设时派；已写小节摘要只在换对话时写；整篇字数只认交付检查。
- **标点**：只在 short-format「标点」一节写一遍，对话里的犹豫、打断用 `……`，叙述用逗号接上，破折号不用；其余各处一句指向。
- **划分**：SKILL.md 一张时刻总表作唯一读取清单，`check-reference-routing.py` 的路由与预算互查扩到短篇；数字引用改成带名字的引用；节尾钩子只在 hooks-chapter、情绪走向只在 emotional-methods 各写一处；短篇卖点保护以 story-deslop 为源共享，完整去味短篇时不再丢。
- **段落长短与碎句规则不动**：七猫短篇 1500 篇随机样本的短段（去空白不到 20 字）占比中位 42%（P10–P90 为 25%–61%），叙述句长中位 21 字；长篇真人是 19% 和 39 字。单句成段是短篇的平台习惯，长篇那套收碎句的改法不能照搬，等短篇对照实验的数据再定。只把「逐拍」「慢镜头逐拍」改成「写足过程」，避免被读成一拍一句。

保留不动：两个时刻与两份设计文件交接、写前参数验收、交付检查、平台表与付费点、节尾统计、「句子要连」、写前每场三问、作者记忆、story-architect 辅助构思及其副本（没有使用记录，但维护者没定，保守保留）、入口里的小节完整性流程与完成门槛。

## Alternatives considered

- **照搬长篇的收碎句改法**。最强理由：两边共用同一个底座模型，长篇实验里技法文件推短句是可见的。不采用：七猫短篇本身短段占比 42%，模型的写法和真人短篇接近，照搬会把短篇往长篇的段落习惯推，偏离平台。
- **删掉 story-architect 辅助构思和四份副本**。最强理由：9 月 26 日的笔记已否掉把构思交给它，没有使用记录，删了以后改短篇不再牵动 story-setup 和七个宿主。不采用：维护者没有表态，保守保留，留到评审时定。
- **把小节完整性流程和完成门槛挪出入口**。最强理由：每次调用都要付约 600 字。不采用：预算说明里写着有同稿实验支持留在入口，找不到实验记录前不动。
- **构思检查改成全部可选**。最强理由：短篇这些字段都没有消融证据。不采用：平台、字数、节数、付费点、反派五字段各有真实事故来历。

## Consequences

- **收益**：作者打开的设定和小节大纲是白话；标点规则不再自相矛盾；精修路径登记完整、回到 35K 以内；改短篇模板字段不会再悄悄弄坏审稿、封面和导入。
- **代价**：构思检查与导入、封面、审稿的读取长期认新旧两套字段名；构思检查一项检查 ID 由 `outline-12-columns` 改为 `outline-header`。
- **验证结果**（三个七猫短篇的同题材前提，Codex 写全文，Claude 子代理评委交换顺序两次一致才算胜，小样本）：
  - 第一次清理后对 0.9.2 打平（两题各 1:1 平 1）；评委指出 skill 两组输给原生的主因是「大段核对、移交、走程序，爽点被稀释」「公文腔」。
  - 加「兑现当面发生」和「不用申诉书、通报腔」两句后，最终版对 0.9.2：像能上架 3:0，读着顺、情绪到位 2:1；对原生仍 0:6，原生胜在情绪落在家常细节、打脸层层递进。
  - 和七猫真人原文比，评委在「读着顺、情绪到位」上三组都压过真人；真人赢在高概念钩子和爽点密度，也被扣在人名前后不一、错字和尺度过线。评委与写手不同家族，但偏好模型文风，真人对照只作参考。
  - 碎度：最终版叙述句长中位 16.3 字、短段 45%；真人三篇 22.7 字、36%，原生 15.3 字、61%。
- **待维护者确认**：番茄短篇有没有付费墙，short 与 story-publish 说法仍相反；story-architect 辅助短篇构思是否保留。
