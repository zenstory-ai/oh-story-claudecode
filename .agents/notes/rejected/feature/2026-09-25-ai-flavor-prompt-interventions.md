# Agent Note: 读感可数约束、检测器闭环改稿、换强写手三种降 AI 味干预都未过预注册门槛

Status: rejected

## Problem

v0.8 提案（[v0.8 瘦身笔记](../../implemented/architecture/2026-09-24-v0-8-lean-writing-loop.md) 第 3 节）把 AI 味列为四个痛点之一，计划在精简后的基座上做可证伪实验：①写作要点只放正向、可数的约束；②检测器给出偏离人类区间的项，一次定点改稿；③写手换更强的模型。依据是本地 tell 项目 r3（可数约束在 GPT 上能推动台词语域、感叹号、对话占比）和 r4（数值反馈改稿能推动分布项，但有刷指标副作用）。

## Decision

- 三种干预都不合入：写手 prompt 不加读感约束块，单章流程不加读感复核步骤，Codex 写手不单独指定更强模型。
- 实验代码只留在 `exp/ai-constraints`、`exp/readfeel-loop` 两个本地实验分支，不进主线。
- 实测（Codex，gpt-5.6-sol 主会话；demo 书第 22–24 章、玄幻与女频新书第 1–3 章，每组各 9 章；协议在数据产生前冻结，见 `~/.oh-story-bench/prereg/v0.8-ai-constraints/`）：

| 组 | 做法 | 每章人类区间越界项（均值，tell `human_ref_check --family gpt`） | 相对对照 | 其他 |
|---|---|---|---|---|
| A 对照 | v0.8 候选 | 5.00 | — | — |
| B 约束 | 写手 prompt 固定注入 7 条读感约束 | 4.44 | −0.56，三本里两本改善 | 感叹号/千字 0.22→0.20，完全没动 |
| C 闭环 | 检测器 ≥2 条白话提示时写手一次定点改稿 | 4.56 | −0.44 | 感叹号 0.22→0.82；每章墙钟 +28%；9 章里只有 2 章实际跑了复核 |
| D 强写手 | 写手改用 gpt-6-astra | 4.78 | −0.22 | 首次字数检查带内 9/9（A 为 7/10，未预注册，仅记录） |

- 预注册主指标门槛是「比对照少 ≥ 1.0 项且三本中至少两本方向一致」，三组都没达到，按协议判无效，护栏评审只作记录不改变结论。

## Alternatives considered

- **合入 B（约束块）**：最强理由是它便宜，只多约 300 字 prompt，方向上两本书有改善，且 tell r3 在裸 prompt 下测到过效果。否：在完整产品流程里效果缩到门槛的一半，被点名最清楚的感叹号一项完全没动，推测和既有「只在情绪峰值少量用感叹号」规则互相抵消；为一个没过门槛的效果让每章多付 prompt 不划算。
- **合入 C（闭环）**：最强理由是它确实推动了感叹号这类分布项，和 tell r4 一致。否：主指标没过门槛，每章耗时 +28% 正好抵消 v0.8 的省时目标；模型在 9 章里有 7 章跳过了复核步骤，要可靠执行就得再加 hook 或脚本强制，复杂度上升。
- **只对 Claude 写手重做实验**：最强理由是 tell 的画像显示各模型家族的 AI 痕迹不同，GPT 上无效不代表 Claude 上无效。否：本机 Claude CLI 未登录，MiMo 额度已用尽，这次拿不到数据；留作重访条件，不在没有数据时合入。

## Consequences

- **收益**：写手 prompt 与单章流程不为没有证据的改动增长，v0.8 的省时省 token 不被抵消。
- **代价**：AI 味这个痛点在 v0.8 里没有被正面推动，只由精简本身带来的不劣化（配对盲评 4 胜 2 负 3 平、人类区间越界项中位 4→3）间接覆盖。
- **重访条件**：拿到 Claude 写手的基准数据时，用同一协议在 Claude 上重测 B 与 D；若某一干预在 Claude 上过门槛，只对该家族启用。评委与指标沿用本次口径（换家族评委、单份盲评、可数主指标）。
